### Q1. 什麼是語意化 HTML？跟無障礙有什麼關係？ <Badge type="tip" text="基礎" /> {#21-2-1}

**考點**：是否把 HTML 當結構而非排版工具；是否知道螢幕閱讀器、SEO 如何讀頁面。

::: details 解題思路
從「誰在讀 HTML」切入：瀏覽器、搜尋引擎、輔助科技。語意標籤讓它們不用猜。最後補一個實務檢查方式。
:::

::: details 標準答案與過程
語意化是用「表達內容意義」的標籤，而不是全部用 `div`、`span`：`header`、`nav`、`main`、`article`、`section`、`aside`、`footer`、`button`、`label`。

好處：

1. **無障礙**：螢幕閱讀器能依地標（landmark）跳轉，`button` 天生可聚焦、可用 Enter／Space 觸發；用 `div` 模擬按鈕就要自己補 `role`、`tabindex`、鍵盤事件。
2. **SEO**：搜尋引擎能判斷主要內容與標題階層。
3. **維護性**：讀程式碼就知道區塊用途。

實務原則：能用原生元素就不要用 ARIA 補；一頁一個 `main`；標題 h1→h2→h3 依內容層級，不為字體大小跳級；圖片有 `alt`，表單有 `label`。驗證可用 Lighthouse Accessibility、axe DevTools，並實際用鍵盤 Tab 走一遍。
:::

**相關筆記**：[1-1-1 HTML 語意化](./1-1-1.md)、[1-1-6 HTML 與無障礙](./1-1-6.md)

### Q2. 什麼是 BFC？怎麼觸發？能解決什麼問題？ <Badge type="tip" text="高頻" /> {#21-2-2}

**考點**：版面配置的底層規則。

::: details 解題思路
先定義（獨立的版面渲染區域），再列觸發條件，最後用三個經典問題證明你真的用過。
:::

::: details 標準答案與過程
BFC（Block Formatting Context）是一塊獨立的區塊版面配置區域，內部元素的排版不會影響外部。

常見觸發方式：`display: flow-root`（最乾淨，專為此設計）、`overflow` 非 `visible`、`float` 非 `none`、`position: absolute/fixed`、`display: inline-block / flex / grid` 的子項目所在容器等。

能解決的問題：

1. **父元素高度塌陷**：子元素 float 後父容器高度為 0，父容器變成 BFC 就會包住浮動子元素。
2. **外邊距合併（margin collapse）**：相鄰兩個區塊的上下 margin 會合併，放進不同 BFC 就不會。
3. **文字繞排**：BFC 區域不會和 float 元素重疊，可做兩欄自適應。

```css
.clearfix-parent {
  display: flow-root; /* 取代舊的 clearfix 偽元素技巧 */
}
```
:::

### Q3. 水平垂直置中有哪些方法？ <Badge type="tip" text="基礎" /> {#21-2-3}

**考點**：對 Flex、Grid、定位的熟悉度，以及能否依情境選擇。

::: details 標準答案與過程
```css
/* 1. Grid：最短 */
.parent { display: grid; place-items: center; }

/* 2. Flex：最常見 */
.parent { display: flex; justify-content: center; align-items: center; }

/* 3. 絕對定位 + transform：不需知道子元素寬高 */
.parent { position: relative; }
.child { position: absolute; top: 50%; left: 50%; transform: translate(-50%, -50%); }

/* 4. 絕對定位 + margin: auto：子元素需有寬高 */
.child { position: absolute; inset: 0; margin: auto; width: 200px; height: 100px; }
```

選擇：一般排版用 Grid／Flex；覆蓋層（Modal）用定位或 `dialog`；行內文字用 `text-align: center` + `line-height`。
:::

**相關筆記**：[1-1-3 實現置中](./1-1-3.md)

### Q4. Box Model 是什麼？`box-sizing` 兩個值差在哪？ <Badge type="tip" text="基礎" /> {#21-2-4}

::: details 標準答案與過程
每個元素由 content、padding、border、margin 組成。

- `content-box`（預設）：`width` 只算 content，加 padding 和 border 會讓元素變寬。
- `border-box`：`width` 包含 content + padding + border，排版較直覺。

實務上全域設定：

```css
*, *::before, *::after { box-sizing: border-box; }
```

margin 不包含在 `width` 內，相鄰區塊的垂直 margin 可能合併（見 Q2）。
:::

**相關筆記**：[1-1-7 CSS 精華觀念](./1-1-7.md)

### Q5. Flex 與 Grid 怎麼選？`flex: 1` 代表什麼？ <Badge type="tip" text="高頻" /> {#21-2-5}

::: details 解題思路
用「一維 vs 二維」和「內容決定 vs 版面決定」兩個角度回答，再解釋縮寫。
:::

::: details 標準答案與過程
- **Flex**：一維（一列或一欄），尺寸常由內容決定。適合導覽列、按鈕群組、卡片內部對齊。
- **Grid**：二維（列與欄同時控制），由版面決定內容位置。適合整頁版面、卡片牆、表單欄位對齊。
- 兩者常混用：外層 Grid 排版面，內層 Flex 排元件。

`flex: 1` 是 `flex: 1 1 0%` 的縮寫：

| 屬性 | 值 | 意義 |
| --- | --- | --- |
| `flex-grow` | 1 | 有剩餘空間時等比例放大 |
| `flex-shrink` | 1 | 空間不足時等比例縮小 |
| `flex-basis` | 0% | 從 0 開始分配，所以多個 `flex: 1` 會等寬 |

常見坑：文字過長撐破 flex item，要加 `min-width: 0`（flex item 預設 `min-width: auto`）。
:::

### Q6. CSS 優先權（specificity）怎麼算？ <Badge type="tip" text="基礎" /> {#21-2-6}

::: details 標準答案與過程
比較順序：

1. 是否 `!important`（它是 cascade 的重要性層級，不是 specificity）。
2. 來源與 `@layer`：未分層的樣式優先於分層樣式，後宣告的 layer 優先。
3. Specificity：以 (ID, Class／屬性／偽類, 元素／偽元素) 三欄比較。例：`#nav .item a` = (1, 1, 1)。
4. 都相同時，後寫的覆蓋先寫的。

特殊規則：`:is()`、`:not()`、`:has()` 取參數中最高的 specificity；`:where()` 永遠是 0，適合寫可被覆蓋的基礎樣式。行內 `style` 高於所有選擇器。

實務：避免靠 ID 與 `!important` 打權重戰，用元件作用域（Vue scoped、CSS Modules）或 `@layer` 管理。
:::

**相關筆記**：[1-1-7 CSS 精華觀念](./1-1-7.md#1-1-7-2)

### Q7. 你怎麼做 RWD？百分比是相對於誰？ <Badge type="tip" text="高頻" /> {#21-2-7}

**考點**：RWD 不只是 media query；是否懂相對單位。

::: details 標準答案與過程
做法分層：

1. `<meta name="viewport" content="width=device-width, initial-scale=1">`。
2. **流動版面**：Grid `repeat(auto-fill, minmax(240px, 1fr))`、Flex wrap，讓版面不靠斷點也能伸縮。
3. **斷點**：Mobile First，用 `min-width` 往上加；元件依自身容器變化時用 **Container Query**（`@container`）。
4. **流動字級與間距**：`clamp(1rem, 2vw + 0.5rem, 1.5rem)`。
5. **圖片**：`srcset` + `sizes`、`picture`、`aspect-ratio` 預留空間避免 CLS。
6. **行動裝置高度**：`100vh` 在手機會被網址列影響，改用 `dvh` / `svh`。

百分比的參考對象：

| 屬性 | 相對於 |
| --- | --- |
| `width`、`padding`、`margin`（含上下） | 包含區塊的**寬度** |
| `height` | 包含區塊的高度（父層需有明確高度） |
| `top/bottom` | 包含區塊高度；`left/right` 相對寬度 |
| `transform: translate()` | 元素**自身**尺寸 |
| `font-size` | 父元素字級 |

```css
.cards {
  display: grid;
  grid-template-columns: repeat(auto-fill, minmax(240px, 1fr));
  gap: 16px;
}
```
:::

### Q8. z-index 設很大卻沒有蓋過去，為什麼？ <Badge type="warning" text="進階" /> {#21-2-8}

::: details 標準答案與過程
z-index 只在**同一個層疊上下文（stacking context）**內比較。如果元素的祖先建立了新的層疊上下文，它再大也只能在祖先內部排序，無法超過祖先的兄弟。

會建立層疊上下文的常見情況：`position` 非 static 且 z-index 非 auto、`opacity` 小於 1、`transform`、`filter`、`position: fixed / sticky`、`isolation: isolate`、flex／grid 子項目設 z-index。

排查：DevTools 的 Layers 面板，或往上找哪個祖先有上述屬性。解法：把 Modal、Tooltip 用 Teleport（Vue）／Portal（React）掛到 `body`，或使用原生 `dialog` 的 top layer。
:::

**相關筆記**：[1-1-7 CSS 精華觀念](./1-1-7.md#1-1-7-2)

### Q9. Reflow 與 Repaint 差在哪？怎麼寫出不卡的動畫？ <Badge type="tip" text="高頻" /> {#21-2-9}

::: details 標準答案與過程
- **Reflow（Layout）**：幾何資訊改變（寬高、位置、字級、增刪 DOM），要重新計算版面，成本最高，且可能影響整棵樹。
- **Repaint**：只改外觀（顏色、背景、陰影），不用重排但要重繪。
- **Composite only**：只改 `transform`、`opacity`，可交給合成器執行緒，最便宜。

寫法：

1. 動畫用 `transform` / `opacity`，不改 `left`、`width`。
2. 避免**強制同步佈局**：在迴圈中先讀 `offsetHeight` 再寫樣式會讓瀏覽器反覆重排；先批次讀、再批次寫。
3. 用 `requestAnimationFrame` 對齊畫面更新；必要時 `will-change: transform`（不要濫用，會吃記憶體）。

```js
// 不好：讀寫交錯，每次迴圈都觸發 layout
items.forEach(el => { el.style.height = el.offsetHeight + 10 + 'px' })

// 好：先讀後寫
const heights = items.map(el => el.offsetHeight)
items.forEach((el, i) => { el.style.height = heights[i] + 10 + 'px' })
```
:::

### Q10. 跨瀏覽器相容問題你怎麼處理？ <Badge type="tip" text="高頻" /> {#21-2-10}

**考點**：有沒有系統化的方法，而不是遇到才查。

::: details 解題思路
分「事前定義範圍 → 建置期自動處理 → 執行期偵測 → 實機驗證」四步，並舉一個真實踩過的坑。
:::

::: details 標準答案與過程
1. **先定義支援範圍**：和 PM 確認要支援的瀏覽器與版本，寫進 `browserslist`。
2. **建置期自動處理**：
   - 語法：Babel／esbuild／SWC 依 browserslist 轉譯。
   - API：`core-js` polyfill（按需引入）。
   - CSS：Autoprefixer、PostCSS 補前綴。
3. **執行期偵測**：`@supports`、`'IntersectionObserver' in window` 做漸進增強，不用 UA sniffing。
4. **實機驗證**：iOS Safari 一定要真機測；Mac Safari 開啟「開發」選單可遠端除錯 iPhone；雲端可用 BrowserStack。

常見坑：

- iOS 上所有瀏覽器多數地區仍是 WebKit，Chrome for iOS 的問題通常就是 Safari 的問題。
- `100vh` 被網址列影響 → `dvh`。
- iOS 輸入框字級小於 16px 會自動放大頁面。
- 日期字串 `new Date('2026-11-04 10:00')` 在舊版 Safari 會是 Invalid Date → 用 ISO 格式 `2026-11-04T10:00:00` 或 dayjs。
:::
