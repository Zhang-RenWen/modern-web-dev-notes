# 1-5-1 瀏覽器架構：引擎與多進程 {#1-5-1}

::: info 新增（2026-11）

:::

## 瀏覽器是什麼 {#1-5-1-1}

瀏覽器 = **殼（UI 與產品功能）** + **引擎（把網頁變成畫面的核心）** + **平台服務（網路、儲存、安全、GPU、作業系統整合）**。

- **渲染引擎（Rendering Engine）**：解析 HTML/CSS、算版面、畫出像素。例：Blink、WebKit、Gecko。
- **JavaScript 引擎**：執行 JS 與 WebAssembly。例：V8、JavaScriptCore、SpiderMonkey。
- **殼**：分頁、書籤、同步、擴充功能、AI 側欄等。Chrome、Edge、Brave、Opera、Comet 的殼不同，但引擎幾乎都是 Chromium。

::: tip 關鍵觀念
使用者感受到的「瀏覽器差異」多半在殼；開發者感受到的「相容性差異」幾乎都來自引擎。全球真正在活躍開發、有規模的引擎只剩三套：Blink、WebKit、Gecko。
:::

## 多進程架構 {#1-5-1-2}

早期瀏覽器是單一進程：一個分頁的 JS 當掉，整個瀏覽器一起死。現代瀏覽器全部改為多進程，用作業系統的進程邊界換取**穩定性**與**安全性**。以 Chromium 為範本（其他家概念相同、名稱不同）：

```txt
┌──────────────── Browser Process（主進程，權限最高）────────────────┐
│ UI／分頁管理／導航決策／權限／書籤、歷史／協調所有子進程            │
└──────┬─────────────┬──────────────┬──────────────┬────────────────┘
       │ IPC (Mojo)  │              │              │
┌──────▼──────┐ ┌────▼───────┐ ┌────▼───────┐ ┌────▼──────────────┐
│ Renderer ×N │ │ GPU        │ │ Network    │ │ Storage／Utility／ │
│ 每個站點一個 │ │ 合成、繪製  │ │ HTTP/QUIC  │ │ Audio／擴充功能…   │
│ Blink + V8  │ │ WebGL/GPU  │ │ Cookie/快取│ │                   │
│ 沙箱，權限最低│ └────────────┘ └────────────┘ └───────────────────┘
└─────────────┘
```

| 進程 | 職責 | 為什麼要獨立 |
| --- | --- | --- |
| Browser | 視窗／分頁 UI、導航、權限、協調 | 唯一高權限進程，其他人透過它存取系統資源 |
| Renderer | 解析 HTML/CSS、跑 JS、排版 | 跑的是「不可信的網路程式碼」，必須關在沙箱裡 |
| GPU | 把各進程的圖層合成到螢幕 | GPU 驅動常不穩，隔離後當掉只會閃一下 |
| Network | DNS、連線、TLS、HTTP 快取、Cookie | 統一管理連線池，渲染進程不能直接碰網路 |
| Storage／Utility／Audio | 資料庫、解碼、音訊 | 拆小、降權、可單獨重啟 |

- **站點隔離（Site Isolation）**：2018 年的 Spectre／Meltdown 讓「同一進程內的記憶體可以被旁路讀取」成為現實，所以瀏覽器改成**不同站點（scheme + eTLD+1）放在不同 Renderer 進程**，頁面裡的跨站 iframe 也拆開。Chrome 稱 Site Isolation，Firefox 的實作專案叫 Fission，Safari 也逐步跟進。可用 `chrome://process-internals` 查看哪些站點在哪個進程。
- **沙箱（Sandbox）**：Renderer 被作業系統限制成幾乎什麼都不能做（不能開檔、不能直接連網、不能呼叫大部分 syscall），要什麼都得透過 IPC 向 Browser 進程申請。所以瀏覽器漏洞通常要「渲染進程 RCE + 沙箱逃逸」兩段串起來才算完整攻擊鏈。
- **代價**：記憶體。每個進程都有自己的 JS heap 與引擎資料結構，這是 Chrome「吃記憶體」的主要原因。各家會在記憶體吃緊時合併同站進程、凍結背景分頁來補償。

## 名詞剖析 {#1-5-1-3}

| 名詞 | 意思 |
| --- | --- |
| 進程（Process）／執行緒（Thread） | 作業系統分配資源的單位，彼此記憶體隔離／同一進程內共用記憶體的執行單位 |
| IPC／Mojo | 進程間通訊／Chromium 的 IPC 框架 |
| Spectre／Meltdown | 2018 年公開的 CPU 推測執行旁路攻擊，可以讀到同一進程內不該讀的記憶體 |
| eTLD+1 | 有效頂級網域再加一層，例如 example.co.uk、google.com；瀏覽器判斷「同站」的單位 |
| RCE | Remote Code Execution：漏洞讓攻擊者能在你的機器上執行任意程式 |
| 沙箱逃逸 | 從權限受限的沙箱突破到高權限環境 |
| syscall | 程式請作業系統核心代辦事情的入口 |
