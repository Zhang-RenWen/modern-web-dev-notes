## 輸入網址後發生什麼事（網路段） {#1-18-18-1}

```txt
URL 解析 → 查快取（Browser／Service Worker／HTTP／DNS cache、可重用連線）
→ DNS 取得 IP
→ 建立連線：HTTP/1.1、HTTP/2 走 TCP；HTTP/3 走 QUIC over UDP
→ TLS handshake
→ HTTP Request → Response
```

- 很多請求根本沒打到遠端 server，被快取攔下了；也不是每次都重新 DNS、重新建連線。
- **DNS 查詢路徑**：Browser → OS → Router → Recursive Resolver → Root → TLD → Authoritative。現代還有 CDN、Anycast、DoH／DoT、公司內網 DNS。常用 record：A（IPv4）、AAAA（IPv6）、CNAME（別名）、MX（郵件）、TXT（SPF／DKIM／DMARC 驗證）、NS。
- 渲染段見 [1-3-3 瀏覽器渲染流程與除錯](./1-3-3.md)。

## HTTP {#1-18-18-2}

- URL 拆解：`https://www.example.com:443/users/123?page=1#section`＝scheme、subdomain、domain、port、path、query、fragment。**#fragment 不會送到 server；query 會。**
- Request＝Request line（method＋path＋版本）＋Headers（Host、Content-Type、Authorization、Cookie、Origin…）＋空行＋Body。
- 修正：不是「只有 POST／PUT／PATCH／DELETE 才能有 body」。任何 request 技術上都能有 body，但 GET／HEAD 不要設計成依賴 body。
- Status 五大類：1xx 資訊、2xx 成功、3xx 導向、4xx client 錯、5xx server 錯。

| 必背對照 | 意義 |
| --- | --- |
| 401 vs 403 | 401：還沒證明你是誰（沒帶／過期 token）；403：知道你是誰但沒權限（一般會員進 admin） |
| 502 vs 503 vs 504 | 502：gateway 收到上游壞回應；503：服務過載／維護；504：gateway 等上游等到 timeout |
| 201／202／204 | 建立成功／非同步任務已受理／成功但無 body |
| 304／307／308 | 快取仍有效／暫時導向保留 method／永久導向保留 method |
| 409／422／429 | 狀態衝突（重複建立）／驗證失敗／被 rate limit |

## HTTPS／TLS {#1-18-18-3}

- HTTPS＝HTTP over TLS，不是 HTTP 自己加密。
- **非對稱加密用來驗證憑證、協商 session key；後續大量資料用對稱加密。**
- TLS 1.3：握手簡化、常見 1-RTT、移除舊演算法；0-RTT 有 replay 風險。舊圖卡的 Client Key Exchange、Change Cipher Spec 是 TLS 1.2。

## 即時通訊 {#1-18-18-4}

- **WebSocket**＝HTTP Upgrade 後的長連線全雙工通道（聊天室、行情、dashboard、協作）。它是通道，不是 message broker。
- **MQTT**＝pub/sub 訊息協定：client → broker → subscribers，topic、QoS 0／1／2、retained message、last will（IoT、感測器、不穩定網路）。
- MQTT 是訊息語義、WebSocket 是雙向通道，MQTT 也能跑在 WebSocket 上，兩者不是同層競品。

## 現代 Web 系統流向與 Proxy {#1-18-18-5}

```txt
Client → DNS → CDN／Edge → WAF → Load Balancer
→ Reverse Proxy／API Gateway → App Server
→ DB／Cache／Queue／Object Storage
```

- **Forward Proxy** 站在 client 那邊（公司上網控管、爬蟲代理）；**Reverse Proxy** 站在 server 那邊（TLS termination、負載平衡、routing、cache、rate limit、隱藏 origin；Nginx、HAProxy、Envoy、Traefik、AWS ALB、Cloudflare）。
- 檔案傳輸：現代用 SFTP、HTTPS、Object Storage presigned URL、rsync over SSH，不用 FTP。Mail：SMTP 寄信、IMAP 同步收信（POP3 老派），還要懂 SPF／DKIM／DMARC。
- Port：22 SSH／SFTP、25／587 SMTP、53 DNS、80 HTTP、443 HTTPS、143／993 IMAP。更多見 [1-17-3](./1-17-3.md)。
- 歷史知道名字即可：Telnet、FTP、POP3、RARP、PPP、Flash Socket。

## 網路自我檢測題（答得出來才算懂） {#1-18-18-6}

1. 為什麼家裡 IP 多是 192.168 開頭？為什麼在公司連不到家裡的電腦？（私有 IP、NAT／NAPT、內網穿透）
2. ping 不通，網路就一定不能用嗎？能 ping 通，TCP 就一定連得上嗎？（ICMP 與 TCP 路徑可能不同）
3. 斷網還能 ping 通 127.0.0.1 嗎？127.0.0.1、localhost、0.0.0.0 差在哪？
4. 程式 send() 成功，資料就真的送出去了嗎？（socket 緩衝區）
5. 沒有 accept()，TCP 連線能建立嗎？收到 RST 就一定斷線嗎？
6. TCP「粘包」是什麼？MTU 和 MSS 差在哪？為什麼 MTU 常是 1500？
7. 用 UDP 一定比 TCP 快嗎？用了 TCP 就一定不會丟包嗎？
8. 502 怎麼排查？既然有 HTTP，為什麼還要 RPC 和 WebSocket？
9. HTTPS 用公鑰加密的內容，為什麼不能用公鑰解密？DNS 為什麼同時用 UDP 和 TCP？
10. 遊戲伺服器為什麼撐得住海量連線？（I/O 多路複用：select／poll／epoll）用了 CDN 一定比較快嗎？
