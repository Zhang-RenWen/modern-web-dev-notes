# 1-9-3 前端專案化背後的專案組織設計 {#1-9-3}

::: info 改寫（2026-11）
原內容整理自 2019 年前的書籍，以 Lerna 3 + yarn 1 示範 monorepo，並逐步展示一次遷移。已改成現在的主流組合：pnpm workspace（或 npm／yarn workspace）管依賴，Turborepo／Nx 管任務與快取，Changesets 管版本與 changelog。Lerna 已由 Nx 團隊接手維護、主要剩發版功能；`lerna bootstrap` 已在 v7 移除。
:::

> 一句話：**多個相關的套件放在同一個 repo，改一處就能在所有用到它的地方立刻驗證**，但要有工具處理依賴、建置順序和發版。

## 為什麼需要 monorepo {#1-9-3-1}

例：主專案 `app` 依賴獨立 repo 的元件庫 `ui`。PM 要改 modal 的樣式：

1. 切到 `ui` repo 改程式、測試。
2. 用 `npm link` 接到 `app` 驗證（常常遇到兩份 React、路徑解析等問題）。
3. 發一版 `ui` 到 npm。
4. 回 `app` 升級版本、再測一次。

改錯一個地方就整套重來；`app` 還可能依賴好幾個這樣的套件。

| | multirepo（每個套件一個 repo） | monorepo（全部放一個 repo） |
| --- | --- | --- |
| 跨套件修改 | 要多次發版、多個 PR | 一個 PR 同時改，CI 一起驗證 |
| 依賴版本 | 各自升級，容易不一致 | 共用設定、一次升級 |
| 權限與邊界 | 天然隔離 | 要靠工具與規範（CODEOWNERS、lint 規則限制跨套件 import） |
| 規模問題 | — | repo 變大、CI 要只跑受影響的部分，否則越來越慢 |

React、Babel、Vue、Next.js 都是 monorepo：npm 上的 `react` 和 `react-dom` 是兩個套件，但在同一個 repo 開發。

## 現在的工具組合 {#1-9-3-2}

| 職責 | 工具 |
| --- | --- |
| 安裝依賴、套件之間互相連結 | **pnpm workspace**（也可用 npm、yarn workspace） |
| 依依賴順序執行任務、快取建置結果、只建置有改動的套件 | **Turborepo**、**Nx** |
| 版本號、changelog、發佈到 npm | **Changesets**（或 Lerna 的 `version`／`publish`） |

```yaml
# pnpm-workspace.yaml
packages:
  - 'apps/*'
  - 'packages/*'
```

```json
// apps/web/package.json
{ "dependencies": { "@acme/ui": "workspace:*" } }
```

`workspace:*` 讓 `apps/web` 直接連到 repo 裡的 `packages/ui`，改了 `ui` 立刻生效；發佈時會自動換成實際版本號。

## 發版流程 {#1-9-3-3}

以 Changesets 為例：

1. 開發者在 PR 裡執行 `pnpm changeset`，選擇影響了哪些套件、是 patch／minor／major，並寫一句說明。
2. 合併到 main 後，CI 自動開一個「Version Packages」PR，裡面是更新後的版本號和 changelog。
3. 合併這個 PR，CI 發佈到 npm 並打 tag。

版本策略二選一：**固定模式**（所有套件同一個版本號，Babel、Lerna 預設）或**獨立模式**（各套件自己的版本號，比較常見）。

## 依賴怎麼安裝：巢狀、扁平與 pnpm {#1-9-3-4}

A、B、C 三個套件都依賴 D，但版本不同：

| 安裝方式 | 結構 | 問題 |
| --- | --- | --- |
| npm 2 以前：巢狀 | 每個套件底下有自己的 `node_modules/D` | 重複安裝、路徑過深（Windows 路徑長度限制） |
| npm 3 起、yarn 1：扁平化 | 盡量把 D 提升到最外層，版本衝突的才放回巢狀 | **幽靈依賴**：沒寫在自己 `package.json` 的套件也 `require` 得到，換環境就壞；哪個版本被提升取決於安裝順序 |
| pnpm | 所有套件只存一份在全域內容儲存區，`node_modules` 用符號連結組成，只放自己宣告的依賴 | 嚴格：沒宣告的依賴就拿不到（這是優點），少數舊套件要設定 `public-hoist-pattern` |

pnpm 省磁碟空間、安裝快，又能杜絕幽靈依賴，是 monorepo 的首選。

鎖定檔（`pnpm-lock.yaml`、`package-lock.json`）一定要提交，CI 用 `pnpm install --frozen-lockfile`（npm 是 `npm ci`），確保每個人、每次建置裝到完全相同的版本。

## 依賴衝突怎麼查 {#1-9-3-5}

- `pnpm why react`（`npm ls react`）：查是誰把某個版本拉進來的。
- 同一個套件出現兩份（例如兩份 React 造成 Hooks 報錯）：在根目錄用 `pnpm.overrides`（npm 是 `overrides`）強制統一版本，或把它設成 `peerDependencies`。
- 元件庫、外掛類的套件，框架要寫在 `peerDependencies`，由使用方提供，避免打包進兩份。
