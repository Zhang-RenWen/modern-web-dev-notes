## 檢測地圖：要檢查什麼、用什麼檢查 {#1-5-9-1}

| 檢測面向 | 核心問題 | 首選工具 |
| --- | --- | --- |
| 結構／DOM／CSS | 畫面為什麼長這樣？ | DevTools Elements |
| JS 執行與錯誤 | 為什麼壞掉？ | DevTools Console、Sources（中斷點） |
| 網路 | 請求有沒有發、回了什麼、多慢？ | DevTools Network、mitmproxy／Charles |
| 效能 | 為什麼慢、哪裡卡？ | Performance 面板、Lighthouse、WebPageTest、CrUX |
| 記憶體 | 為什麼越用越肥？ | Memory 面板（Heap Snapshot） |
| 儲存與狀態 | Cookie、Storage、Service Worker 對不對？ | Application 面板 |
| 安全 | 標頭、憑證、XSS 風險？ | Security 面板、SSL Labs、Mozilla Observatory、OWASP ZAP |
| 無障礙 | 螢幕閱讀器、鍵盤能不能用？ | Lighthouse a11y、axe DevTools、無障礙樹 |
| SEO／結構化資料 | 搜尋引擎看得懂嗎？ | Lighthouse SEO、Search Console、Rich Results Test |
| 相容性 | 別的瀏覽器會不會壞？ | caniuse／MDN Baseline、Playwright 三引擎、BrowserStack |
| 自動化／回歸 | 每次改版都自動檢查 | Playwright、Puppeteer、Lighthouse CI |
| 線上監控 | 真實使用者遇到什麼？ | RUM（web-vitals 套件）、Sentry、Datadog |

## Chrome DevTools 面板逐一拆解 {#1-5-9-2}

快捷鍵：`F12`／`Ctrl+Shift+I`（Mac：`Cmd+Opt+I`）；`Ctrl+Shift+P` 開 **Command Menu**（所有隱藏功能都從這裡找）。

### Elements

- 即時編輯 DOM 與 CSS；`Computed` 分頁看最終樣式與它來自哪條規則。
- Box Model 可視化、Flex／Grid 疊加層（點元素旁的 `grid`／`flex` 徽章）。
- 強制狀態：右鍵 → Force state → `:hover`、`:focus` 等，檢查互動樣式。
- **DOM 中斷點**：右鍵節點 → Break on → subtree modifications，抓「是誰偷改了 DOM」。
- 2026 新增：CSS Anchor Positioning 的 position-area 互動編輯器。

### Console

- 常用工具函式：`$0`（目前選取的元素）、`$$('selector')`、`copy(obj)`、`monitorEvents(el, 'click')`、`getEventListeners(el)`、`queryObjects(Class)`。
- `console.table()` 看陣列資料、`console.time()`／`timeEnd()` 快速計時。
- **Live Expression**（眼睛圖示）：持續監看某個運算式的值。

### Sources

- 中斷點種類：一般、條件式、**Logpoint**（不停下只印 log）、XHR／fetch 中斷點、事件監聽中斷點、例外中斷點。
- **Overrides**：把線上檔案替換成本地版本，直接在正式環境測試修改（不必重新部署）。
- **Workspaces**：DevTools 改的東西直接寫回本機原始碼。Source Map 讓你在壓縮過的程式碼裡看到原始 TypeScript。

### Network

- 必看欄位：Status、Type、Initiator（是誰發起的）、Size（傳輸 vs 實際）、Time 與 **Waterfall**（DNS／連線／TLS／TTFB／下載）。
- 勾選 **Disable cache**、使用 **Throttling**（模擬慢速網路）。
- 右鍵請求 → Copy as cURL／fetch，直接在終端或程式重現。
- **Request blocking**：封鎖某個 JS 或網域，測試「第三方腳本掛掉時網站還能不能用」。**Response Override**：偽造 API 回應測試前端錯誤處理。可匯出 **HAR** 檔給後端或廠商分析。

### Performance

- 錄製後看 **Main 執行緒火焰圖**：黃色是 Scripting、紫色是 Rendering（Style／Layout）、綠色是 Painting。紅色三角形標示的 **Long Task（>50ms）**是 INP 不佳的主因。
- **Live metrics**：即時顯示 LCP、CLS、INP，並可對比真實使用者（CrUX）數據。
- **Insights** 側欄自動分析：LCP 拆解、版面位移原因、第三方影響、Render-blocking 資源。
- 用 CPU throttling（4x／6x）模擬中低階手機；2026 年新增「CPU 效能等級」覆寫，讓跨硬體的效能測試可重現。SPA 的軟導航（Soft Navigation）量測已完整支援。

### Memory

- **Heap Snapshot**：拍兩張快照比較（Comparison 檢視），找操作後沒被釋放的物件；`Detached` 開頭的 DOM 節點通常就是洩漏源（排查 SOP 見前端實戰案例）。
- **Allocation instrumentation on timeline**：看記憶體在什麼時間點、被什麼程式碼配置。

### Application

- Cookie（可看 HttpOnly、Secure、SameSite、Partitioned）、localStorage、IndexedDB、Cache Storage。
- **Service Worker**：Update on reload、Bypass for network、模擬離線、測推播。**Manifest**：檢查 PWA 是否可安裝。
- **Back/forward cache** 測試：告訴你頁面為什麼進不了 bfcache。**Clear site data**：一鍵清除該站所有狀態，重現新使用者情境。

### 其他面板

- **Security**：憑證資訊、是否有混合內容（HTTPS 頁面載入 HTTP 資源）。
- **Lighthouse**：一鍵產出效能、無障礙、最佳實務、SEO 報告。它是實驗室數據，分數會因機器狀態浮動，要跑多次取中位數。
- **Recorder**：錄下使用者操作流程，重播並量效能，可匯出成 Puppeteer／Playwright 腳本。
- **Rendering**（在 Command Menu 搜尋）：Paint flashing、Layout Shift Regions、Layer borders、模擬深色模式／減少動態／色盲。
- **Device Mode**（`Ctrl+Shift+M`）：模擬手機尺寸、DPR、觸控、地理位置、感測器。
- **Coverage**：列出沒被執行到的 JS／CSS 比例，找可以刪或延遲載入的程式碼。
- **AI 協助**：DevTools 內建的 AI 助手可解釋 Console 錯誤、分析效能錄製、解釋網路請求（需登入且依地區開放）。

## 效能檢測：實驗室數據 vs 真實數據 {#1-5-9-5}

**Core Web Vitals（2026 仍是三項）**

| 指標 | 量什麼 | 「良好」門檻 | 常見改善方向 |
| --- | --- | --- | --- |
| LCP（Largest Contentful Paint） | 主要內容多快出現 | ≤ 2.5 秒 | 優化 TTFB、預載主圖、`fetchpriority="high"`、移除 render-blocking |
| INP（Interaction to Next Paint） | 互動後多快有反應 | ≤ 200 毫秒 | 切碎長任務、`scheduler.yield()`、減少第三方 JS |
| CLS（Cumulative Layout Shift） | 版面跳動程度 | ≤ 0.1 | 圖片／廣告預留尺寸、字型 `font-display`、避免在上方插入內容 |

| 類型 | 工具 | 用途 |
| --- | --- | --- |
| 實驗室（Lab） | Lighthouse、DevTools Performance、WebPageTest | 可重現、適合除錯與 CI |
| 真實（Field／RUM） | CrUX、PageSpeed Insights 上方區塊、Search Console、`web-vitals` 套件 | 反映真實使用者，是 Google 排名採用的數據 |

**WebPageTest** 的強項：多地點、真實裝置、Filmstrip（逐格畫面）、比較兩版本、Request map 看第三方。

## 安全檢測（只對自己擁有或被授權的網站進行） {#1-5-9-6}

| 工具 | 檢查內容 |
| --- | --- |
| Mozilla HTTP Observatory | 安全標頭評分：CSP、HSTS、X-Content-Type-Options、Referrer-Policy 等 |
| securityheaders.com | 快速看回應標頭缺什麼 |
| SSL Labs Server Test | TLS 版本、加密套件、憑證鏈、已知弱點 |
| CSP Evaluator | 檢查 CSP 是否存在可被繞過的寫法 |
| OWASP ZAP／Burp Suite | 攔截代理 + 弱點掃描（XSS、SQLi、CSRF 等），用於授權的滲透測試 |
| npm audit／Snyk／Dependabot | 前端相依套件的已知漏洞 |
| Retire.js | 偵測頁面載入的過時 JS 函式庫 |

::: warning 金融業的檢查清單
CSP 有沒有 `unsafe-inline`、Session Cookie 是否 `HttpOnly + Secure + SameSite`、HSTS 是否含 preload、CORS 有沒有回 `Access-Control-Allow-Origin: *` 配 credentials、第三方腳本有沒有用 SRI（`integrity` 屬性）、錯誤訊息是否洩漏堆疊。對外系統的掃描務必走公司資安流程取得授權。
:::

## 自動化檢測與瀏覽器控制協定 {#1-5-9-7}

| 技術 | 說明 |
| --- | --- |
| **CDP（Chrome DevTools Protocol）** | DevTools 本身就是透過 CDP 控制瀏覽器；Puppeteer、Playwright 的 Chromium 驅動都建立在它上面 |
| **WebDriver BiDi** | W3C 標準化的雙向協定，目標是取代各家私有協定，讓同一套腳本跨 Chrome／Firefox／Safari |
| **Playwright** | 微軟出品，一套 API 控制 Chromium、Firefox、WebKit 三引擎；自動等待、Trace Viewer、截圖比對，E2E 首選 |
| **Puppeteer** | Google 出品，Chrome／Firefox，貼近 CDP，適合爬取與自動化 |
| **Lighthouse CI** | 在 CI 中每次 PR 跑 Lighthouse，設預算（budget）防止效能退步 |
| **Chrome DevTools MCP** | 讓 AI 編碼代理直接操作 DevTools：看 Console、錄效能、檢查 CSS、分析記憶體 |

```ts
// Playwright：跨三引擎檢查 Console 錯誤 + 截圖比對
import { test, expect } from '@playwright/test'

test('首頁沒有 Console 錯誤', async ({ page }) => {
  const errors: string[] = []
  page.on('console', (msg) => { if (msg.type() === 'error') errors.push(msg.text()) })
  page.on('pageerror', (err) => errors.push(err.message))

  await page.goto('https://localhost:3000/')
  await expect(page.locator('h1')).toBeVisible()
  await expect(page).toHaveScreenshot('home.png') // 視覺回歸
  expect(errors).toEqual([])
})
// playwright.config.ts 的 projects 設定 chromium／firefox／webkit 即可三引擎同跑
```

## 網路層深度檢測 {#1-5-9-8}

- **mitmproxy／Charles／Fiddler**：攔截代理，看手機 App 或任何裝置的 HTTPS 流量（需安裝自簽根憑證，只用於自己的裝置）。
- **Wireshark**：封包層級，看 TCP／QUIC 握手、重傳。
- **curl**：`curl -I`（只看標頭）、`curl -w` 自訂輸出各階段耗時、`--http3` 測 HTTP/3。
- **dig／nslookup**：DNS 問題排查。

## 一套標準排查流程（遇到「網站怪怪的」時） {#1-5-9-9}

1. 開無痕視窗重現 → 排除擴充功能與快取干擾。
2. Console 看紅字 → Network 看失敗請求（4xx／5xx／CORS／被封鎖）。
3. 換另一個引擎（Firefox、Safari）→ 判斷是程式問題還是引擎差異。
4. 慢 → Performance 錄製，先看 Insights，再看 Long Task 與 Waterfall。
5. 越用越慢 → Memory 兩張快照比較。
6. 只有線上壞 → Sources Overrides 在正式環境直接試修正。
7. 修好後 → 寫成 Playwright 測試，放進 CI 防止再犯。

## 名詞剖析 {#1-5-9-10}

| 名詞 | 意思 |
| --- | --- |
| Logpoint | 不暫停執行、只在經過時印出訊息的中斷點 |
| Source Map | 對照表，把壓縮、打包後的程式碼對應回原始檔案與行號 |
| Waterfall | Network 面板裡每個請求各階段（DNS、連線、TLS、等待、下載）的時間條 |
| TTFB | Time To First Byte：送出請求到收到第一個位元組的時間，反映後端與網路速度 |
| HAR | HTTP Archive，把一整段網路請求存成 JSON 檔方便分享分析 |
| 火焰圖 | 橫軸是時間、縱向是呼叫堆疊的圖，越寬的區塊耗時越久 |
| Lab vs Field（RUM） | 實驗室數據是在固定環境模擬量的；RUM 是真實使用者瀏覽器回傳的 |
| CrUX | Chrome UX Report，Google 收集的 Chrome 使用者真實效能數據 |
| Coverage | 統計載入的 JS／CSS 實際被執行的比例 |
| SRI | Subresource Integrity：在 script 標籤放檔案雜湊，內容被竄改就拒絕執行 |
| CDP／WebDriver BiDi | 程式化控制 Chrome 的協定／W3C 標準化的瀏覽器自動化協定 |
| 視覺回歸 | 截圖與基準圖逐像素比對，抓出非預期的畫面變化 |
| MCP | Model Context Protocol：讓 AI 代理用標準介面呼叫外部工具的協定 |
| 攔截代理 | 夾在裝置與伺服器中間，解密並顯示 HTTPS 流量的工具（需信任它的根憑證） |
