> 一句話：**函式記得自己「被定義時」所在的作用域**，就算那個作用域的函式早就執行完了。

## 作用域與提升 {#1-3-2-1}

JavaScript 的作用域在**寫程式時就決定**（詞法作用域），不是看在哪裡呼叫：全域、模組、函式、區塊（`{}`）四種。

| 宣告 | 作用域 | 提升 | 宣告前使用 |
| --- | --- | --- | --- |
| `var` | 函式 | 提升並初始化成 `undefined` | 得到 `undefined` |
| `let`／`const`／`class` | 區塊 | 提升但**不初始化** | `ReferenceError`（暫時性死區 TDZ） |
| `function` 宣告 | 函式（嚴格模式下是區塊） | 整個函式一起提升 | 可以呼叫 |

```js
console.log(a) // undefined
var a = 1
console.log(b) // ReferenceError：b 在 TDZ 裡
let b = 2
```

預設參數也有 TDZ，參數由左到右初始化：

```js
function f(x = y, y) {}
f(undefined, 1) // ReferenceError：初始化 x 時 y 還在 TDZ
f(null, 1)      // OK：傳 null 不會觸發預設值
```

函式宣告和同名 `var` 同時存在時，函式先提升，之後執行到 `var` 的賦值才會覆蓋：

```js
var bar = () => 'bar2'
function bar() { return 'bar1' }
bar() // 'bar2'（不論兩段順序怎麼放都一樣）
```

## 執行上下文與呼叫堆疊 {#1-3-2-2}

每次呼叫函式，引擎會建立一個**執行上下文**，裡面有：這次呼叫的變數（詞法環境）、指向外層環境的參考、`this`。上下文推進**呼叫堆疊**，函式結束就彈出。

找變數時，從目前的環境沿著「外層參考」一路往外找，直到全域，這條路就是**作用域鏈**。因為外層參考在**定義時**就決定，所以：

```js
function foo() {
  const a = 2
  return function inner() { console.log(a, c) }
}
function bar() {
  const c = 100
  foo()() // 印出 2，接著 ReferenceError：c is not defined
}
bar()
```

`inner` 是在 `foo` 裡定義的，它的外層是 `foo` 和全域，不是呼叫它的 `bar`。

## 閉包 {#1-3-2-3}

一般來說函式結束後，它的區域變數就可以回收。但如果裡面定義的函式被傳到外面，而且用到了這些變數，變數就會留下來，這個「函式 + 它記住的環境」就是閉包。

```js
function createCounter() {
  let count = 0 // 外界碰不到，只能透過回傳的函式操作
  return { inc: () => ++count, get: () => count }
}
const c = createCounter()
c.inc(); c.inc()
c.get() // 2
```

在 DevTools 的 Sources 面板對 `inc` 下中斷點，右邊 Scope 會看到一區 **Closure (createCounter)**，裡面就是 `count`。

| 常見用途 | 例子 |
| --- | --- |
| 私有狀態 | 上面的計數器；class 現在也可以用 `#count` 私有欄位 |
| 函式工廠、部分套用 | `const add = (a) => (b) => a + b` |
| 保留計時器、狀態 | `debounce`、`throttle`、`once`、memoize |
| 框架 | React Hooks 靠閉包記住每次渲染的 props／state；Redux middleware 是三層閉包 |

## 經典題：迴圈與閉包 {#1-3-2-4}

```js
const fns = []
for (var i = 0; i < 3; i++) fns.push(() => i)
fns.map((f) => f()) // [3, 3, 3]：三個函式共用同一個 i
```

`var` 是函式作用域，整個迴圈只有一個 `i`；迴圈跑完 `i` 是 3。改成 `let` 就是 `[0, 1, 2]`：`let` 在每一輪都建立新的綁定。

<ClosureLoopAnim />

```js
const next = (() => { let v = 0; return () => v++ })()
for (let i = 0; i < 10; i++) next()
next() // 10：呼叫了 10 次，v 已經加到 10，這次回傳 10 後才變 11
```

## 記憶體洩漏 {#1-3-2-5}

垃圾回收用的是**標記清除**：從全域、呼叫堆疊這些「根」出發，走得到的物件都留下，走不到的回收。所以洩漏的本質是：**不再需要的東西，還有一條路從根走得到它。**（參考計數會被循環參考卡住，現代引擎回收 JS 物件不用它。）

| 情境 | 為什麼還走得到 | 修法 |
| --- | --- | --- |
| 移除了 DOM 節點，但變數或陣列還存著它 | 變數 → 節點（DevTools 叫 detached element） | 移除後把參考清掉；或用 `WeakMap`／`WeakRef` 存 |
| 事件監聽沒移除 | 目標物件 → 監聽函式 → 閉包裡的資料 | 元件卸載時 `removeEventListener`，或用 `AbortController` 一次移除 |
| `setInterval`、訂閱、WebSocket 沒停 | 計時器表 → callback → 閉包 | `clearInterval`、`unsubscribe` |
| 全域變數、模組層快取一直加 | 全域 → 陣列／Map | 設上限或改用 `WeakMap` |
| 閉包抓到用不到的大物件 | 同一個函式裡的閉包共用同一個環境，其中一個用到大物件，所有閉包都會讓它留著 | 只把需要的值傳進閉包，用完設成 `null` |

```js
const controller = new AbortController()
window.addEventListener('resize', onResize, { signal: controller.signal })
window.addEventListener('scroll', onScroll, { signal: controller.signal })
controller.abort() // 一次移除所有綁了這個 signal 的監聽
```

**用 DevTools 找洩漏**：

1. Performance 面板錄一段操作，看 JS Heap、Nodes 曲線：做完操作、手動 GC（垃圾桶按鈕）後仍一直往上，就有洩漏。
2. Memory 面板拍兩張 Heap snapshot（操作前、重複操作幾次後），切到 Comparison 檢視，看哪種物件一直增加。
3. 在 snapshot 篩選 `Detached` 找脫離 DOM 卻沒被回收的節點；點選後看 Retainers，就是「誰還抓著它」。

Vue、React 元件的洩漏案例見 [1-8-2 實戰案例](./1-8-2.md)。
