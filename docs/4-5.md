# 4-5 非同步迭代

::: info 改寫（2026-11）
整理自《Practical Modern JavaScript》（2017），當時還是提案，ES2018 已成為標準。已精簡，補上現在最常見的用途：讀取 `fetch` 的串流、分頁 API、Node.js 的串流與事件。
:::

一般的迭代器 `next()` 直接回傳 `{ value, done }`；非同步迭代器的 `next()` 回傳的是 **Promise**，資料要等一下才會來。

### 4-5-1 非同步迭代器與 for await...of {#4-5-1}

物件有 `[Symbol.asyncIterator]()` 方法，就能用 `for await...of` 走訪：

```js
const interval = (ms) => ({
  [Symbol.asyncIterator]: () => ({
    next: () => new Promise((resolve) => setTimeout(() => resolve({ value: Date.now(), done: false }), ms)),
  }),
})

for await (const time of interval(1000)) {
  console.log(time) // 每秒印一次
  if (shouldStop()) break // 無限序列一定要有結束條件
}
```

`for await...of` 也能走訪一般的可迭代物件（陣列裡放 Promise 也行），會逐一等待每個元素。

### 4-5-2 非同步產生器 {#4-5-2}

`async function*` 可以同時 `await` 和 `yield`，是寫非同步迭代器最簡單的方式：

```js
// 自動翻頁：使用端只管一筆一筆拿資料
async function* fetchAll(url) {
  let next = url
  while (next) {
    const res = await fetch(next)
    const { items, nextPage } = await res.json()
    yield* items
    next = nextPage
  }
}

for await (const item of fetchAll('/api/items?page=1')) {
  if (render(item) === 'enough') break // break 會讓產生器結束，不會再請求下一頁
}
```

常見的非同步可迭代來源：

| 來源 | 寫法 |
| --- | --- |
| `fetch` 的回應串流 | `for await (const chunk of res.body.pipeThrough(new TextDecoderStream()))`（`ReadableStream` 可非同步迭代，Safari 支援較晚，必要時用 `getReader()`） |
| Node.js 讀檔串流 | `for await (const chunk of fs.createReadStream(file))` |
| Node.js 逐行讀取 | `for await (const line of readline.createInterface({ input }))` |
| Node.js 事件 | `for await (const [msg] of events.on(emitter, 'message'))` |

ES2024 的 `Array.fromAsync(asyncIterable)` 可以一次收集成陣列（無限序列不要用）。
