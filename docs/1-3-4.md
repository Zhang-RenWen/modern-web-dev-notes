# 1-3-4 資料型別判斷與轉換 {#1-3-4}

::: info 改寫（2026-11）

## 八種型別 {#1-3-4-1}

| 原始型別（值不可變，比較的是值） | 物件（比較的是參考） |
| --- | --- |
| `undefined`、`null`、`boolean`、`number`、`bigint`（ES2020）、`string`、`symbol` | `object`：一般物件、陣列、函式、`Date`、`Map`… |

## 判斷型別：四種方法各管什麼 {#1-3-4-2}

| 方法 | 適合 | 陷阱 |
| --- | --- | --- |
| `typeof x` | 原始型別、函式 | `typeof null === 'object'`（歷史 bug）；陣列、日期都是 `'object'` |
| `x instanceof Foo` | 自訂 class 的實例 | 看原型鏈，原始值永遠 `false`；跨 iframe 的陣列 `instanceof Array` 是 `false` |
| `Object.prototype.toString.call(x)` | 內建物件的精確類別 | 會被 `Symbol.toStringTag` 改寫 |
| 專用 API | 最可靠 | `Array.isArray(x)`、`Number.isNaN(x)`、`Number.isInteger(x)`、`x === null` |

```js
Object.prototype.toString.call([])         // '[object Array]'
Object.prototype.toString.call(null)       // '[object Null]'
Object.prototype.toString.call(new Date()) // '[object Date]'

// 常用的工具函式
const typeOf = (x) => Object.prototype.toString.call(x).slice(8, -1).toLowerCase()
typeOf(1n) // 'bigint'
typeOf(new Map()) // 'map'
```

`instanceof` 的原理：沿著左邊物件的原型鏈往上找，看有沒有遇到右邊的 `prototype`。

```js
function myInstanceof(obj, Ctor) {
  if (obj === null || (typeof obj !== 'object' && typeof obj !== 'function')) return false
  for (let p = Object.getPrototypeOf(obj); p; p = Object.getPrototypeOf(p)) {
    if (p === Ctor.prototype) return true
  }
  return false
}
```

`x.constructor === Foo` 也能判斷，但 `null`、`undefined` 會直接報錯，`constructor` 也可能被改掉，實務上少用。

## 型別轉換 {#1-3-4-3}

JavaScript 是動態、弱型別語言：運算時會自動轉型。極端例子是 [JSFuck](https://jsfuck.com/)，只用 `[]()!+` 六個字元就能寫出任何程式，例如 `![]` 是 `false`、`+[]` 是 `0`。

**物件轉原始值（ToPrimitive）** 依「偏好」決定先呼叫哪個方法：

| 情境 | 偏好 | 呼叫順序 |
| --- | --- | --- |
| 數學運算、比較 `<` | number | `valueOf` → `toString` |
| 字串樣板、`String(x)`、物件當屬性名 | string | `toString` → `valueOf` |
| `+`、`==` | default（`Date` 當成 string，其他當 number） | `valueOf` → `toString` |
| 有定義 `[Symbol.toPrimitive](hint)` | — | 只呼叫它，`hint` 是 `'number'`、`'string'`、`'default'` |

```js
const price = {
  valueOf: () => 100,
  toString: () => 'NT$100',
}
price + 1  // 101：+ 偏好 default → valueOf
`${price}` // 'NT$100'：字串樣板偏好 string → toString
```

**`+` 的規則**：先把物件轉成原始值；只要有一邊是字串就做字串串接，否則都轉數字相加。

```js
1 + '1'     // '11'
1 + true    // 2
1 + null    // 1
1 + undefined // NaN
[] + []     // ''：兩個空陣列 toString 都是 ''
[] + {}     // '[object Object]'
1n + 1      // TypeError：BigInt 不能和 Number 混算
```

**`==` 會轉型，`===` 不會**。除了 `x == null`（同時檢查 `null` 和 `undefined`）這個慣用法，其他一律用 `===`。

```js
null == undefined // true
null == 0         // false：null 只和 undefined 相等
'' == 0           // true
[] == false       // true：[] → '' → 0，false → 0
NaN === NaN       // false，用 Number.isNaN 或 Object.is(NaN, NaN)
```

## 參數傳遞：傳的是參考的副本 {#1-3-4-4}

JavaScript 永遠是**傳值**；物件的「值」是指向它的參考。所以：

```js
function f(obj) {
  obj.a = 2      // 透過參考改到原本的物件 → 外面看得到
  obj = { a: 3 } // 只是讓區域變數指向新物件 → 外面看不到
}
const o = { a: 1 }
f(o)
o.a // 2
```

要避免函式改到傳進來的物件，就先複製：

| 方式 | 深度 | 備註 |
| --- | --- | --- |
| `{ ...obj }`、`Object.assign({}, obj)`、`[...arr]` | 淺拷貝，只複製第一層 | 巢狀物件仍共用 |
| `structuredClone(obj)` | 深拷貝 | 2022 起瀏覽器與 Node 17+ 內建；支援 `Date`、`Map`、`Set`、循環參考；**不能**複製函式、DOM 節點、class 的原型 |
| `JSON.parse(JSON.stringify(obj))` | 深拷貝 | 舊方法：`Date` 變字串、`undefined` 和函式消失、遇到循環參考會報錯 |

## 安全取值：避免 Cannot read properties of undefined {#1-3-4-5}

以前要寫 `a && a.b && a.b[0] && a.b[0].c`，或用 lodash 的 `get`。ES2020 起直接用：

```js
const comments = obj.user?.posts?.[0]?.comments ?? []
obj.onLoad?.()   // 方法存在才呼叫
```

- `?.`（可選串連）：左邊是 `null` 或 `undefined` 就停下來，整個運算式回傳 `undefined`。
- `??`（空值合併）：只有左邊是 `null`／`undefined` 才用預設值。和 `||` 不同，`0`、`''`、`false` 會被保留。

```js
const count = 0
count || 10 // 10：0 被當成假值
count ?? 10 // 0
```
