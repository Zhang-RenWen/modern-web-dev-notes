# 15-8 FinalizationRegistry {#15-8}

::: info 新增（2026-11）
ES2021 和 [`WeakRef`](./15-7.md) 一起加入。一般應用程式很少需要它，但看得懂它在做什麼，讀函式庫原始碼時會用到。
:::

`FinalizationRegistry` 讓你登記一個物件，**等它被垃圾回收之後**，呼叫你指定的清理函式。

```js
const registry = new FinalizationRegistry((heldValue) => {
  console.log(`${heldValue} 已被回收`)
})

let user = { name: 'Ann' }
registry.register(user, 'user Ann') // 第二個參數會傳給清理函式

user = null // 之後某個時間點（也可能永遠不會）印出「user Ann 已被回收」
```

## 最重要的限制：不保證會執行 {#15-8-1}

垃圾回收什麼時候發生、會不會發生，由引擎決定。所以清理函式：

- **可能很晚才執行**，晚多久無法預測。
- **可能永遠不執行**：分頁關閉、程式結束、物件一直沒被回收，或 registry 本身先被回收了。
- 不會同步執行，最早也要等目前的工作（task）結束之後。

因此它**不能用來做一定要完成的事**：儲存資料、關閉資料庫連線、離開頁面前送出紀錄，都要在程式裡明確呼叫（`close()`、`dispose()`，或用 `using` 宣告搭配 `Symbol.dispose`）。`FinalizationRegistry` 只適合當「忘記清理時的保險」或「省一點記憶體」的最佳化。

## API {#15-8-2}

| 方法 | 說明 |
| --- | --- |
| `new FinalizationRegistry(callback)` | 建立 registry，`callback(heldValue)` 是清理函式 |
| `register(target, heldValue, token?)` | 登記 `target`；回收後用 `heldValue` 呼叫清理函式。`token` 是之後取消登記用的鑰匙 |
| `unregister(token)` | 取消用這個 `token` 登記的項目，有取消到就回傳 `true` |

幾個容易踩的地方：

- `target` 必須是物件（或沒有登記過的 Symbol）。
- **`heldValue` 不能是 `target` 本身**，否則會拋出 `TypeError`。
- registry 會**強參照** `heldValue`：如果 `heldValue` 裡面又參照到 `target`，`target` 永遠不會被回收。`heldValue` 通常放 ID、字串，或是外部資源的 handle。
- `token` 是弱參照，所以直接把 `target` 自己當 `token` 是常見寫法。

## 用途一：WeakRef 快取，清掉失效的項目 {#15-8-3}

用 `Map` 存 `WeakRef` 可以做一個「不阻止回收」的快取，但物件被回收後，`Map` 裡還留著空的 `WeakRef` 和它的 key。用 `FinalizationRegistry` 把這些 key 清掉：

```js
const cache = new Map()

const registry = new FinalizationRegistry((key) => {
  // 回收發生前，這個 key 可能已經被放進新的值，要確認是舊的才刪
  const ref = cache.get(key)
  if (ref && !ref.deref()) cache.delete(key)
})

function setCache(key, value) {
  cache.set(key, new WeakRef(value))
  registry.register(value, key)
}

function getCache(key) {
  return cache.get(key)?.deref() // 已被回收就是 undefined，呼叫端要重新產生
}
```

## 用途二：忘記釋放外部資源時的保險 {#15-8-4}

JavaScript 物件包著 JS 管不到的資源時（例如 WebAssembly 裡配置的記憶體），正常流程是使用者呼叫 `close()`；萬一忘了，物件被回收時至少還能補救。wasm-bindgen 這類工具就提供這種機制。

```js
const registry = new FinalizationRegistry((handle) => {
  console.warn('資源沒有被 close()，由 GC 補救釋放')
  releaseNative(handle)
})

class NativeBuffer {
  #handle

  constructor(size) {
    this.#handle = allocateNative(size)
    registry.register(this, this.#handle, this) // heldValue 是 handle，不是 this
  }

  close() {
    releaseNative(this.#handle)
    registry.unregister(this) // 已經手動釋放，不需要補救
  }

  [Symbol.dispose]() {
    this.close()
  }
}
```

`allocateNative`、`releaseNative` 代表實際配置與釋放資源的函式。

## 自己觀察回收 {#15-8-5}

在 Node.js 加上 `--expose-gc` 參數，就能用 `gc()` 要求立刻回收，方便練習時觀察：

```js
// node --expose-gc demo.mjs
const registry = new FinalizationRegistry((v) => console.log('回收：', v))

let obj = {}
registry.register(obj, 'obj')
obj = null

await new Promise((r) => setTimeout(r, 0)) // 先讓目前的工作結束
gc()
await new Promise((r) => setTimeout(r, 0)) // 清理函式在之後的工作才執行
// 回收： obj（大多數情況下）
```

即使這樣也只是「大多數情況下」會印出來，正式程式碼不能依賴這個行為。在瀏覽器開發者工具裡把物件印到 console，console 本身也會參照它，讓它無法被回收。
