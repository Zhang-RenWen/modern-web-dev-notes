## 選語言的判斷框架 {#1-21-1}

- 不看單一排行榜：TIOBE＝討論熱度；Stack Overflow Survey＝實際使用率；GitHub Octoverse＝新專案趨勢；薪資榜＝稀缺性（小眾高薪 ≠ 好入門、好找工作）。
- 依「用途 × 產業 × 職缺量 × 個人路線」選，不依潮流。
- 2026 分層
  - 第一梯隊：TypeScript、Python、SQL、Java、C#、C/C++
  - 第二梯隊（看方向）：Go（雲端／微服務／Infra）、Rust（安全系統／WASM／工具）、Kotlin、Swift、R
  - 小眾高薪（不押主線）：Clojure、F#、Elixir／Erlang、Haskell、Scala、Perl／COBOL
- 金融業主線組合：TypeScript + SQL + Java（台灣金融較常見）／C# + Python；Go 補 infra。
- 型別分類是光譜：靜態／動態看「何時檢查」；強／弱看「隱式轉換多寡」。

> 沒有最好的語言，只有最適合的。寫好 Rust 比寫好 Go 難得多，很多時候只是品味與決策問題。

## C++／系統路線：AI 把瓶頸推回硬體 {#1-21-2}

- **現象**：2026 年 C++ 職缺增加，是 AI 從應用層往系統／硬體層擴張：Python → PyTorch → C++ runtime → CUDA → GPU。PyTorch 本身是 C++，Python 只是包裝層。
- **需求來源**：AI inference／runtime、GPU／CUDA、Robotics／自駕（real-time、SIMD、DMA、ROS2）、Edge AI、車載、HFT、資料庫／瀏覽器／遊戲引擎。2026 初 2,724 個 robotics 職缺中 27.8% 提到 C++，且常與 Python 同時要求。
- **真正的難點**：語法不難，難在 Object Lifetime、Ownership、RAII、Copy／Move、Concurrency、Memory／Cache——這也是 AI 最難替人安全接手的部分。
- **C++ 的 OOP**：multi-paradigm，簡單資料就用 `struct` + `vector`，不要層層 AbstractFactory。
- **時間分配**：30% DSA／LeetCode（Medium 能穩定拆解即可）＋ 40% C++ Systems ＋ 30% 作品。
- **6 個月路線**
  1. 1–2 月：Modern C++（C++17/20、RAII、smart pointer、move、STL、template）
  2. 3–4 月：Systems（thread／mutex／atomic、socket、mmap、cache、CMake、GDB、profiling）
  3. 5–6 月：CUDA、GPU memory、kernel，開始讀 inference runtime
- **作品**：Web UI → API Gateway → C++ Service → Task Queue／Thread Pool → CUDA Inference，附 P50/P95/P99、QPS、VRAM、GPU utilization、不同 batch size 的 throughput。
- **Benchmark 練習**：vector vs list vs deque、map vs unordered_map、single thread vs thread pool、mutex vs atomic、copy vs move——用 profiler 看 cache miss 與 allocation，讓「會資料結構」變成工程能力。
- **學歷**：能把競爭從履歷訊號移到可驗證能力；研究、晶片、特定碩博職缺的硬門檻仍在。若讀碩士，選 Systems／Distributed／HPC／AI Systems，讓學習、作品、學位指向同一方向。
- 初學資源：台大開放式課程「孔令傑 程式設計」＋ CSES 題庫，卡住就問 AI。

## Rust：安全的代價與 Rust for Linux 的教訓 {#1-21-3}

- **價值**：微軟每年登記的漏洞約七成是記憶體安全問題。Rust 無 GC，靠 ownership 在編譯期決定釋放時機，速度與 C/C++ 同級。Android 改用記憶體安全語言後，記憶體漏洞占比由 2019 年 76% 降到 2024 年 24%。
- **限制**：為了預測記憶體形狀犧牲直接存取；與既有 C 做 FFI 時又回到不安全；寫 OS／driver 需 `no_std` + `unsafe`，MCU 生態仍不成熟。
- **Rust for Linux 衝突的本質**：Rust 用型別在「個體層」綁定資源與流程（與 C++ RAII 一脈相承）；核心開發者重視「整體層」調度的彈性。
  - SQLite 把整個 DB 放在一個檔案，一個 transaction 只 open/close 一次，讀寫比檔案系統快約 35%。
  - CPU 亂序執行分析整段依賴關係，同一段程式從 5 個 cycle 壓到 3 個。
  - 結論：越接近底層，越需要從整體批次處理消除個體 overhead；安全與彈性是取捨，不是對錯。
- **學習順序**：目標是理解底層 → C → C++ → Rust；目標是寫高效能服務 → 先 Rust。資源：[play.rust-lang.org](https://play.rust-lang.org)、Rustlings。

## 每學一門語言，先搞懂它的記憶體模型 {#1-21-4}

- Python：所有值都是 heap 上的物件，int 也 immutable；變數記在 namespace 表（區域、全域各一張），assign 只是改指向——跟 C# 的 value／reference type 完全不同。

- **Python 的定位**（整理自 Notion「語言特性 › Python」）：語法簡潔、用縮排劃分區塊，函式庫生態龐大，主要用在資料處理與分析（pandas）、AI 與機器學習（PyTorch、scikit-learn）、Web 後端（Django、FastAPI、Flask）、自動化測試與爬蟲（Selenium、Playwright、BeautifulSoup）。缺點是執行速度較慢（直譯執行，CPython 有 GIL；3.13 起有實驗性的無 GIL 版本），以及強制縮排。學 Python 很快，但只會呼叫函式庫容易忽略底層運作，打基礎可以搭配 C。
- **Ruby on Rails**（整理自 Notion「語言特性 › Ruby on Rails」）：Ruby 是直譯式語言，Rails 是以「慣例優於設定」聞名的全端框架，規範比 PHP 嚴謹、開發速度快，早期的 GitHub、Shopify、Airbnb 都用它起家，適合新創快速驗證市場；可以部署在便宜的 Linux 主機上。

## Java 與 OOP {#1-21-5}

- 四大概念：封裝（狀態只能透過方法改，如 `order.pay()`、`order.cancel()`）、抽象（依賴穩定介面）、繼承（只用在明確的 is-a）、多型（同介面不同實作，減少 if-else）。
- 現代實務：interface + composition + DI，優先組合而非深層繼承。後端最常見的形態是 `UserRepository`、`PaymentService`、`NotificationService` 搭配不同實作。
- Java 基礎坑：String 是 class，內容比較用 `.equals()` 不用 `==`；`int / int` 是整數除法；int 會 overflow；金額用 `BigDecimal`；新式 `switch ->` expression；token 不可用 `Math.random()`。
- Class vs Struct：不要背「class 在 heap、struct 在 stack」，依語言實作而定。
- 面試短答：OOP 是把資料與行為組織成物件，以封裝、抽象、繼承、多型管理複雜度。
- 用 TypeScript 學 OOP 並對照 Java 見 [1-25 TypeScript 與物件導向](./1-25.md)。

## Go 學習地圖 {#1-21-6}

定位：Go 的價值不在語法，而在「簡潔 ＋ 高併發 ＋ context ＋ 顯式 error ＋ 好部署 ＋ 雲原生」。

1. 語法：slice／map／struct／interface／goroutine／channel；switch 不需 break、少用 fallthrough；`type A string` 是新型別，`type A = string` 才是 alias。
2. 現代必備：Go Modules、error wrapping（`%w`、`errors.Is`／`errors.As`）、context、generics、table-driven test。
3. 後端：net/http、middleware、database/sql、transaction、connection pool、graceful shutdown。
4. 併發穩定性：WaitGroup、Mutex、select、worker pool、`go test -race`、pprof、goroutine leak。
5. 部署：Docker、K8s、metrics／tracing、CI/CD。

（Go 1.22 起 for range 迴圈變數每次迭代獨立，舊教材的 closure 陷阱已改善。）

## 工程判斷案例 {#1-21-7}

### TypeScript 7 為何用 Go 重寫（技術選型）

- 目標是 native port（逐函式一對一翻譯），不是 rewrite，確保相容。
- 排除法：生態要成熟 → 要編譯語言（排除 Python／Ruby）→ 要貼近 TS 的函數式寫法（排除 Java／C#／C++）→ 要相同 GC 語意、能直接寫循環資料結構（排除 Rust）→ 只剩 Go。
- 10 倍是「編譯速度」：原生編譯約 3 倍 × 多執行緒。
- 啟示：選型先定義約束條件，再用排除法，不是比誰最潮。

### 命名三要三不要

- 要有資訊量：需要旁邊加註解，就代表名字不夠好（`reportCutoffDate`，不是 `date1`）。
- 要有區分度並預留擴充：`generateShopOrdersReport`、`generateWarehouseInventoryReport`。
- boolean 用提問式：`isAdmin`、`hasInventory`、`canBeProcessed`。
- 不要自創縮寫（`genrep`），只用約定俗成的（info、spec、tmp）。
- 不要為了統一而卡同義詞（delete／remove）；只要無歧義、不增加維護成本就接受。
- SQL 關鍵字維持全大寫：一眼分辨語法與小寫欄位。

## C++ 深入 {#1-21-8}

### C++ 用在哪裡 {#1-21-8-1}

核心價值不是「什麼都用它寫」，而是**需要效能、記憶體控制、低延遲、直接控制硬體，或維護大型 native 系統時，很難被完全取代**。

| 領域 | 用途 |
| --- | --- |
| 遊戲 | 引擎、物理、渲染（Unreal） |
| 系統軟體 | 作業系統元件、瀏覽器、資料庫 |
| 機器人、車用 | ROS、感測器與控制、ADAS、ECU，要求即時性 |
| 金融 | 高頻交易、撮合引擎，要求微秒級延遲 |
| 圖形與影像 | 3D 渲染、影像處理 |
| AI 基礎設施 | 推論引擎、runtime、CUDA 周邊 |
| 嵌入式 | MCU、IoT、韌體（常與 C 並存） |
| 基礎設施 | 儲存、網路、訊息系統 |

每天用的高階工具底下常常就是 C/C++：`TypeScript → Node.js → V8（C++）→ OS`；`Python → PyTorch → C++／CUDA → GPU`。

AI 沒有讓 C++「復活」，而是讓大量運算重新往貼近硬體的軟體移動（GPU、NPU、邊緣裝置），C++ 原本的優勢因此又變得重要；同時 AI 工具能解釋編譯錯誤、產生樣板、補測試，降低了 C++ 難寫的成本。不過韌體很多仍是 C 與 C++ 並存，AI 應用上層仍大量是 Python。

**要不要學**：主要做 SaaS、Web、一般後端與企業系統，不需要把 C++ 當主力，TypeScript、Java、Go、Python 的投入產出比高得多。但如果想把「框架到底幫我藏了什麼」一路往下打穿到網路、作業系統、記憶體，C++ 是很好的**拆開抽象層的學習工具**：自己寫 TCP server、thread pool、memory pool、簡易 HTTP server，再回頭看 Node.js，很多黑盒會變透明。

### 為什麼科技公司的職缺常寫 C++ {#1-21-8-2}

技術棧越往下，效能、延遲、記憶體、併發、硬體越重要，這是 C++ 的主場：

```txt
產品層       React / Vue / TypeScript
服務層       Java / Go / Python / Node.js
基礎設施     C++ / Rust / C
             OS / Network / Memory / CPU / GPU
```

AI 公司表面上是 `model.generate()`，真正難的是「這批推論為什麼多 8ms」「GPU 記憶體為什麼爆了」「這裡是不是多複製了一次」「執行緒在哪裡搶鎖」「cache miss 為什麼這麼多」，這時候 JS、Java、Python 的抽象層太高。

另一個原因是 **C++ 是能力篩選器**：真的會 C++ 的人，通常被迫碰過記憶體、指標與參考、stack／heap、物件生命週期、RAII、執行緒、編譯與連結、建置系統、效能分析。越接近大型科技公司的核心工程，語言本身反而越不是重點，真正考的是 DSA、系統設計、OS、網路、併發、分散式系統，而 C++ 很容易一次暴露這些能力。

建議路線：不必「背完 C++」或轉職純 C++，而是 `現有 Web 能力 → Linux／網路／OS → C++ 基礎 → 記憶體與生命週期、RAII → 執行緒與併發 → 自己做 TCP server、thread pool → 效能分析 → 回頭理解 Node.js、JVM、資料庫`。

### C++ 的物件導向：多典範語言 {#1-21-8-3}

C++ 具備完整的 OOP（封裝、繼承、多型），從 Java、C# 看過去很熟悉：

```cpp
class Animal {
private:
    std::string name;                 // 封裝
public:
    explicit Animal(std::string n) : name(std::move(n)) {}
    virtual ~Animal() = default;
    virtual void speak() const { std::cout << "..."; }   // 多型
};

class Dog : public Animal {           // 繼承
public:
    using Animal::Animal;
    void speak() const override { std::cout << "Woof"; }
};

Dog dog("Lucky");
const Animal& animal = dog;
animal.speak();                       // Woof
```

但 C++ 不是「以 OOP 為中心」的語言，而是多典範：程序式、OOP、泛型（template）、偏函數式、編譯期計算、低階系統程式設計。現代 C++ 不鼓勵層層 `AbstractFactory → BaseManager → ConcreteManager`，簡單資料就用 `struct` + `std::vector` 表示。

C++ 的 OOP 也比 Java「赤裸」：虛擬函式派發、物件記憶體佈局、建構與解構、copy／move、生命週期都直接暴露給你。真正的難關不是 `class`，而是 **物件生命週期 + 所有權 + RAII + 指標／參考 + copy／move 語意**。

### 為什麼 C++ 有一堆「靈異」bug {#1-21-8-4}

C++ 非常照邏輯跑，只是它的邏輯常常不是你腦中那套。它相信你：你說這是一個位址，它就讓你讀，至於那塊記憶體還是不是你的，是你的責任。

```cpp
int* p = new int(10);
delete p;
std::cout << *p;      // use-after-free：未定義行為

int a[3] = {1, 2, 3};
std::cout << a[10];   // 越界：可能印出亂數、0，或 Debug 正常 Release 崩潰
```

這類錯誤屬於 **未定義行為（UB）**：程式違反語言規則後，標準不再保證任何結果。編譯器還會假設「合法程式不會發生 UB」來重排或刪除程式碼，所以實際執行的順序不等於你逐行讀的順序。常見來源：記憶體生命週期、懸空指標與參考、iterator 失效、緩衝區溢位、data race、有號整數溢位、未初始化的值、移動後再使用。錯誤往往不是立刻報錯，而是三百行之後才爆。

| 語言 | 態度 |
| --- | --- |
| JS、Python | 危險的事我幫你處理 |
| Java、C# | 給你一些控制權，但 GC 和 runtime 幫你守住很多東西 |
| Rust | 危險操作？先向編譯器證明你沒搞錯 |
| C++ | 你是工程師，你知道自己在做什麼吧？ |

**把玄學 bug 壓到最低的工作流**：

1. 編譯器警告拉滿並視為錯誤：`-Wall -Wextra -Wpedantic -Wconversion -Werror`。
2. Debug build 永遠開 Sanitizer：`-fsanitize=address,undefined`（越界、use-after-free、double free、有號溢位、null 解參考）；多執行緒另外跑 `-fsanitize=thread`。開了之後「怎麼印出 948712」會直接變成 `heap-buffer-overflow` 的明確錯誤。
3. 不用裸的 `new`/`delete`/`malloc`/`free`，優先 `std::vector`、`std::string`、`std::array`、`std::unique_ptr`；真的需要共享所有權才用 `std::shared_ptr`。
4. 看到指標就要能回答：誰擁有它？誰負責釋放？能活多久？可以是 `nullptr` 嗎？參考會不會比物件活得久？答不出來就先別往下寫。
5. 靜態分析（clang-tidy），Debug 與 Release 都跑測試；「Debug 正常、Release 崩潰」幾乎就是 UB、race 或生命週期問題的警訊。

學習順序建議：**Stack → Heap → 指標／參考 → 物件生命週期 → RAII → UB → 編譯器最佳化**。

### 會 C++ 再學 Java 會比較順嗎 {#1-21-8-5}

通常會，因為你會開始問「這個 `user` 到底存什麼？物件在哪？誰管生命週期？」，然後看懂 Java 替你藏了哪些東西：

| C++ | Java |
| --- | --- |
| 指標／參考 | 參考抽象化 |
| `new` / `delete` / RAII | GC |
| 解構子 | GC + `try-with-resources` |
| header／source | class 與 module |
| 手動所有權 | runtime 管理 |
| template | generics（機制不同，型別擦除） |
| `virtual` | 動態派發是預設 |
| 原生執行緒 | JVM 的併發抽象 |
| 機器碼 | bytecode → JIT → 機器碼 |

但**會 C++ 不等於會 Java 生態**：語法、OOP、集合、例外、併發會很快；JVM 與 GC、Spring Boot、JPA／Hibernate、Maven／Gradle、企業架構都是新東西。目標是後端或架構師的話，不必把 C++ 練到專家才開始 Java：C++ 負責理解下面發生什麼（記憶體、OS、網路、併發、效能），Java 負責理解大型企業系統上面怎麼蓋。

## Rust 與 C++ 比較 {#1-21-9}

| 項目 | Rust | C++ |
| --- | --- | --- |
| 學習曲線 | 陡峭 | 陡峭 |
| 記憶體安全 | 編譯期強制檢查 | 主要靠開發者 |
| 記憶體管理 | Ownership／Borrowing | RAII、智慧指標、手動管理 |
| 執行效能 | 極高 | 極高 |
| 併發安全 | 編譯期保障較強 | 要自己管理更多風險 |
| Web 後端 | 生態成長中 | 相對小眾 |
| 遊戲引擎 | 生態較小 | 主流 |
| 嵌入式 | 持續發展，MCU 支援仍在成熟中 | 成熟 |
| 既有企業系統 | 較少 | 大量 |

- 依目標選：高效能 API、資料處理 → Rust 優先；遊戲引擎、既有原生系統 → C++；想徹底理解電腦怎麼運作 → C → C++ → Rust（先體會指標與生命週期的風險，再看 Rust 怎麼在編譯期限制它們）。
- 用 Rust 寫 OS 或驅動要用 `no_std`（不能依賴作業系統提供的動態記憶體配置等標準函式庫功能），而且無法完全避免 `unsafe`；市面上隨附 Rust 工具鏈與範例的單晶片開發板仍少，要取代 C 還有很長的路。
- 區分兩個概念：**控制能力**（能不能操作記憶體、執行緒、socket、檔案描述符）與**控制自由度**（語言施加多少限制）。C++ 與 Rust 控制能力都很強，C++ 允許更多不受安全規則約束的操作。但**語言本身不決定作業系統權限**：沒有管理員權限的 C++ 程式一樣不能改 Kernel；Python（ctypes、原生擴充）和 Go 一樣能呼叫系統 API。權限由 CPU 特權層級、作業系統、程序權限決定（見 [1-16-3](./1-16-3.md#1-16-3-1)、[1-16-7](./1-16-7.md)、[1-23-6 JavaScript 的能力邊界](./1-23-6.md)）。

## C++ 能建立哪些連線 {#1-21-10}

C++ 可以主動建立 TCP、UDP、Bluetooth、Serial、USB 等連線，甚至自訂封包，但仍然依賴作業系統、驅動程式與硬體。

| 連線 | 依賴 |
| --- | --- |
| TCP、UDP | OS 的 Socket API |
| HTTP／HTTPS、WebSocket | 網路函式庫（TLS、HTTP 實作） |
| Bluetooth、Wi-Fi、Ethernet | 網卡或藍牙晶片 + OS 驅動 |
| USB、Serial／UART、CAN Bus | 控制器與驅動 |
| Raw Socket | OS 權限 |

```cpp
// Linux：連線到本機 TCP 8080（不需要 Node.js 或框架，但仍走 Kernel 的 TCP/IP Stack）
#include <sys/socket.h>
#include <arpa/inet.h>
#include <unistd.h>

int main() {
    int fd = socket(AF_INET, SOCK_STREAM, 0);
    if (fd < 0) return 1;
    sockaddr_in server{};
    server.sin_family = AF_INET;
    server.sin_port = htons(8080);
    inet_pton(AF_INET, "127.0.0.1", &server.sin_addr);
    int result = connect(fd, reinterpret_cast<sockaddr*>(&server), sizeof(server));
    close(fd);
    return result == 0 ? 0 : 1;
}
```

- 能不能繞過 Kernel：Raw Socket 和 Linux 的 `AF_PACKET` 能處理較底層的封包，但仍經過 Kernel；**DPDK** 在適當的驅動、權限與硬體條件下，讓使用者空間程式直接處理網卡封包，用於高效能網路設備與電信系統；寫 Kernel Driver 則要在核心層執行。
- 和 JavaScript 的差別：瀏覽器 JS 被沙箱限制，不能開原生 TCP socket；但 Node.js 可以用 `node:net`（TCP）、`node:dgram`（UDP）。差別不是做不做得到，而是 C++ 對記憶體、執行緒、封包處理有更細的控制。
- C++ 標準函式庫沒有完整的跨平台 socket API，可以停在不同抽象層：Boost.Asio、Qt（高階）→ POSIX socket、Winsock（中階）→ Raw socket、系統呼叫（低階）→ 驅動、Kernel、硬體暫存器。
- 練習建議：先不用框架，用 Linux + C/C++ 原生 API 親手寫 TCP server、UDP server、檔案 I/O、多執行緒。
