## 選語言的判斷框架 {#1-21-1}

- 不看單一排行榜：TIOBE＝討論熱度；Stack Overflow Survey＝實際使用率；GitHub Octoverse＝新專案趨勢；薪資榜＝稀缺性（小眾高薪 ≠ 好入門、好找工作）。
- 依「用途 × 產業 × 職缺量 × 個人路線」選，不依潮流。
- 2026 分層
  - 第一梯隊：TypeScript、Python、SQL、Java、C#、C/C++
  - 第二梯隊（看方向）：Go（雲端／微服務／Infra）、Rust（安全系統／WASM／工具）、Kotlin、Swift、R
  - 小眾高薪（不押主線）：Clojure、F#、Elixir／Erlang、Haskell、Scala、Perl／COBOL
- 金融業主線組合：TypeScript + SQL + Java（台灣金融較常見）／C# + Python；Go 補 infra。
- 型別分類是光譜：靜態／動態看「何時檢查」；強／弱看「隱式轉換多寡」。

> 沒有最好的語言，只有最適合的。寫好 Rust 比寫好 Go 難得多，很多時候只是品味與決策問題。

## C++／系統路線：AI 把瓶頸推回硬體 {#1-21-2}

- **現象**：2026 年 C++ 職缺增加，是 AI 從應用層往系統／硬體層擴張：Python → PyTorch → C++ runtime → CUDA → GPU。PyTorch 本身是 C++，Python 只是包裝層。
- **需求來源**：AI inference／runtime、GPU／CUDA、Robotics／自駕（real-time、SIMD、DMA、ROS2）、Edge AI、車載、HFT、資料庫／瀏覽器／遊戲引擎。2026 初 2,724 個 robotics 職缺中 27.8% 提到 C++，且常與 Python 同時要求。
- **真正的難點**：語法不難，難在 Object Lifetime、Ownership、RAII、Copy／Move、Concurrency、Memory／Cache——這也是 AI 最難替人安全接手的部分。
- **C++ 的 OOP**：multi-paradigm，簡單資料就用 `struct` + `vector`，不要層層 AbstractFactory。
- **時間分配**：30% DSA／LeetCode（Medium 能穩定拆解即可）＋ 40% C++ Systems ＋ 30% 作品。
- **6 個月路線**
  1. 1–2 月：Modern C++（C++17/20、RAII、smart pointer、move、STL、template）
  2. 3–4 月：Systems（thread／mutex／atomic、socket、mmap、cache、CMake、GDB、profiling）
  3. 5–6 月：CUDA、GPU memory、kernel，開始讀 inference runtime
- **作品**：Web UI → API Gateway → C++ Service → Task Queue／Thread Pool → CUDA Inference，附 P50/P95/P99、QPS、VRAM、GPU utilization、不同 batch size 的 throughput。
- **Benchmark 練習**：vector vs list vs deque、map vs unordered_map、single thread vs thread pool、mutex vs atomic、copy vs move——用 profiler 看 cache miss 與 allocation，讓「會資料結構」變成工程能力。
- **學歷**：能把競爭從履歷訊號移到可驗證能力；研究、晶片、特定碩博職缺的硬門檻仍在。若讀碩士，選 Systems／Distributed／HPC／AI Systems，讓學習、作品、學位指向同一方向。
- 初學資源：台大開放式課程「孔令傑 程式設計」＋ CSES 題庫，卡住就問 AI。

## Rust：安全的代價與 Rust for Linux 的教訓 {#1-21-3}

- **價值**：微軟每年登記的漏洞約七成是記憶體安全問題。Rust 無 GC，靠 ownership 在編譯期決定釋放時機，速度與 C/C++ 同級。Android 改用記憶體安全語言後，記憶體漏洞占比由 2019 年 76% 降到 2024 年 24%。
- **限制**：為了預測記憶體形狀犧牲直接存取；與既有 C 做 FFI 時又回到不安全；寫 OS／driver 需 `no_std` + `unsafe`，MCU 生態仍不成熟。
- **Rust for Linux 衝突的本質**：Rust 用型別在「個體層」綁定資源與流程（與 C++ RAII 一脈相承）；核心開發者重視「整體層」調度的彈性。
  - SQLite 把整個 DB 放在一個檔案，一個 transaction 只 open/close 一次，讀寫比檔案系統快約 35%。
  - CPU 亂序執行分析整段依賴關係，同一段程式從 5 個 cycle 壓到 3 個。
  - 結論：越接近底層，越需要從整體批次處理消除個體 overhead；安全與彈性是取捨，不是對錯。
- **學習順序**：目標是理解底層 → C → C++ → Rust；目標是寫高效能服務 → 先 Rust。資源：[play.rust-lang.org](https://play.rust-lang.org)、Rustlings。

## 每學一門語言，先搞懂它的記憶體模型 {#1-21-4}

- Python：所有值都是 heap 上的物件，int 也 immutable；變數記在 namespace 表（區域、全域各一張），assign 只是改指向——跟 C# 的 value／reference type 完全不同。

## Java 與 OOP {#1-21-5}

- 四大概念：封裝（狀態只能透過方法改，如 `order.pay()`、`order.cancel()`）、抽象（依賴穩定介面）、繼承（只用在明確的 is-a）、多型（同介面不同實作，減少 if-else）。
- 現代實務：interface + composition + DI，優先組合而非深層繼承。後端最常見的形態是 `UserRepository`、`PaymentService`、`NotificationService` 搭配不同實作。
- Java 基礎坑：String 是 class，內容比較用 `.equals()` 不用 `==`；`int / int` 是整數除法；int 會 overflow；金額用 `BigDecimal`；新式 `switch ->` expression；token 不可用 `Math.random()`。
- Class vs Struct：不要背「class 在 heap、struct 在 stack」，依語言實作而定。
- 面試短答：OOP 是把資料與行為組織成物件，以封裝、抽象、繼承、多型管理複雜度。

## Go 學習地圖 {#1-21-6}

定位：Go 的價值不在語法，而在「簡潔 ＋ 高併發 ＋ context ＋ 顯式 error ＋ 好部署 ＋ 雲原生」。

1. 語法：slice／map／struct／interface／goroutine／channel；switch 不需 break、少用 fallthrough；`type A string` 是新型別，`type A = string` 才是 alias。
2. 現代必備：Go Modules、error wrapping（`%w`、`errors.Is`／`errors.As`）、context、generics、table-driven test。
3. 後端：net/http、middleware、database/sql、transaction、connection pool、graceful shutdown。
4. 併發穩定性：WaitGroup、Mutex、select、worker pool、`go test -race`、pprof、goroutine leak。
5. 部署：Docker、K8s、metrics／tracing、CI/CD。

（Go 1.22 起 for range 迴圈變數每次迭代獨立，舊教材的 closure 陷阱已改善。）

## 工程判斷案例 {#1-21-7}

### TypeScript 7 為何用 Go 重寫（技術選型）

- 目標是 native port（逐函式一對一翻譯），不是 rewrite，確保相容。
- 排除法：生態要成熟 → 要編譯語言（排除 Python／Ruby）→ 要貼近 TS 的函數式寫法（排除 Java／C#／C++）→ 要相同 GC 語意、能直接寫循環資料結構（排除 Rust）→ 只剩 Go。
- 10 倍是「編譯速度」：原生編譯約 3 倍 × 多執行緒。
- 啟示：選型先定義約束條件，再用排除法，不是比誰最潮。

### 命名三要三不要

- 要有資訊量：需要旁邊加註解，就代表名字不夠好（`reportCutoffDate`，不是 `date1`）。
- 要有區分度並預留擴充：`generateShopOrdersReport`、`generateWarehouseInventoryReport`。
- boolean 用提問式：`isAdmin`、`hasInventory`、`canBeProcessed`。
- 不要自創縮寫（`genrep`），只用約定俗成的（info、spec、tmp）。
- 不要為了統一而卡同義詞（delete／remove）；只要無歧義、不增加維護成本就接受。
- SQL 關鍵字維持全大寫：一眼分辨語法與小寫欄位。
