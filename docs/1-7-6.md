## Cloud / AWS 架構 {#1-7-6-1}

**先記問題類型，最後才記服務名**（Azure 只做概念映射，不要「Azure X = AWS Y」死記，語意與保證不同）。

| 架構問題 | 通用概念 | AWS |
| --- | --- | --- |
| 跑後端程式 | Compute / Container / Serverless | EC2 / ECS / Fargate / EKS / Lambda |
| API 入口 | API Gateway | API Gateway |
| 檔案 | Object Storage | S3 |
| 關聯式 / NoSQL / 快取 | RDBMS / NoSQL / Cache | RDS·Aurora / DynamoDB / ElastiCache |
| 非同步 / 發布訂閱 / 事件 | Queue / Pub-Sub / Event-driven | SQS / SNS / EventBridge |
| 身份 / 權限 / 密鑰 | AuthN / IAM / Secrets | Cognito / IAM / Secrets Manager |
| CDN / DNS | CDN / DNS | CloudFront / Route 53 |
| 觀測 | Observability | CloudWatch |
| 基礎設施即程式碼 | IaC | CloudFormation / CDK / Terraform |

**最小架構骨架**：

```txt
Client → CDN → API Gateway → Backend ─── Database
                                │  └──── Cache
                                ├── Object Storage
                                └── Queue → Worker
外圍：AuthN/AuthZ、Logging、Metrics、Tracing、Secrets、LB、Auto Scaling、Backup、CI/CD
```

**架構師的核心是決策**：同步 vs 非同步、SQL vs NoSQL、Cache vs 直查 DB、Monolith vs Microservices、EC2 vs Container vs Serverless、強一致 vs 最終一致、Scale Up vs Out、自管 vs Managed、可用性 vs 成本、效能 vs 複雜度。

**資料 Pipeline**：Data Source（Crawler / API / Webhook）→ Queue / Stream（Kafka、Kinesis）→ Raw Storage（S3）→ ETL/ELT（Spark、Glue）→ Warehouse（Redshift、BigQuery、Snowflake）→ Dashboard / Alert / AI。

## IaC / Terraform {#1-7-6-2}

- **一句話**：用程式碼宣告、建立、修改、管理基礎設施。AWS 是平台；Terraform 是基礎設施的**宣告與生命週期管理工具**（不只是「自動幫你點 Console」）。
- **宣告式**：像寫 `<MyButton />` 描述 UI 應該長什麼樣，Terraform 描述「最終狀態應該有這個 S3 Bucket」，再由 `terraform plan` 比對差異、`terraform apply` 套用。

```txt
resource "aws_s3_bucket" "assets" {
  bucket = "my-app-assets"
}
```

- **帶來的軟體工程特性**：版本控制 → Code Review → 可重現 → 自動化 → Dev / Staging / Prod 一致；環境壞了能重建，不用問「這台當初誰點出來的」。
- **面試 / 評估公司**：對方不知道 Terraform ≠ 不懂 Infra（可能用 CDK、CloudFormation、Pulumi）。與其問「用不用 Terraform」，不如問 **「你們 Infrastructure lifecycle 怎麼管理？」**，延伸：有沒有 IaC？VPC / IAM / SG 怎麼版本控制？環境怎麼同步？部署是 CI/CD 還人工？變更有沒有 review / rollback？——全靠 Console 手動 + 無版本控制，才是警訊。

## Observability 與 Security {#1-7-6-3}

- **觀測五件事**：Logs（發生什麼）、Metrics（狀態數字）、Traces（一個 request 經過哪些服務）、Alerts（異常通知）、Dashboard。工具：CloudWatch、Prometheus + Grafana、ELK / Loki、OpenTelemetry。
- **上線後要看**：是否掛掉、錯誤率、API 延遲、CPU / Memory、DB 連線數、業務轉換率。
- **安全必補**：IAM / RBAC 最小權限、Secrets 不寫死在程式碼、HTTPS/TLS、Firewall / Security Group / WAF、Image & Dependency Scan、SBOM、Supply Chain。
- 一句話：**DevOps 的安全重點不是懂駭客攻擊，而是部署流程不會把系統暴露出去。**
