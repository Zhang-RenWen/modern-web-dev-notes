## SPA 越用越慢：Memory Leak 排查 SOP {#1-6-12-1}

1. 先懷疑：Event Listener、Timer、WebSocket、Observer、Closure、Cache 沒釋放。
2. 驗證不靠猜：錄 Performance → Heap Snapshot → 操作後再拍一次 → 比較兩次 → 找 **Retainers**（真正的引用者）。
3. 對照生命週期：誰該活多久？React cleanup、Vue `onUnmounted` 有沒有收掉。
4. 架構層預防：快取用 LRU / TTL / WeakMap、分頁、Virtualization，而不是一直 push。

- 觀念：設成 null 不一定會回收，要「沒有任何引用」才會被 GC。

## 高難度通用元件（B 端核心） {#1-6-12-2}

- 最值得深挖：Date/Time Picker（range、disabled rules、鍵盤與無障礙、日期邊界）、Virtual List（DOM recycling、動態高度）、Drag & Drop（巢狀、跨容器、auto scroll）、Dynamic Form Engine（欄位相依、schema-driven）、Rich Text Editor（selection、IME、undo）、Advanced Uploader（progress、cancel、retry）。
- 策略：**成熟底層 Library + 自己的 Wrapper/API + Domain Component**，把第三方隔離在一層。

```txt
第三方 DatePicker → AppDatePicker → PolicyPeriodPicker → 業務頁面
```

- 真正的能力是判斷 Primitive / 通用 Component / Composite / Domain Component 的邊界切在哪。
- B 端技能樹：狀態、規則、精確性、可維護性；C 端技能樹：動畫、手感、裝置適配、感知效能。以金融系統背景，B 端複雜元件 → Design System → 前端架構是延續性最高的路線。

## 文件查不到時：讀套件原始碼的方法 {#1-6-12-3}

- 順序：**文件 → 型別定義 `.d.ts` → 原始碼入口**，只追到第一層處理就停，再用 DevTools/Playground 驗證。
- 先猜繼承關係：Vuetify `VAutocomplete` 文件沒列 `placeholder`，但它繼承 `VTextField` 的 props，所以可以用。
- 爆出全部 props：`console.log(Object.keys(VBtn.props))`。
- 樣式類設定多半是 CSS 變數：DevTools 看 `--v-*`，寫進 `theme.variables` 或全域 CSS。
- Vuetify 3 全域入口只有：theme / defaults / display / locale / icons / blueprint / aliases；局部覆寫用 `VDefaultsProvider`。v2 走 SASS 變數。
- 官方範例原始碼、GitHub Issues/PR 常比文件準。

## WASM 不一定比 JS 快（Mode7 飛空艇測試） {#1-6-12-4}

- 1800 個障礙物座標計算、Chrome 降速 20 倍：JS 7–10 FPS，WASM 只剩 4–5 FPS。
- **原因：資料在 JS 與 WASM 之間搬運的成本抵銷了運算優勢。**
- 規則：WASM 適合「大量運算、輸出資料量小」的任務；每幀都要把大量座標搬回 JS 渲染的場景反而吃虧。渲染交給 WebGL。

## 藍牙 IoT App：Flutter / RN / Native 怎麼選 {#1-6-12-5}

- 硬體整合深、要長期發展、人力夠 → Native（好 debug、分工清楚）。
- 短期要雙平台上架、人力有限 → Flutter 較省事（社群經驗是比 RN 坑少，仍可寫 native bridge）；Android 藍牙本身問題就多。
- 圖文展示型 → Hybrid 即可。
- 心態：先用當下最合適的方案做，之後人力夠再改寫 native。

## LINE Bot 用 Google Apps Script 的坑 {#1-6-12-6}

- GAS 對 POST 會先回 302 轉址，LINE Webhook 不跟隨 redirect → Verify 永遠失敗（但 Bot 其實能跑）。
- Web App 設成「所有人匿名可呼叫」時，`console.log` / Logger 全部失效，無法除錯。
- 結論：正式 Bot 不要放 GAS，改用 Cloudflare Worker / Cloud Functions 等。

## SSR（Hydration）的登入 {#1-6-12-7}

- 伺服器拿不到 localStorage → 用 **httpOnly cookie** 存 secret，在 Rendering Server 換回 token，再於渲染 HTML 前打後端 API。
- 多數網站沒有即時 SEO 需求，全 SSR 會大幅提高複雜度；優先考慮 **Prerender**。

## Vue Router 4 動態路由 + 動態 import {#1-6-12-8}

- 靜態 `import` 不能用變數；動態 `import()` 可以用變數與模板字串，回傳 Promise。
- **不要讓後端直接給檔案路徑**（bundler 編譯期無法分析會報錯）。後端只給 key，前端白名單對應：

```ts
const modules = import.meta.glob('@/views/*.vue')
const VIEW_MAP: Record<string, string> = {
  AdminDashboard: 'AdminDashboard.vue',
  AdminUsers: 'AdminUsers.vue',
}
export function resolveView(key: string) {
  const file = VIEW_MAP[key]
  const loader = file && modules[`/src/views/${file}`]
  if (!loader) throw new Error(`Unknown view: ${key}`)
  return loader
}
```

- Router 4：`router.addRoute(route)`、`router.addRoute('ParentName', child)`（第一參數是父路由 **name**）、`router.removeRoute(name)`、`router.hasRoute(name)`；同名會覆蓋。登入後註冊、登出移除。
- Router 3（Vue 2）只有 `addRoutes([...])`，且不能移除。
- 遠端元件才用完整 URL＋`/* @vite-ignore */`；記得用 `defineAsyncComponent` 加錯誤兜底。
- 不存在的路徑導回首頁：

```javascript
{ path: '/:pathMatch(.*)*', redirect: '/' } // 放在 routes 最後
```

## 雙層迴圈不是原罪 {#1-6-12-9}

- 資料量小、或結構本來就是巢狀（table → tr → td）就沒問題；資料量大才換 Map/Set、排序＋雙指標。
- DOM 操作優先用選擇器一次抓，避免外層迴圈：

```javascript
document.querySelectorAll('tr > :is(td, th):nth-child(-n+2)') // 每列前兩格
```

- 大量節點：迴圈內不要重複 `querySelector`，先快取；綁事件用 **event delegation**。

## 作品點子：Chrome Extension 追蹤粉絲增減 {#1-6-12-10}

- 架構：Content Script 讀 DOM → `chrome.storage.local` 存快照 → 與上次比對 → Popup 顯示新增/消失；GitHub Pages 只做官網、說明、匯入 JSON 畫圖（它是靜態站，不能當資料庫）。
- 比對用穩定的 user id，其次 username，不用顯示名稱；用 Map/Set 比對。
- 真正難點：無限捲動抓不完整、DOM 改版 selector 失效、區分「退追 / 改名 / 刪帳 / 抓取失敗」、遵守平台條款。
- **絕不把 GitHub token 寫進前端或 Extension**；要同步就用自己的後端或 OAuth。
- 上架 Chrome Web Store 是一次性 5 美元；本機開發者模式免費。
- 履歷寫法：寫安裝數、活躍用戶、評分、節省時間、技術（Manifest V3、Service Worker、最小權限、本機儲存）。
