# Chapter 5 運用 ECMAScript 集合

## 5-1 運用ES6 的映射

### 為什麼不用一般物件當雜湊表 {#5-1-0}

用 `{}` 存「鍵 → 值」的對應有幾個問題：

| 問題 | 說明 |
| --- | --- |
| 鍵會和原型上的屬性衝突 | 使用者輸入 `__proto__`、`toString` 當鍵就會出錯，甚至造成原型污染。可以用 `Object.create(null)` 建立沒有原型的物件來避免 |
| 鍵只能是字串或 Symbol | 數字會被轉成字串（`obj[1]` 和 `obj['1']` 是同一個），物件當鍵會變成 `'[object Object]'` |
| 走訪麻煩 | 要 `Object.keys`／`entries`，`for...in` 還會走到繼承的屬性 |
| 沒有現成的大小 | 要 `Object.keys(obj).length` |

`Map` 把這些都解決了。

### 5-1-1 Map 的用法 {#5-1-1}

```js
const map = new Map([['contra', { description: '非同步流程控制' }]]) // 可以用 [鍵, 值] 陣列初始化

map.set('dragula', { description: '拖放' }) // set 回傳 map 本身，可以串接
map.get('contra')    // { description: … }
map.has('dragula')   // true
map.delete('contra') // true
map.size             // 1
map.clear()          // 清空，但 map 這個參考不變
```

- **鍵可以是任何值**：物件、函式、DOM 元素、`NaN` 都可以，而且不會被轉型（`1` 和 `'1'` 是兩個不同的鍵）。
- 物件當鍵時比較的是**參考**：`map.get({})` 拿不到用另一個 `{}` 存的值。
- **保持插入順序**，可以直接走訪：

```js
for (const [key, value] of map) { … }
[...map.keys()]
[...map.values()]
Object.fromEntries(map) // 轉成物件（鍵要是字串）
new Map(Object.entries(obj)) // 物件轉 Map
```

- 分組（ES2024）：`Map.groupBy(orders, (o) => o.customerId)` 回傳以顧客為鍵的 `Map`。

### 5-1-2 用 DOM 元素當鍵 {#5-1-2}

替 DOM 元素記住額外資料，不必在元素上加屬性：

```js
const cache = new Map()
function getWidget(el) {
  if (!cache.has(el)) cache.set(el, createWidget(el))
  return cache.get(el)
}
```

問題是：元素從頁面移除後，`Map` 仍然持有它的參考，元素和資料都無法被回收，造成記憶體洩漏。這種「物件 → 附加資料」的情況應該改用 [`WeakMap`](./5-2.md)。

### Map 還是物件 {#5-1-3}

| 用 `Map` | 用一般物件 |
| --- | --- |
| 鍵是使用者輸入、動態產生、或不是字串 | 固定的欄位（像 `{ id, name, price }` 這種資料結構） |
| 會頻繁新增刪除 | 要 `JSON.stringify` 傳給 API（`Map` 序列化會變成 `{}`） |
| 需要知道數量、依插入順序走訪 | 需要解構、展開 |
