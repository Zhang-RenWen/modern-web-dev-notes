## 引擎族譜 {#1-5-7-1}

```txt
KHTML (KDE, 1998)
  └─ WebKit (Apple, 2001) ──────────────▶ Safari、iOS 上所有瀏覽器（多數地區）
        └─ Blink (Google, 2013 分叉) ───▶ Chrome、Edge、Opera、Brave、Vivaldi、Samsung Internet、Arc/Dia、Comet…
Netscape ─▶ Gecko (Mozilla) ────────────▶ Firefox、Tor Browser、LibreWolf…
Servo（Mozilla 實驗 → Linux Foundation）─▶ 嵌入式／研究用 Rust 引擎
Ladybird（2024 起，全新從零打造）────────▶ 2026 alpha 目標（見 2026 年新趨勢）
```

舊引擎 Trident（IE）、EdgeHTML、Presto，以及 Chakra 等舊 JS 引擎都已淘汰。

## 三大引擎陣營深度比較 {#1-5-7-3}

| 面向 | Chromium 系（Chrome／Edge 等） | Safari（WebKit） | Firefox（Gecko） |
| --- | --- | --- | --- |
| 主導者 | Google（開源，多家公司貢獻） | Apple | Mozilla（非營利基金會旗下） |
| JS 引擎 | V8 | JavaScriptCore | SpiderMonkey |
| 繪圖／合成 | Skia + cc，GPU 合成 | Core Animation／Core Graphics（Apple 平台） | WebRender（Rust、GPU 場景化） |
| 進程模型 | 最激進的站點隔離，進程最多 | 多進程，與系統深度整合 | Fission 站點隔離，進程數較節制 |
| 記憶體／電量 | 功能最強但最吃資源 | 在 Mac／iPhone 上省電表現最佳（軟硬整合） | 中間，近年優化幅度大 |
| 新 Web API 速度 | 最快，常是第一個實作（含實驗性 API） | 較保守，重視隱私與電量；近年追趕明顯 | 重標準共識，對有爭議的 API 常持反對立場 |
| 隱私預設 | 相對寬鬆，商業模式與廣告相關 | 嚴格（ITP、隱私報告） | 嚴格（ETP、Total Cookie Protection） |
| 擴充功能 | Manifest V3，最大的商店生態 | Safari Web Extensions（需透過 App 打包） | WebExtensions，仍保留較完整的 MV2 式阻擋能力（廣告封鎖器表現較好） |
| 平台 | 全平台 | 只有 Apple 平台 | 全平台 |
| 開發工具 | Chrome DevTools（業界標準） | Web Inspector | Firefox DevTools（CSS Grid／Flex 檢視器強） |
| 使用 Rust | 逐步導入於部分元件 | 少 | 最早大量使用（Stylo、WebRender 等） |

## 同樣是 Chromium，殼的差異 {#1-5-7-4}

| 瀏覽器 | 與 Chrome 的主要差異 |
| --- | --- |
| Microsoft Edge | 整合 Windows 與 Microsoft 365、Copilot 側欄、企業管理政策、效率模式／睡眠分頁 |
| Brave | 預設封鎖廣告與追蹤（Rust 寫的 Shields）、指紋防護、內建 Leo AI、移除 Google 帳號整合 |
| Opera／Opera GX | 內建 VPN、側欄聊天工具、遊戲向資源限制 |
| Vivaldi | 極度可客製化的 UI、內建郵件與行事曆 |
| Samsung Internet | 為 Android／Galaxy 裝置最佳化，自帶隱私功能 |
| Arc → Dia（The Browser Company） | 從介面創新轉向 AI 優先的瀏覽體驗 |
| Perplexity Comet | AI 原生瀏覽器，主打研究與代理操作；2026 年 3 月起全面免費 |

::: warning iOS 特例
長期以來 Apple 規定 iOS 上所有瀏覽器都必須使用 WebKit，所以 iPhone 上的「Chrome」其實是 WebKit 核心套 Chrome 的殼，相容性問題要以 Safari 為準。歐盟（DMA，iOS 17.4 起）與日本（2025 年 12 月起）已因法規要求開放替代引擎，但大廠真正推出非 WebKit 版本的進度有限。開發時請把「iOS = WebKit」當作預設前提。
:::

## 行動裝置除錯 {#1-5-7-5}

- **iOS Safari 遠端除錯**：Mac Safari → 設定 → 進階 → 勾「顯示網頁開發者功能」，iPhone 開啟「設定 → Safari → 進階 → 網頁檢閱器」，用線接上 Mac 即可檢查全部內容。
- **iOS Chrome**：網址列輸入 `chrome://inspect` 只能看 console；其餘用 Mac 上的 Safari 或 Chrome 模擬。
- **Android Chrome**：手機開 USB 偵錯，桌機 Chrome 開 `chrome://inspect`。

## User-Agent {#1-5-7-6}

範例：`Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/130.0.0.0 Safari/537.36`

- `Mozilla/5.0` 是歷史相容標記，幾乎所有瀏覽器都以此開頭；括號內是平台。
- `AppleWebKit/537.36` 是渲染引擎標記（Blink 仍保留這段）；最後的 `Safari/...` 是給無法辨識 Chrome 的伺服器用的備選。
- UA 容易偽造，而且瀏覽器正在凍結 UA 字串、改用 **User-Agent Client Hints**（`Sec-CH-UA` 等標頭）。功能判斷應該用特性偵測（`'serial' in navigator`、`CSS.supports()`），不要靠 UA。

## 名詞剖析 {#1-5-7-7}

| 名詞 | 意思 |
| --- | --- |
| 分叉（fork） | 從既有開源專案複製一份、往不同方向獨立發展 |
| Skia／cc | Chromium 的 2D 繪圖函式庫／合成器 |
| WebRender | Firefox 用 Rust 寫、以 GPU 為主的渲染器 |
| Fission | Firefox 的站點隔離實作專案 |
| Manifest V3 | 擴充功能設定檔第 3 版（見瀏覽器擴充功能開發） |
| DMA | 歐盟《數位市場法》，要求大型平台開放競爭 |
| 指紋防護 | 阻止網站靠字型、螢幕、GPU 等特徵組合辨識使用者 |
