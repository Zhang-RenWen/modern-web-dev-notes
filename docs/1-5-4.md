## 執行流程：從原始碼到機器碼 {#1-5-4-1}

```txt
Source ─▶ Parser ─▶ AST ─▶ Bytecode ─▶ Interpreter（立刻能跑）
                                    │
                         收集型別回饋（Profiling）
                                    ▼
                 Baseline JIT ─▶ 中階最佳化 JIT ─▶ 頂級最佳化 JIT
                       ▲                                   │
                       └───────── Deoptimize（假設失效時退回）◀┘
```

**分層編譯（Tiered Compilation）**的核心思想：大部分程式碼只跑幾次，不值得花時間最佳化；只有「熱」的函式才逐級往上編譯。最佳化 JIT 會根據觀察到的型別做**投機性假設**（例如「這個參數一直是整數」），假設被打破就 **Deopt** 退回直譯器。

| 引擎 | 所屬 | 直譯器 | Baseline | 中階 | 頂級最佳化 |
| --- | --- | --- | --- | --- | --- |
| V8 | Chrome／Edge／所有 Chromium 系／Node.js | Ignition | Sparkplug | Maglev | TurboFan（逐步演進中） |
| JavaScriptCore | Safari／iOS 上的瀏覽器／Bun | LLInt | Baseline JIT | DFG | FTL |
| SpiderMonkey | Firefox | Baseline Interpreter | Baseline Compiler | — | WarpMonkey（Ion 後端） |

## 讓 JS 變快的關鍵技術 {#1-5-4-2}

- **Hidden Class／Shape**：JS 物件本來是雜湊表，引擎會把「屬性相同、加入順序相同」的物件歸成同一個隱藏類別，讓屬性存取變成固定位移讀取，跟 C struct 一樣快。實務上：**建構時一次把屬性加齊、順序一致**，不要事後 `delete` 屬性。
- **Inline Cache（IC）**：在呼叫點記住「上次看到的 Shape 與結果位置」。同一呼叫點只見過一種 Shape 叫 monomorphic（最快），見過太多種叫 megamorphic（變慢）。
- **陣列元素種類（Elements Kinds）**：全整數陣列最快，混入浮點數、`undefined`、洞（hole）會降級。
- **垃圾回收（GC）**：分代式。新生代用 Scavenge 快速清理短命物件，老生代用 Mark-Sweep／Compact；並搭配增量、並行、並發標記，盡量不讓主執行緒停頓。V8 的 GC 叫 Orinoco，同時負責 DOM 物件與 JS 物件之間的跨堆回收。

## Event Loop：單執行緒為什麼不會卡死 {#1-5-4-3}

頁面主執行緒同時負責 **JS 執行 + 樣式 + 排版 + 繪製**，所以它是一個排程迴圈：

```txt
loop {
  取出一個 Task（macrotask：script、setTimeout、事件回呼、postMessage、I/O）並執行
  清空所有 Microtask（Promise.then、queueMicrotask、MutationObserver）
  如果該更新畫面了（約每 16.7ms）：
      執行 requestAnimationFrame 回呼
      Style → Layout → Paint → 交給 Compositor（見渲染管線）
  有空閒時間：requestIdleCallback
}
```

- Microtask 會在**每個 Task 結束後一次清空**，所以無限遞迴的 Promise 鏈會餓死渲染。
- 想把長任務切碎讓出主執行緒：`scheduler.yield()`、`setTimeout(0)`，或丟給 **Web Worker**（獨立執行緒，不能碰 DOM）。

## WebAssembly {#1-5-4-4}

- 一種**二進位、強型別、沙箱化**的指令格式，跟 JS 共用同一個引擎與安全模型，但跳過 JS 的動態型別推測，啟動與執行更可預期。
- 近年重點：Wasm GC（讓 Kotlin、Dart、Java 等有 GC 的語言能直接編譯過來）、例外處理、SIMD、多執行緒。適合影像處理、遊戲、壓縮、密碼學、在瀏覽器裡跑資料庫或 ML 推論。

## 名詞剖析 {#1-5-4-5}

| 名詞 | 意思 |
| --- | --- |
| AST | 抽象語法樹：原始碼解析後的樹狀結構 |
| Bytecode／Interpreter | 引擎內部的中間指令／逐條執行它的直譯器 |
| JIT | 執行期把常跑的程式碼編譯成機器碼 |
| Profiling／型別回饋 | 執行時記錄函式實際收到哪些型別，給最佳化器用 |
| Deopt | 最佳化假設被打破，丟掉最佳化版本、退回直譯器 |
| Hidden Class／Shape | 引擎給「結構相同」的物件分配的內部類別 |
| Inline Cache | 呼叫點的小快取，記住上次的 Shape 與屬性位置 |
| monomorphic／megamorphic | 呼叫點只見過一種／見過很多種 Shape |
| Scavenge／Mark-Sweep／Compact | 新生代複製回收／標記清除／整理碎片 |
| Macrotask／Microtask | 一般任務（setTimeout、事件）／每個任務結束後立刻清空的小任務（Promise） |
| `scheduler.yield()` | 主動讓出主執行緒、之後優先接續執行的 API |
| Web Worker | 在背景執行緒跑 JS，不能碰 DOM |
| WebAssembly／Wasm GC | 瀏覽器可執行的二進位格式／讓 Wasm 使用引擎內建 GC |
| SIMD | 一道指令同時處理多筆資料 |
