# 9-5 探究各類函式宣告方法

::: info 改寫（2026-11）
整理自《Practical Modern JavaScript》（2017），已精簡成比較表與選擇原則。
:::

| 寫法 | 提升 | `this` | 適合 |
| --- | --- | --- | --- |
| 函式宣告 `function sum() {}` | 整個提升，宣告前就能呼叫 | 依呼叫方式 | 模組頂層的主要函式，可以把細節函式放在檔案後面 |
| 函式運算式 `const sum = function () {}` | 變數依 `const` 規則（TDZ），宣告前不能用 | 依呼叫方式 | 需要條件式建立函式時 |
| 具名函式運算式 `const f = function sum() {}` | 同上 | 依呼叫方式 | 需要在函式內部遞迴呼叫自己；名稱也會出現在錯誤堆疊裡 |
| 箭頭函式 `const sum = () => {}` | 同上 | 外層的 `this` | callback、短小的轉換函式 |
| 方法簡寫 `{ sum() {} }` | — | 依呼叫方式 | 物件與 class 的方法 |

```js
// 具名函式運算式：sum 這個名稱只在函式內部有效
const sumMany = function sum(total = 0, ...values) {
  return values.length ? sum(total + values[0], ...values.slice(1)) : total
}
```

**箭頭函式的隱式回傳**：

```js
const makeArray = (a, b) => [a, b]
const makeObject = (id) => ({ id })   // 物件要包括號，否則 {} 被當成函式本體
const ignored = (id) => { id }        // 陷阱：這是函式本體加一個標籤 id，回傳 undefined
```

選擇原則：

- callback 預設用箭頭函式，不必擔心 `this`。
- 需要動態 `this` 的地方（物件方法、DOM 事件處理函式要用 `this` 拿元素、`function` 寫的建構函式）不要用箭頭函式。
- 一個檔案裡主要的函式用宣告或 `const` + 箭頭都可以，**團隊統一**比哪種寫法更重要。
- 箭頭函式主體超過幾行、裡面有多個步驟時，加上大括號和明確的 `return`，比較好讀也好除錯。

箭頭函式的語法細節見 [2-2](./2-2.md)。
