# 1-25-2 讀懂 TypeScript 程式碼 {#1-25-2}

::: info 新增（2026-11）
看別人的 TS 程式碼或套件型別定義時，遇到看不懂的符號來這裡查。
:::

## 符號速查表 {#1-25-2-1}

| 寫法 | 意思 |
| --- | --- |
| `x: string` | 型別註記 |
| `name?: string` | 可選屬性（可能是 `undefined`） |
| `readonly id: number` | 唯讀屬性 |
| `A \| B` / `A & B` | 聯集 / 交集 |
| `Array<T>` / `T[]` | 陣列，兩種寫法相同 |
| `[string, number]` | Tuple：固定長度與各位置的型別 |
| `Record<K, V>` | key 為 K、value 為 V 的物件 |
| `(a: number) => string` | 函式型別 |
| `keyof T` | T 所有 key 組成的聯集 |
| `typeof x`（在型別位置） | 取變數 x 的型別 |
| `T[K]` | 索引存取：T 的 K 屬性的型別 |
| `T extends U ? X : Y` | 條件型別 |
| `infer R` | 在條件型別中抓出某個位置的型別 |
| `{ [K in keyof T]: ... }` | Mapped type：逐一走過 T 的 key |
| `` `/api/${string}` `` | Template literal type |
| `value!` | 非空斷言：告訴 TS「這裡一定不是 null」（不檢查，出錯就是執行期錯誤） |
| `value as Type` | 型別斷言：強制當成某型別 |
| `obj satisfies Type` | 檢查符合型別，但保留更精確的推論 |
| `as const` | 讓值變成唯讀的字面量型別 |
| `import type { X }` | 只匯入型別，編譯後會被移除 |
| `declare` | 宣告某個東西存在（通常在 `.d.ts`），不產生程式碼 |
| `@Something()` | Decorator（Angular、NestJS 大量使用） |

## 一步一步拆解複雜的型別 {#1-25-2-2}

遇到長長的型別，**由外往內、一層一層代入具體型別**：

```ts
type Getters<T> = {
  [K in keyof T as `get${Capitalize<string & K>}`]: () => T[K]
}
```

1. `[K in keyof T ...]`：對 T 的每個 key 做事（mapped type）。
2. `` as `get${Capitalize<...>}` ``：把 key 改名，`name` 變成 `getName`。`string & K` 是確保 K 是字串（key 也可能是 number 或 symbol）。
3. `: () => T[K]`：值是一個回傳原屬性型別的函式。
4. 代入實例驗證：

```ts
type User = { name: string; age: number }
type UserGetters = Getters<User>
// { getName: () => string; getAge: () => number }
```

技巧：在編輯器中把滑鼠移到型別名稱上看展開結果；或寫一行 `type Test = Getters<User>` 觀察。

## 函式多載 {#1-25-2-3}

同一個函式依參數不同回傳不同型別：

```ts
function parse(input: string): number
function parse(input: string[]): number[]
function parse(input: string | string[]) {      // 實作簽章，外部看不到
  return Array.isArray(input) ? input.map(Number) : Number(input)
}

parse('1')          // number
parse(['1', '2'])   // number[]
```

前面幾行是對外的簽章，最後一個帶實作的是內部簽章。讀套件型別時常看到一長串多載，由上往下比對，第一個符合的就是會用到的那個。

## 型別定義檔 .d.ts {#1-25-2-4}

- `.d.ts` 只有型別、沒有實作，描述「某個 JS 程式長什麼樣子」。
- 套件自帶型別（`package.json` 的 `types` 欄位），或由社群在 `@types/套件名` 提供。
- 文件查不到時，直接打開 `.d.ts` 看最準：用編輯器的「Go to Type Definition」跳過去（見 [1-6-12 讀套件原始碼的方法](./1-6-12.md#1-6-12-3)）。

```ts
// 擴充全域或第三方型別（declaration merging）
declare global {
  interface Window { __APP_VERSION__: string }
}

declare module 'vue-router' {
  interface RouteMeta { perm?: string; title?: string }   // 讓 route.meta.perm 有型別
}
```

## Decorator {#1-25-2-5}

Decorator 是「包裝 class、方法、屬性」的函式，用 `@` 標在宣告上。Angular、NestJS、TypeORM 大量使用，寫法和 Java 的 annotation 很像，但本質不同：Decorator 是執行期會跑的函式，Java annotation 是附加的 metadata，要靠框架用反射讀取。

```ts
@Controller('users')                 // NestJS：這個 class 處理 /users 路由
export class UsersController {
  constructor(private readonly users: UsersService) {}   // 依賴注入

  @Get(':id')                        // GET /users/:id
  findOne(@Param('id') id: string) {
    return this.users.findOne(id)
  }
}
```

注意：TypeScript 5.0 起支援 ECMAScript 標準的 Decorator；Angular、NestJS 等仍多使用舊版的 `experimentalDecorators`，兩者行為不同，看 `tsconfig.json` 就知道專案用哪一種。

## 讀一個陌生 TS 專案的順序 {#1-25-2-6}

1. `package.json`：框架、套件、scripts。
2. `tsconfig.json`：是否 `strict`、路徑別名（`paths`）、Decorator 設定。
3. 型別定義集中的地方（`types/`、`models/`、`entities/`、API client 產生的型別）：先懂資料長什麼樣子。
4. 入口（`main.ts`、路由設定）→ 一條主要流程追到底。
5. 看不懂的型別用滑鼠移上去看推論結果，或「Go to Definition」追。
