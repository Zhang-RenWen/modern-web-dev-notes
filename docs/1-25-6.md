## 語法對照 {#1-25-6-1}

| 概念 | TypeScript | Java |
| --- | --- | --- |
| 變數 | `let x = 1` / `const x = 1` | `var x = 1;` / `final var x = 1;`（或寫明型別 `int x = 1;`） |
| 型別位置 | `name: string` | `String name` |
| 函式 | `function add(a: number, b: number): number` | `int add(int a, int b)`（一定寫在 class 裡） |
| 箭頭函式 | `(x) => x * 2` | Lambda：`x -> x * 2` |
| 陣列／列表 | `number[]`、`.map()`、`.filter()` | `List<Integer>`、`.stream().map().filter().toList()` |
| 物件／字典 | `Record<string, User>`、`Map` | `Map<String, User>` |
| 可能沒有值 | `User \| undefined`、`?.`、`??` | `null` 或 `Optional<User>`，`.orElse(...)` |
| 字串樣板 | `` `Hi ${name}` `` | `"Hi " + name`、`String.format("Hi %s", name)`、Text Block |
| 相等 | `===` | 基本型別用 `==`；**物件內容比較用 `.equals()`**（`==` 比的是是否同一個物件） |
| 列舉 | 字面量聯集或 `enum` | `enum`（可以有欄位和方法） |
| 純資料物件 | `type` / `interface` | `record`（Java 16+）、或 class + Lombok `@Data` |
| 非同步 | `async` / `await`、Promise | 多半是同步程式（一個請求一條執行緒）；`CompletableFuture`、虛擬執行緒（Java 21） |
| 模組 | `import { x } from './x'` | `package com.example.order;` + `import com.example.user.User;` |
| Decorator | `@Injectable()` | Annotation：`@Service`、`@Autowired` |

## 最關鍵的差異：名義型別 {#1-25-6-2}

TS 只看結構（形狀相同就相容），Java 看**名字與宣告**：

```java
interface Point { int x(); int y(); }

record Pixel(int x, int y) {}             // 雖然有 x()、y()，但沒有宣告 implements Point
Point p = new Pixel(1, 2);                // ❌ 編譯錯誤

record Pixel2(int x, int y) implements Point {}
Point p2 = new Pixel2(1, 2);              // ✅
```

所以 Java 專案裡會看到大量的 `implements`、明確的型別轉換，以及一層層的 interface：它們是讓編譯器確認關係的方式。

## 型別系統的其他差異 {#1-25-6-3}

- **基本型別與包裝型別**：`int` 不能是 `null`，`Integer` 可以；集合裡只能放包裝型別（`List<Integer>`）。從資料庫或 JSON 讀進可能為空的值要用 `Integer`，否則會 NullPointerException。
- **沒有聯集型別**：TS 的 `'a' | 'b'` 在 Java 用 `enum`；不同結構的狀態用 `sealed interface` + `record`（Java 17+），搭配 `switch` 模式比對（Java 21）達到類似 TS 可辨識聯合的效果：

```java
sealed interface PaymentResult permits Success, Failed {}
record Success(String txId) implements PaymentResult {}
record Failed(String reason) implements PaymentResult {}

String render(PaymentResult r) {
  return switch (r) {
    case Success s -> "成功 " + s.txId();
    case Failed f -> "失敗：" + f.reason();
  };   // 少處理一種情況會編譯錯誤，等同 TS 的 never 窮舉檢查
}
```

- **泛型**：寫法相似（`List<User>`、`<T extends Comparable<T>>`），也有型別擦除；Java 多了萬用字元 `List<? extends Animal>`（可以讀出 Animal）與 `List<? super Dog>`（可以放入 Dog）。
- **例外**：Java 有 **checked exception**，方法簽章上的 `throws IOException` 代表呼叫端一定要處理；TS 沒有這個機制。
- **數字與金額**：`int / int` 是整數除法；金額用 `BigDecimal`，不用 `double`（見 [模擬面試 3 Q12](./interview-3.md#interview-3-12)）。

## 同一段程式的兩種寫法 {#1-25-6-4}

```ts
// TypeScript
interface UserRepository {
  findById(id: string): Promise<User | undefined>
}

class UserService {
  constructor(private readonly repo: UserRepository) {}

  async getActiveUserName(id: string): Promise<string> {
    const user = await this.repo.findById(id)
    if (!user || !user.active) throw new NotFoundError(`user ${id}`)
    return user.name
  }
}
```

```java
// Java（Spring Boot）
public interface UserRepository extends JpaRepository<User, String> {
  // findById 由 Spring Data 自動實作，回傳 Optional<User>
}

@Service
public class UserService {
  private final UserRepository repo;

  public UserService(UserRepository repo) {   // 建構子注入，Spring 自動傳入
    this.repo = repo;
  }

  public String getActiveUserName(String id) {
    return repo.findById(id)
        .filter(User::isActive)                // 方法參考：等同 u -> u.isActive()
        .map(User::getName)
        .orElseThrow(() -> new NotFoundException("user " + id));
  }
}
```

對照重點：`Optional` 的 `filter`／`map`／`orElseThrow` 就是 TS 裡的 `if (!user)` 判斷；建構子注入就是 TS 的建構子參數屬性；Java 的方法多半是同步的，不需要 `await`。

## Stream：Java 的陣列方法 {#1-25-6-5}

```ts
const names = users
  .filter((u) => u.age >= 18)
  .map((u) => u.name)
  .sort()
```

```java
List<String> names = users.stream()
    .filter(u -> u.getAge() >= 18)
    .map(User::getName)
    .sorted()
    .toList();                                       // Java 16+；舊專案是 .collect(Collectors.toList())

Map<String, List<User>> byDept = users.stream()
    .collect(Collectors.groupingBy(User::getDept));  // 類似 Object.groupBy（見 18-1）
```

## Spring Boot 專案怎麼看 {#1-25-6-6}

```txt
src/main/java/com/example/order/
  controller/   OrderController.java   @RestController、@GetMapping("/orders/{id}")
  service/      OrderService.java      @Service、@Transactional
  repository/   OrderRepository.java   extends JpaRepository<Order, Long>
  entity/       Order.java             @Entity、@Table、@Id、@Column
  dto/          OrderResponse.java     API 回傳的資料形狀（常用 record）
  config/       SecurityConfig.java    @Configuration、@Bean
src/main/resources/
  application.yml                      資料庫連線、環境設定
  db/migration/V1__init.sql            Flyway 資料庫遷移
```

**常見 Annotation**

| Annotation | 意思 | TS／前端的類比 |
| --- | --- | --- |
| `@RestController` | 這個類別處理 HTTP 請求，回傳 JSON | NestJS `@Controller` |
| `@GetMapping("/{id}")`、`@PostMapping` | 路由與 HTTP 方法 | Express `app.get('/:id')` |
| `@PathVariable`、`@RequestParam`、`@RequestBody` | 從路徑、query、body 取值 | `req.params`、`req.query`、`req.body` |
| `@Valid` + `@NotNull`、`@Size` | 驗證請求內容 | Zod schema |
| `@Service`、`@Repository`、`@Component` | 交給 Spring 管理的元件，可被注入 | Angular／NestJS `@Injectable()` |
| `@Autowired` | 注入依賴（新程式偏好建構子注入，可以省略這個 annotation） | 建構子參數 |
| `@Transactional` | 方法內的資料庫操作在同一個交易中，丟例外就回滾 | — |
| `@Entity`、`@Id`、`@Column` | 對應資料表 | TypeORM、Prisma model |
| `@Data`、`@Builder`、`@RequiredArgsConstructor` | Lombok：自動產生 getter／setter、建構子、builder | — |

**追一個 API 的方法**：
1. 從前端打的網址搜尋 `@GetMapping("/orders` 找到 Controller。
2. 看它呼叫哪個 Service 方法，Service 裡是業務規則與 `@Transactional` 邊界。
3. Service 呼叫 Repository；方法名稱如 `findByUserIdAndStatus` 會被 Spring Data 自動轉成 SQL，複雜的查詢寫在 `@Query` 或 MyBatis XML（見 [1-6-13 MyBatis 動態查詢](./1-6-13.md#1-6-13-5)）。
4. 回傳的 DTO 就是前端拿到的 JSON 形狀；欄位名稱轉換看 `@JsonProperty` 或全域的命名策略。

**前端工程師跨端除錯時最常遇到的問題**
- 前端收到 500：看後端 log 的 stack trace，找第一行屬於專案 package 的位置。
- `NullPointerException`：某個物件是 null 卻被呼叫方法，常見於沒處理的 `Optional` 或包裝型別。
- `LazyInitializationException`：交易結束後才讀取延遲載入的關聯資料。
- 欄位名稱對不上（`user_name` vs `userName`）：JSON 序列化的命名策略設定。
- 時間差 8 小時：時區設定（伺服器 UTC、資料庫、JSON 格式不一致）。
