# 1-3-11 函數式程式設計 {#1-3-11}

::: info 改寫（2026-11）
原內容整理自 2019 年前的書籍，已精簡並更新：裝飾器改用 2022 年定案的新語法（舊版 `(target, name, descriptor)` 只剩 TypeScript 的 `experimentalDecorators`）；相容 IE9 的範例刪除；補上 ES2023 不改原陣列的方法；Functor／Maybe 濃縮成概念與現代對應。
:::

> 一句話：**把程式拆成「輸入決定輸出」的小函式，再組合起來**；狀態改變和副作用集中在少數地方。

## 純函式與不可變 {#1-3-11-1}

純函式：相同輸入一定得到相同輸出，而且不改外部的東西（不改參數、不改全域變數、不發請求、不讀 `Date.now()`／`Math.random()`）。

```js
// 不純：改了外部的陣列
const removeLast = () => { items.pop() }
// 純：回傳新陣列
const withoutLast = (arr) => arr.slice(0, -1)
```

好處：好測試（不用 mock）、可以安全快取結果、React／Vue 靠「新物件 ≠ 舊物件」判斷要不要更新畫面。

ES2023 起陣列有不改原陣列的版本，不用再先複製：

| 會改原陣列 | 回傳新陣列（ES2023） |
| --- | --- |
| `sort()` | `toSorted()` |
| `reverse()` | `toReversed()` |
| `splice()` | `toSpliced()` |
| `arr[i] = x` | `arr.with(i, x)` |

## 高階函式 {#1-3-11-2}

接收函式或回傳函式的函式。`filter`、`map`、`reduce` 把「怎麼走訪」抽掉，只留下「要做什麼」：

```js
// 命令式：迴圈和判斷混在一起，每種條件都要再寫一次迴圈
const result = []
for (const n of list) if (typeof n === 'number' && n < 10) result.push(n)

// 函式式：條件獨立成小函式，可以重複組合
const isNumber = (x) => typeof x === 'number'
const lessThan = (max) => (x) => x < max
list.filter(isNumber).filter(lessThan(10))
```

**記憶化（memoize）**：用閉包快取結果，只適用純函式。

```js
const memoize = (fn) => {
  const cache = new Map()
  return (...args) => {
    const key = JSON.stringify(args)
    if (!cache.has(key)) cache.set(key, fn(...args))
    return cache.get(key)
  }
}
```

**裝飾器**也是高階函式的應用。標準裝飾器（2022 定案，TypeScript 5.0 起支援）接收方法本身，回傳替代的方法：

```js
const callLimit = (max) => (method, context) => {
  let count = 0
  return function (...args) {
    if (++count > max) return console.warn(`${String(context.name)} 超過呼叫上限`)
    return method.apply(this, args)
  }
}
class Api {
  @callLimit(3) getSum() { /* … */ }
}
```

## 組合與 point-free {#1-3-11-3}

把單一功能的小函式串成大功能（`compose`／`pipe` 的實作見 [1-3-5](./1-3-5.md#1-3-5-3)）：

```js
const slugify = pipe(trim, toLowerCase, replaceSpaces)
```

**point-free** 是「定義函式時不提到參數」的風格，例如 `const slugify = pipe(…)` 而不是 `(s) => replaceSpaces(toLowerCase(trim(s)))`。適度使用能讓意圖更清楚；為了 point-free 硬拆反而更難讀，就不值得。

## 柯里化與偏函式 {#1-3-11-4}

- **柯里化（curry）**：`f(a, b, c)` → `f(a)(b)(c)`，每次只收一個參數，直到收滿才執行。
- **偏函式（partial）**：先固定部分參數，回傳收剩下參數的函式，例如 `fn.bind(null, a)`。

用途：預先填好設定，產生專用函式，例如 `const logError = log('error')`、`const lessThan10 = lessThan(10)`。

```js
const curry = (fn) =>
  function curried(...args) {
    return args.length >= fn.length
      ? fn.apply(this, args)
      : (...more) => curried.apply(this, [...args, ...more])
  }

const add3 = curry((a, b, c) => a + b + c)
add3(1)(2)(3)  // 6
add3(1, 2)(3)  // 6
```

注意 `fn.length` 不計算有預設值的參數和其餘參數，這類函式要自己傳入參數個數。

**面試題：`add(1)(2)(3) == 6`**，而且可以無限串：每次都回傳函式，靠改寫 `valueOf` 讓 `==` 比較時轉成數字。

```js
function add(...args) {
  const fn = (...more) => add(...args, ...more)
  fn.valueOf = () => args.reduce((a, b) => a + b, 0)
  return fn
}
add(1)(2)(3) == 6   // true
add(1, 2)(3)(4) == 10 // true
add(1)(2)(3) === 6  // false：它其實還是函式，只是比較時被轉型
```

**反柯里化（uncurry）**：把「某個物件的方法」變成「第一個參數是物件的普通函式」，讓其他物件也能借用：

```js
const uncurry = (fn) => (obj, ...args) => fn.apply(obj, args)
const toString = uncurry(Object.prototype.toString)
toString([]) // '[object Array]'
const push = uncurry(Array.prototype.push)
push(arrayLike, 'x') // 類陣列物件借用陣列方法
```

## Functor 與 Maybe：概念就好 {#1-3-11-5}

**Functor** 是「包著一個值、提供 `map` 的容器」：`map` 對裡面的值套函式，回傳同類型的新容器，所以能一直串下去。`Array` 就是最常見的 Functor，`Promise` 的 `then` 也是類似的概念。

**Maybe** 是遇到 `null`／`undefined` 就停止後續運算的容器，用來避免一路檢查空值：

```js
const Maybe = (value) => ({
  map: (fn) => (value == null ? Maybe(null) : Maybe(fn(value))),
  getOrElse: (fallback) => value ?? fallback,
})
Maybe(user).map((u) => u.address).map((a) => a.city).getOrElse('未填寫')
```

在 JavaScript 裡，這個需求現在多半直接寫 `user?.address?.city ?? '未填寫'`。需要完整的函式式工具（`pipe`、`Option`、`Either` 型別）時，可以看 Ramda 或 Effect 這類函式庫。
