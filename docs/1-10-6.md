> 資料結構不是背名詞，而是理解資料怎麼存、怎麼查、怎麼改、成本多少，以及在真實系統中該選哪一種來控制複雜度。

## 資料結構與系統設計用途 {#1-10-6-1}

| 結構 | 操作成本 | 系統設計用途 |
| --- | --- | --- |
| Array（連續記憶體＋index） | 存取 O(1)、搜尋 O(n)、中間插刪 O(n) | 列表、批次處理、分頁、排序 |
| HashMap／Set | 平均 O(1)；collision 嚴重時最壞 O(n) | Cache、Session、Dedup、計數、Rate limit、JWT denylist |
| Stack（LIFO） | push／pop O(1) | 函式呼叫堆疊、undo、DFS、括號匹配、parser |
| Queue（FIFO） | enqueue／dequeue O(1) | BFS、Message Queue、Event Loop、**削峰＋解耦＋非同步＋重試** |
| Linked List | 存取 O(n)；已知節點時插刪 O(1) | LRU Cache、底層結構 |
| Tree／BST | 平衡時 O(log n)；不平衡會退化成 O(n) | 目錄、權限樹、組織架構、DOM、AST |
| B／B+ Tree | O(log n)，適合磁碟讀取 | 資料庫 index |
| Heap | 取極值 O(1)；插入／彈出 O(log n) | Priority Queue、排程器、Top K、排行榜、Dijkstra |
| Trie | O(字串長度) | Autocomplete、prefix 搜尋、敏感詞、路由匹配 |
| Graph | 看表示法：adjacency list／matrix | 社群、推薦、路徑、服務依賴、資金流、供應鏈、信用鏈 |
| Union Find | 近乎 O(1)（α(n)） | 帳號合併、群組連通、Kruskal 最小生成樹 |

- **Hashing 正確流程**：key → hash function → hash value → bucket → value。只 hash key，value 跟著存。不同 key 可能撞到同一格（collision），要補 chaining、open addressing、load factor、rehash。
- 2D／3D Array＝row／column（／z），用在影像、遊戲地圖、DP 表格、線代與 tensor。
- **每個結構都用這 7 問整理**：是什麼？解決什麼問題？查／插／刪成本？實作上怎麼存？適合什麼？不適合什麼？在系統設計裡對應什麼？
- 優先序（後端／架構路線）：HashMap、Array、Queue、Tree、Big-O → Graph、Heap、Trie → Stack、Linked List、BST、Union Find。

## Big-O {#1-10-6-2}

- **Big-O＝資料量變大時成本的成長趨勢，不是實際執行秒數。**

```txt
O(1)        Array index、HashMap 平均查找
O(log n)    Binary Search、平衡樹、Heap 操作
O(n)        掃一遍：filter、map、find
O(n log n)  Merge／Heap Sort、Quick Sort 平均
O(n²)       雙層迴圈兩兩比對、暴力 join
O(2ⁿ)       子集合枚舉、暴力遞迴
O(n!)       全排列暴力搜尋
```

- 修正常見誤解：Binary Search 前提是資料已排序；Divide and Conquer 不一定是 O(log n)；巢狀迴圈是 O(n²)、O(n³)，不是 O(n!)；埃氏篩是 O(n log log n)，判斷單一數字是否為質數才是 O(√n)。
- **工程最常爆的地方**：O(n²) 資料處理、N+1 Query、沒有 index 的全表掃描、暴力比對權限／tag／關係。

## 排序與搜尋 {#1-10-6-3}

| 排序 | 複雜度 | 什麼時候用 |
| --- | --- | --- |
| Insertion | 最佳 O(n)、平均／最壞 O(n²) | 小陣列、幾乎排好；混合排序在小資料時切回它 |
| Merge | 一律 O(n log n)、額外空間 O(n)、stable | Linked List、外部排序、需要穩定排序 |
| Quick | 平均 O(n log n)、最壞 O(n²) | 實務核心；randomized pivot、median-of-three、introsort 防退化，cache locality 好 |
| Heap | 一律 O(n log n)、空間 O(1)、不 stable | 理論重要、省空間 |
| Shell | 取決於 gap 序列，不能死背 | gap-based insertion sort，知道概念 |
| Bubble／Selection | O(n²) | 教學用，實務幾乎不用 |

- **搜尋**：Linear O(n) 不用排序；Binary O(log n) 要先排序；BFS／DFS 精準說是樹與圖的遍歷演算法，不是陣列搜尋。修正：Quick／Merge Sort 可用遞迴樹分析，但不是「二元樹遍歷」。

## 演算法設計思路 {#1-10-6-4}

- **Recursion**：要有 base case（停止）＋recursive case（拆小）。
- **Divide and Conquer**：拆成子問題 → 分別解 → 合併（Merge Sort、Quick Sort、Binary Search）。
- **DP**：儲存中間結果避免重複計算，適用「重疊子問題＋最優子結構」。不只是 recursion＋memoization（top-down），也有 iteration＋tabulation（bottom-up）。重點是**狀態設計與轉移方程**。
- **Boids 群體模擬**：Separation（別太近）、Alignment（方向跟鄰居一致）、Cohesion（往群中心靠）三條規則 → 鳥群、魚群、粒子、生成式藝術。適合用 Canvas／WebGL 做作品集差異化。
