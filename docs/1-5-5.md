::: info 新增（2026-11）
整理自 Notion「2026 全新瀏覽器原理」05。同源政策與 CORS 的細節見下一頁。

## 安全模型 {#1-5-5-1}

| 機制 | 解決什麼問題 | 一句話理解 |
| --- | --- | --- |
| 同源政策（Same-Origin Policy） | 不同網站互讀資料 | 協定 + 網域 + 埠號都相同才算同一個「源」 |
| CORS | 需要合法跨源存取時 | 由**伺服器**透過回應標頭授權哪些來源可讀 |
| CSP | XSS 注入腳本 | 白名單規定頁面能從哪裡載入、執行什麼 |
| 沙箱 + Site Isolation | 引擎漏洞、Spectre 旁路 | 就算渲染進程被攻破，也拿不到別站資料和系統（見瀏覽器架構） |
| COOP／COEP（跨源隔離） | 高精度計時器帶來的旁路風險 | 頁面宣告自我隔離後，才能用 `SharedArrayBuffer` |
| HTTPS／HSTS／憑證透明度 | 中間人竊聽與竄改 | 強制加密，而且憑證的發行可被稽核 |
| 權限模型 | 相機、定位、通知濫用 | 需使用者授權，且限定 Secure Context |

**隱私與 Cookie**：Safari（ITP）與 Firefox（Enhanced Tracking Protection；Total Cookie Protection 把 Cookie 依頂層網站分區）早已預設封鎖第三方追蹤 Cookie；Chrome 在第三方 Cookie 上的路線反覆調整，最終並未全面預設淘汰，這是三家在隱私哲學上最明顯的分歧。Chromium 也導入了 CHIPS（分區 Cookie）作為折衷。

::: warning 金融業實務
正確設定 CSP、`HttpOnly`／`Secure`／`SameSite` Cookie、CORS 白名單、HSTS；理解「瀏覽器只負責執行政策，政策由伺服器宣告」。
:::

## 儲存與離線能力 {#1-5-5-2}

| 儲存 | 特性 | 適合 |
| --- | --- | --- |
| Cookie | 小、每次請求自動帶上 | session、登入狀態（配 HttpOnly） |
| localStorage／sessionStorage | 同步 API、容量小，會阻塞主執行緒 | 少量偏好設定；不適合大量資料與機密 |
| IndexedDB | 非同步的交易式物件資料庫 | 大量結構化資料 |
| Cache Storage + Service Worker | Service Worker 是介於頁面與網路之間的可程式化代理，可攔截請求 | 離線、推播、背景同步，PWA 的基礎 |
| OPFS（Origin Private File System） | 高效能檔案存取 | 搭配 Wasm 在瀏覽器內跑 SQLite |

各家都有**配額與清除策略**：Safari 對長時間未互動網站的資料清除最積極，這也是 iOS 上 PWA 可靠度常被討論的原因。

## 名詞剖析 {#1-5-5-3}

| 名詞 | 意思 |
| --- | --- |
| Origin（源） | 協定 + 網域 + 埠號的組合 |
| CSP | Content Security Policy，用回應標頭限制可載入與執行的資源 |
| XSS | 攻擊者的腳本被注入頁面執行 |
| COOP／COEP | 跨源開啟者政策／跨源嵌入者政策；兩者都設才算「跨源隔離」 |
| SharedArrayBuffer | 可在多個 Worker 間共享的記憶體，可用來做高精度計時，所以被限制 |
| HSTS | 告訴瀏覽器之後一律用 HTTPS |
| 憑證透明度（CT） | 所有憑證都要登記在公開日誌，誤發或假憑證可被發現 |
| Secure Context | HTTPS（或 localhost）頁面；很多敏感 API 只在這裡開放 |
| ITP／ETP／Total Cookie Protection | Safari／Firefox 的追蹤防護；後者把 Cookie 依頂層網站分區 |
| CHIPS | Cookies Having Independent Partitioned State，宣告 Partitioned 的第三方 Cookie |
| SameSite／HttpOnly／Secure | 限制跨站帶送（擋 CSRF）／禁止 JS 讀取／只在 HTTPS 傳送 |
| Service Worker | 頁面與網路之間的背景代理腳本 |
| PWA | 可安裝、可離線的網頁應用 |
| OPFS | 每個源私有、使用者看不到的高效能檔案系統 |
