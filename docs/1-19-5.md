## 登入、MFA 與信任裝置 {#1-19-5-1}

- 三個概念要分開：**Authentication**（你是本人嗎）、**Session**（這次登入還有效嗎）、**Trusted Device**（這個瀏覽器曾被本人授權嗎）。
- IP、User-Agent、Fingerprint 只是 **風險訊號**，不是身分憑證。
- 信任裝置做法：MFA 成功後由 server 產生高熵 device token → 放 HttpOnly Cookie → DB 只存 hash，含 `expires_at`、`revoked_at`，可列出、單台移除、全部撤銷。
- Logout 只讓 session 失效；移除信任裝置才讓 device token 失效。兩者生命週期不同。
- 高風險操作（改密碼/Email/MFA、看 recovery codes、交易、改付款資訊）一律 **Step-up 驗證**，信任裝置也不例外。
- MFA 強度：Passkey/WebAuthn（抗釣魚）＞ TOTP ＞ Email OTP ＞ SMS OTP。
- 核心句：**不是證明「這是哪台設備」，而是證明「這個 client 持有我在強驗證後簽發的憑證」。**

## 權限模型：Role / Permission / Scope / Condition {#1-19-5-2}

- 職級 ≠ 系統權限。不要設計成「Level 越高權限越大」。
- RBAC：Role 是 Permission 的集合；Permission 用具體動作命名，如 `invoice.approve`、`report.export`。
- 組織擴張後加 **Scope**（哪些資料：SELF / CHILDREN / ALL，配合組織樹 `org_units.parent_id`）。
- 再複雜加 **Condition / ABAC**（如金額 ≤ 10 萬、狀態為 Pending）。
- 判斷函式應長成 `can(user, action, resource, context)`，而不是到處 `if (role === 'manager')`。
- 避免角色爆炸：**Role 管職能、Permission 管動作、Scope 管範圍、Condition 管情境。**
- 職責分離（SoD）：建立者 ≠ 審核者、申請者 ≠ 自己的核准者、開發者 ≠ Production 核准者。
- 演進路線：RBAC → + Org Scope → + Policy/ABAC → SSO / MFA / Device Trust / Risk-based Auth。
