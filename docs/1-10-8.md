# 1-10-8 Flow 思維與最佳化模型 {#1-10-8}

::: info 新增（2026-11）
整理自 Notion「計算機基礎」第 12 節〈數學工具箱〉的「Flow 思維：Flow＋Constraint＋Optimization」。
:::

人流、車流、物流、金流、資訊流、API request、組織決策，都能問同一串問題：**從哪來 → 經過哪些節點 → bottleneck 在哪 → 容量多少 → 如何 routing → 資源怎麼配 → 最佳化什麼？**

| 模型／公式 | 意思 | 實務用法 |
| --- | --- | --- |
| Little's Law $L = \lambda W$ | 系統內平均數量＝到達率 × 平均停留時間 | 估連線池、thread pool、排隊人數、翻桌率 |
| 利用率 $\rho = \lambda / \mu$ | 到達速度 ÷ 服務速度；ρ 接近 1 等待暴增，ρ ≥ 1 隊伍無限變長 | 容量規劃：別把系統長期跑在 90% 以上 |
| M/M/1 平均停留 $W = 1/(\mu - \lambda)$ | 負載接近滿載時，延遲非線性上升 | 解釋「負載從 80% 到 95%，延遲翻好幾倍」 |
| 最大流 $f(u,v) \le c(u,v)$ | 每段流量不能超過容量 | API TPS、資料管線、動線瓶頸 |
| 最短路徑 $\min \sum w_i$；A\* $f(n)=g(n)+h(n)$ | 總成本最小；A\*＝已走成本＋預估剩餘成本 | 導航、遊戲 AI、路由 |
| Bellman／DP；Q-learning $Q(s,a)=r+\gamma \max Q(s',a')$ | 當前最佳＝現在報酬＋折現後的未來最佳 | 庫存、資產配置、強化學習 |
| Greedy | 每步取局部最佳（如價值／重量比） | 廣告競價、排序推薦；不保證全域最佳 |
| K-Means | 讓資料點離群中心的距離平方和最小 | 客群、商圈、股票族群分群 |
| 模擬退火 $P = e^{-\Delta E / T}$ | 早期容許變差的解以跳出局部最佳，後期收斂 | 排程、組合最佳化 |
| 連續方程 | 流入＝流出＋系統內變化 | 人流、車流、封包、金流 |
| 貨幣數量論 $MV = PQ$ | 貨幣量 × 流通速度＝價格 × 產出 | 理解流動性 → 資產價格的傳導 |
| Cache Hit Rate＝Hits ÷ Requests | 快取命中比例 | 快取設計與監控 |

- 修正原文：ρ 是「利用率」，不是「等待率」；原本的「Latency≈Load／Capacity」太粗，用上面 M/M/1 的式子才看得出接近滿載時延遲會爆。CAP 不是公式，而是分散式系統的取捨限制。
- **核心原則：不要只學公式；學會辨認現實問題屬於哪種模型，以及模型在什麼假設下會失效。**
- 懂演算法不會自動變成管理能力。能力是一條鏈：**現象 → 抽象模型 → 找 bottleneck → 建指標 → 提方案 → 配資源 → 落地 → 驗證商業結果。**例：懂排隊理論本身價值有限，用它重設餐廳流程、真的降低等待並提升翻桌率才算數。
- 商業可看成更大的系統設計（定價 → 消費行為、空間 → 人流、UI → 轉換率、組織設計 → 決策流、資本配置 → 產業）。政治與治理則不能直接套最佳化：還有利益、聯盟、合法性、認同與敘事；數學最佳解不等於社會能接受的解。
- 長期收斂方向：軟體架構、資料流、金流、人流、商業、組織 → Complex Systems／Network／Flow／Optimization／Decision Science 一套通用工具箱。
