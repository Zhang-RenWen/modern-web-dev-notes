# 1-9-1 前端模組化發展及專案規劃 {#1-9-1}

::: info 改寫（2026-11）
原內容整理自 2019 年前的書籍，當時 Node.js 的 ES Module 還要加 `--experimental-modules`，瀏覽器要用 `nomodule` 做降級。已把模組化歷史濃縮成一張表，更新為現在的狀況：ES Module 是瀏覽器與 Node.js 共同的標準，Node 22 起可以直接 `require()` ES Module，瀏覽器支援 import maps。
:::

> 一句話：**模組化 = 每個檔案有自己的作用域，明確宣告依賴什麼、提供什麼。** 現在一律寫 ES Module，其他格式看得懂就好。

## 演進史 {#1-9-1-1}

| 時期 | 寫法 | 解決了什麼 | 留下的問題 |
| --- | --- | --- | --- |
| 全域變數、命名空間 | `var MyApp = MyApp \|\| {}` | — | 命名衝突、依賴順序靠 `<script>` 排列 |
| IIFE | `(function ($) { … })(jQuery)` | 私有作用域、明確傳入依賴 | 依賴順序還是要手動管理 |
| CommonJS（2009，Node.js） | `const x = require('./x')`、`module.exports = …` | 伺服器端的同步模組 | 同步載入不適合瀏覽器 |
| AMD（RequireJS）、CMD（Sea.js） | `define(['dep'], function (dep) { … })` | 瀏覽器非同步載入 | 寫法繁瑣，只是過渡方案 |
| UMD | 同一份程式碼判斷環境，相容 CommonJS、AMD、全域變數 | 函式庫一次支援所有環境 | 樣板程式碼多 |
| **ES Module（ES2015）** | `import`／`export` | 語言標準，瀏覽器與 Node.js 都支援，可靜態分析 | — |

## ES Module 與 CommonJS 的差別 {#1-9-1-2}

| | ES Module | CommonJS |
| --- | --- | --- |
| 載入時機 | 先解析所有 `import` 建立依賴圖，再執行（非同步） | 執行到 `require` 才載入（同步） |
| 依賴能不能動態決定 | 靜態 `import` 只能寫在頂層、路徑要是字串；動態用 `import()` | 可以在任何地方、用變數 `require` |
| 匯出的是什麼 | **即時綁定**：模組內部改了值，外面讀到的也會變 | 一個物件：解構出來的原始值是當下的值，之後不會跟著變 |
| `this`、嚴格模式 | 頂層 `this` 是 `undefined`，自動嚴格模式 | 頂層 `this` 是 `module.exports` |
| 頂層 `await` | 可以（ES2022） | 不行 |

```js
// counter.mjs
export let count = 0
export const inc = () => { count++ }

// main.mjs
import { count, inc } from './counter.mjs'
inc()
console.log(count) // 1：即時綁定
```

同樣的寫法用 CommonJS（`const { count, inc } = require('./counter')`）會印出 `0`，因為解構時就把數字複製出來了。

## 為什麼 ES Module 設計成靜態的 {#1-9-1-3}

不執行程式碼就能知道「誰匯入了誰的什麼」，所以建置工具可以：

- **Tree shaking**：沒被匯入的匯出直接不打包。它是「從入口開始只留下用到的部分」，和傳統的死碼消除（打包完再刪掉跑不到的程式碼）方向相反。
- 提早報錯：匯入不存在的名稱，在載入階段就失敗。
- 型別檢查、IDE 自動完成更準確。

讓 tree shaking 真的有效：

- 函式庫要提供 ES Module 版本，並在 `package.json` 標註 `"sideEffects": false`（或列出有副作用的檔案，例如 CSS），打包工具才敢刪掉沒用到的模組。
- 少用 `export default` 匯出一個大物件（`export default { a, b, c }`），用具名匯出，未用到的才能個別刪掉；具名匯出也讓重新命名、自動匯入更可靠。
- 匯入時寫 `import { debounce } from 'lodash-es'`，而不是 `import _ from 'lodash'`。

## 現在怎麼用 {#1-9-1-4}

**瀏覽器**：

```html
<script type="importmap">
  { "imports": { "vue": "https://cdn.jsdelivr.net/npm/vue@3/dist/vue.esm-browser.prod.js" } }
</script>
<script type="module">
  import { createApp } from 'vue' // import map 讓瀏覽器也能用套件名稱匯入
</script>
```

- `type="module"` 的腳本自動 `defer`、自動嚴格模式、跨網域載入要有 CORS。
- 所有現代瀏覽器都支援 ES Module，不需要再用 `nomodule` 準備降級版本。
- 正式專案還是用建置工具打包：省掉大量請求、壓縮、處理 TypeScript 和 CSS。

**Node.js**：

- `package.json` 寫 `"type": "module"`，`.js` 就是 ES Module；也可以用副檔名 `.mjs`（ESM）／`.cjs`（CommonJS）個別指定。
- Node 22（並回補到 20.19）起，CommonJS 可以直接 `require()` 一個 ES Module（只要它沒有頂層 `await`），兩種格式混用的痛點大幅減少。
- 不再需要 `--experimental-modules` 或 `babel-node`。
