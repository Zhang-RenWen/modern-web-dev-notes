## 命名格式轉換：`snake_case` 與 `camelCase` {#1-6-13-1}

後端（尤其 Java、資料庫欄位）常回傳 `POLICY_NO` 這種大寫底線格式，前端習慣 `policyNo`。

```js
// POLICY_START_DATE → policyStartDate
function toCamelCase(str) {
  return str
    .toLowerCase()
    .split('_')
    .map((word, i) => (i === 0 ? word : word.charAt(0).toUpperCase() + word.slice(1)))
    .join('')
}

// policyStartDate → POLICY_START_DATE
function toUpperSnakeCase(str) {
  return str.replace(/([A-Z])/g, '_$1').toUpperCase()
}

// 整個物件的 key 一起轉（只轉第一層；巢狀資料要遞迴）
const camelizeKeys = (obj) =>
  Object.fromEntries(Object.entries(obj).map(([k, v]) => [toCamelCase(k), v]))
```

架構上的建議：這種轉換只在 API 層做**一次**（見 [1-6-11 去框架化 7 原則](./1-6-11.md#1-6-11-1)），不要散落在各元件裡。

## 起訖日期互相限制 {#1-6-13-2}

需求：查詢條件有「起日」與「迄日」，起日不能晚於迄日、迄日不能早於起日，兩者都不能早於 N 年前、不能晚於今天。

```js
import { computed } from 'vue'

const LIMIT_YEARS = 11

// N 年前的今天
function yearsAgo(years) {
  const d = new Date()
  return new Date(d.getFullYear() - years, d.getMonth(), d.getDate())
}

// 'YYYY-MM-DD' → 當地時間的 Date（不要用 new Date('2026-11-04')，那會被當成 UTC 零時）
function parseLocalDate(str) {
  const [y, m, d] = str.split('-').map(Number)
  return new Date(y, m - 1, d)
}

const startMin = computed(() => yearsAgo(LIMIT_YEARS))
const startMax = computed(() => (form.endDate ? parseLocalDate(form.endDate) : new Date()))
const endMin = computed(() => (form.startDate ? parseLocalDate(form.startDate) : yearsAgo(LIMIT_YEARS)))
const endMax = computed(() => new Date())
```

```vue
<DatePicker v-model="form.startDate" :min-date="startMin" :max-date="startMax" />
<DatePicker v-model="form.endDate" :min-date="endMin" :max-date="endMax" />
```

注意：
- 前端限制只是 UX，後端查詢仍要驗證日期範圍（避免一次撈出十幾年資料拖垮資料庫）。
- 跨時區系統要明確定義「今天」是哪個時區的今天。

## 讓日期元件也能顯示表單驗證錯誤 {#1-6-13-3}

問題：第三方日期元件（例如 `@vuepic/vue-datepicker`）不是表單框架的原生輸入框，驗證訊息與紅框樣式接不上。

做法：在日期元件上疊一個**看不見、不可點擊**的表單輸入元件，讓表單框架對它做驗證並顯示錯誤，使用者實際操作的仍是底下的日期元件。

```scss
// 在 main.ts 全域引入；統一日期元件的高度與邊框，跟其他輸入框一致
.dp__input {
  height: 30px;
  line-height: 22px;
  border: 1px solid rgba(0, 0, 0, 0.33);
}
.dp__input:hover:not(.dp__input_focus) {
  border-color: rgba(0, 0, 0, 1);
}

// 用來包住「日期元件 + 驗證用輸入框」
.dp-validate-wrapper {
  position: relative;
}

// 驗證用輸入框：疊在上面、透明、不攔截點擊，只保留錯誤訊息與外框樣式
.dp-validate {
  position: absolute;
  inset: 0;
  color: transparent;
  pointer-events: none;

  input {
    display: none;
  }

  // 起迄日之間有「-」連接符號時，扣掉符號寬度讓兩邊一致
  &.start {
    width: calc(100% - 17px);
  }
}
```

更好的長期做法是把日期元件包成自己的 `AppDatePicker`，內部處理 v-model 與驗證狀態，業務頁面不用知道這個技巧（見 [1-6-12 高難度通用元件](./1-6-12.md#1-6-12-2)）。

## 表格排序轉成後端排序參數 {#1-6-13-4}

UI 框架的資料表（例如 Vuetify `v-data-table`）的排序狀態是 `[{ key: 'createdAt', order: 'desc' }]`，後端 API 要的是 `['createdAt desc']`。

```js
import { ref } from 'vue'

const sortBy = ref([])

// 多欄排序
function onMultiSort(newSortBy) {
  sortBy.value = structuredClone(newSortBy)
  query.orderBys = newSortBy.map(({ key, order }) => `${key} ${order}`)
  fetchList()
}

// 單欄排序：只保留最新點擊的那一欄
function onSingleSort(newSortBy) {
  const latest = newSortBy.at(-1)
  sortBy.value = latest ? [latest] : []
  query.orderBys = sortBy.value.map(({ key, order }) => `${key} ${order}`)
  fetchList()
}
```

修正原始寫法的兩個問題：原本 `sortBy = reactive(...)` 直接重新賦值會讓模板失去響應（應該用 `ref` 改 `.value`，見 [模擬面試 5 Q2](./interview-5.md#interview-5-2)）；原本在 `forEach` 裡每次迴圈都呼叫查詢，應該組好參數後只查一次。

## MyBatis 動態查詢的寫法與陷阱 {#1-6-13-5}

這是 Java 後端常見的 MyBatis XML 寫法，前端工程師讀後端程式除錯時很常遇到。

```xml
<select id="findGroups" resultType="GroupView">
  SELECT g.group_id,
         g.group_name,
         LISTAGG(gc.channel_code, ',') WITHIN GROUP (ORDER BY gc.channel_code) AS channel_codes
  FROM app_group g
  LEFT JOIN app_group_channel gc ON g.group_id = gc.group_id
  <where>
    <if test="groupId != null and groupId != ''">
      AND g.group_id = #{groupId}
    </if>
    <if test="startDate != null and startDate != ''">
      AND g.created_at &gt;= TO_DATE(#{startDate}, 'YYYY-MM-DD')
    </if>
    <if test="endDate != null and endDate != ''">
      <!-- 迄日要包含當天整天：小於「迄日 + 1 天」 -->
      AND g.created_at <![CDATA[ < ]]> TO_DATE(#{endDate}, 'YYYY-MM-DD') + 1
    </if>
  </where>
  GROUP BY g.group_id, g.group_name
  <!-- 排序欄位不能用參數綁定，只能拼接，所以必須在 Java 端先比對白名單 -->
  <if test="orderBy != null">ORDER BY ${orderBy}</if>
</select>
```

重點：
1. **`#{}` 與 `${}`**：`#{}` 是參數綁定（PreparedStatement），安全；`${}` 是字串直接拼接，**有 SQL Injection 風險**。排序欄位只能用 `${}`，所以要在後端用白名單把前端傳來的 `createdAt desc` 對應成實際欄位與方向，不符合就丟棄。
2. **`<where>`** 會自動加上 `WHERE` 並去掉第一個多餘的 `AND`。
3. **XML 中的 `<`** 要寫成 `&lt;` 或包在 `<![CDATA[ ]]>` 裡。
4. **日期迄日**：欄位有時分秒時，`<= 迄日` 會漏掉當天 00:00 之後的資料，改成 `< 迄日 + 1 天`。
5. **`LISTAGG`**（Oracle）把多列合併成逗號字串，PostgreSQL 對應 `string_agg`、MySQL 對應 `GROUP_CONCAT`。
6. 欄位轉成字串比對（`TO_DATE(欄位)`、`LIKE '%' || x || '%'`）會讓索引失效，資料量大時要改成在欄位本身建索引、讓條件直接比對欄位。

相關：[1-19-6 寫入 API 防護（欄位白名單）](./1-19-6.md#1-19-6-1)、[1-22-4 效能診斷順序](./1-22-4.md#1-22-4-5)

## 民國年轉換 {#1-6-13-7}

```js
// Date → 民國年字串
const toRocDate = (date) => {
  const y = date.getFullYear() - 1911
  const m = String(date.getMonth() + 1).padStart(2, '0')
  const d = String(date.getDate()).padStart(2, '0')
  return `${y}/${m}/${d}`                           // '115/11/04'
}

// 或用內建的民國曆
new Intl.DateTimeFormat('zh-TW-u-ca-roc', { year: 'numeric', month: '2-digit', day: '2-digit' })
  .format(new Date(2026, 10, 4))                    // '民國115/11/04'

// '1151104'（後端常見的 7 碼民國日期）→ Date
const parseRoc7 = (str) => {
  const [, y, m, d] = str.match(/^(\d{2,3})(\d{2})(\d{2})$/) ?? []
  if (!y) return null
  return new Date(Number(y) + 1911, Number(m) - 1, Number(d))
```

## 身分證字號與統一編號檢查碼 {#1-6-13-8}

前端先擋明顯打錯的格式，減少送出後才被退件；**正式驗證仍在後端**。

```js
// 身分證字號（含 2021 年起新式外來人口統一證號：第二碼 8 或 9）
const LETTER_CODE = {
  A: 10, B: 11, C: 12, D: 13, E: 14, F: 15, G: 16, H: 17, I: 34, J: 18, K: 19, L: 20, M: 21,
  N: 22, O: 35, P: 23, Q: 24, R: 25, S: 26, T: 27, U: 28, V: 29, W: 32, X: 30, Y: 31, Z: 33,
}

function isValidTwId(id) {
  const v = id.trim().toUpperCase()
  if (!/^[A-Z][1289]\d{8}$/.test(v)) return false
  const code = LETTER_CODE[v[0]]
  const weights = [8, 7, 6, 5, 4, 3, 2, 1]
  let sum = Math.floor(code / 10) + (code % 10) * 9
  for (let i = 1; i <= 8; i++) sum += Number(v[i]) * weights[i - 1]
  sum += Number(v[9])                                // 檢查碼
  return sum % 10 === 0
}

isValidTwId('A123456789')   // true

// 統一編號（2023 年起檢查規則由「被 10 整除」放寬為「被 5 整除」）
function isValidUbn(ubn) {
  if (!/^\d{8}$/.test(ubn)) return false
  const weights = [1, 2, 1, 2, 1, 2, 4, 1]
  const digitSum = (n) => (n >= 10 ? digitSum(Math.floor(n / 10) + (n % 10)) : n)
  const sum = [...ubn].reduce((acc, ch, i) => acc + digitSum(Number(ch) * weights[i]), 0)
  if (sum % 5 === 0) return true
  // 第 7 碼為 7 時，7 × 4 = 28 → 10 → 可視為 1 或 0
  return ubn[6] === '7' && (sum - 1) % 5 === 0
}
```

## 全形與半形轉換 {#1-6-13-10}

使用者常用中文輸入法打出全形數字、英文與空白，送到後端驗證就失敗。

```js
// 全形 → 半形：全形 ！～（U+FF01–U+FF5E）與半形相差 0xFEE0；全形空白是 U+3000
const toHalfWidth = (str) =>
  str
    .replace(/[！-～]/g, (ch) => String.fromCharCode(ch.charCodeAt(0) - 0xfee0))
    .replace(/　/g, ' ')

toHalfWidth('１２３ＡＢＣ　ｘ')   // '123ABC x'

// 也可以用 Unicode 正規化（會一併處理其他相容字元）
'１２３ＡＢＣ'.normalize('NFKC')   // '123ABC'
```

建議在輸入框 `blur` 或送出前統一轉換，而不是在每個驗證規則裡各自處理。Unicode 正規化見 [7-3 String#normalize](./7-3.md)。

## 匯出 CSV 給 Excel 開啟 {#1-6-13-11}

```js
function exportCsv(rows, columns, filename) {
  // 欄位內有逗號、引號、換行時要用雙引號包起來，內部的引號重複一次
  const escape = (v) => {
    const s = v == null ? '' : String(v)
    return /[",\r\n]/.test(s) ? `"${s.replace(/"/g, '""')}"` : s
  }
  const header = columns.map((c) => escape(c.label)).join(',')
  const body = rows.map((r) => columns.map((c) => escape(r[c.key])).join(',')).join('\r\n')

  // 開頭加 BOM，Excel 才會用 UTF-8 解讀，否則中文變亂碼
  const blob = new Blob(['﻿' + header + '\r\n' + body], { type: 'text/csv;charset=utf-8' })
  downloadBlob(blob, filename)
}

exportCsv(list, [{ key: 'policyNo', label: '保單號碼' }, { key: 'amount', label: '金額' }], '保單清單.csv')
```

注意：
- 以 `0` 開頭的號碼（電話、帳號）被 Excel 打開會被吃掉前導零；需要保留時改由後端產生 `.xlsx`，或用 ExcelJS、SheetJS 指定儲存格為文字格式。
- 開頭是 `=`、`+`、`-`、`@` 的值可能被 Excel 當成公式執行（CSV Injection）；匯出使用者輸入的內容時，在前面加一個單引號 `'` 中和。
- 資料量大時由後端產檔，不要把幾萬筆資料拉到前端組字串。

## 下載後端產生的檔案 {#1-6-13-12}

```js
function downloadBlob(blob, filename) {
  const url = URL.createObjectURL(blob)
  const a = Object.assign(document.createElement('a'), { href: url, download: filename })
  document.body.append(a)
  a.click()
  a.remove()
  URL.revokeObjectURL(url)                    // 釋放記憶體
}

// 從 Content-Disposition 取出檔名（支援 RFC 5987 的 filename*=UTF-8''... 中文檔名）
function getFilename(res, fallback = 'download') {
  const cd = res.headers.get('Content-Disposition') ?? ''
  const star = cd.match(/filename\*=UTF-8''([^;]+)/i)
  if (star) return decodeURIComponent(star[1])
  const plain = cd.match(/filename="?([^";]+)"?/i)
  return plain ? plain[1] : fallback
}

async function downloadReport(params) {
  const res = await fetch(`/api/reports/export?${new URLSearchParams(params)}`, {
    headers: { Authorization: `Bearer ${token}` },
  })
  if (!res.ok) throw new Error(`下載失敗：${res.status}`)
  downloadBlob(await res.blob(), getFilename(res, 'report.xlsx'))
}
```

- 跨網域時，後端要在 CORS 設定 `Access-Control-Expose-Headers: Content-Disposition`，前端才讀得到這個標頭。
- 為什麼用 `fetch` 而不是直接 `<a href>`：需要帶 `Authorization` 標頭時，`<a>` 無法加標頭。
- 檔案很大（幾百 MB）時，`blob()` 會整個載入記憶體；改由後端產生短效的下載連結（presigned URL）讓瀏覽器直接下載。

## 檔案大小與上傳前檢查 {#1-6-13-13}

```js
const formatBytes = (bytes, digits = 1) => {
  if (bytes === 0) return '0 B'
  const units = ['B', 'KB', 'MB', 'GB', 'TB']
  const i = Math.min(Math.floor(Math.log(bytes) / Math.log(1024)), units.length - 1)
  return `${(bytes / 1024 ** i).toFixed(i === 0 ? 0 : digits)} ${units[i]}`
}
formatBytes(1536000)          // '1.5 MB'

function checkFile(file, { maxBytes = 10 * 1024 * 1024, types = ['application/pdf', 'image/jpeg', 'image/png'] } = {}) {
  if (!types.includes(file.type)) return `不支援的檔案格式：${file.type || '未知'}`
  if (file.size > maxBytes) return `檔案超過 ${formatBytes(maxBytes)}`
  return null
}
```

`file.type` 來自副檔名，可以被偽造；前端檢查只是提早提醒使用者，後端仍要檢查檔案內容（magic number）、大小與病毒掃描。

## 篩選條件同步到網址 {#1-6-13-14}

查詢條件放在網址，重新整理不會不見、可以把連結貼給同事、上一頁也能回到原本的篩選。

```js
// 物件 → query string（略過空值）
function toQuery(params) {
  const q = new URLSearchParams()
  for (const [k, v] of Object.entries(params)) {
    if (v === '' || v == null) continue
    if (Array.isArray(v)) v.forEach((item) => q.append(k, item))   // status=A&status=B
    else q.set(k, String(v))
  }
  return q.toString()
}

// query string → 物件（陣列欄位要明確指定）
function fromQuery(search, arrayKeys = []) {
  const q = new URLSearchParams(search)
  const result = {}
  for (const key of new Set(q.keys())) {
    result[key] = arrayKeys.includes(key) ? q.getAll(key) : q.get(key)
  }
  return result
}

toQuery({ keyword: '壽險', status: ['A', 'B'], page: 2, empty: '' })
// 'keyword=%E5%A3%BD%E9%9A%AA&status=A&status=B&page=2'
```

在 Vue Router 中用 `router.replace({ query })` 更新網址而不新增歷史紀錄；網址的值都是字串，數字、布林要自己轉型（見 [1-6-11 狀態先分類](./1-6-11.md#1-6-11-3)）。

## 物件差異比對：異動紀錄用 {#1-6-13-15}

送出修改前列出「改了哪些欄位」，用在確認視窗或稽核紀錄：

```js
function diff(before, after, labels = {}) {
  const keys = new Set([...Object.keys(before), ...Object.keys(after)])
  const changes = []
  for (const key of keys) {
    const a = before[key]
    const b = after[key]
    if (JSON.stringify(a) !== JSON.stringify(b)) {
      changes.push({ field: key, label: labels[key] ?? key, from: a, to: b })
    }
  }
  return changes
}

diff({ phone: '0912000000', city: '台北' }, { phone: '0988000000', city: '台北' }, { phone: '手機' })
// [{ field: 'phone', label: '手機', from: '0912000000', to: '0988000000' }]
```

- 只送出有改的欄位（PATCH），可以減少「兩個人同時編輯，後送的人把前一個人的修改蓋掉」的機會；完整的防護要搭配樂觀鎖（見 [1-19-6 併發](./1-19-6.md#1-19-6-1)）。
- `JSON.stringify` 比較對屬性順序敏感，巢狀物件要精確比較時用 lodash 的 `isEqual`。
- 真正的稽核紀錄由後端寫入，前端的差異只用於顯示（見 [1-22-4 歷史與資料保護](./1-22-4.md#1-22-4-3)）。

## 防止重複送出 {#1-6-13-16}

按鈕連點、網路慢時重按，可能建立兩筆資料。

```js
// 同一個 key 正在進行中，就回傳同一個 Promise，不再發第二次請求
const inflight = new Map()

function singleFlight(key, task) {
  if (inflight.has(key)) return inflight.get(key)
  const p = task().finally(() => inflight.delete(key))
  inflight.set(key, p)
  return p
}

async function onSubmit() {
  await singleFlight('create-order', () => api.post('/orders', form))
}
```

```vue
<!-- 畫面上同時鎖住按鈕 -->
<button :disabled="submitting" @click="submit">{{ submitting ? '送出中…' : '送出' }}</button>
```

前端防連點只是第一道；網路逾時後的重送，後端要靠 Idempotency-Key 才能真正避免重複建立（見 [模擬面試 9 Q7](./interview-9.md#interview-9-7)）。throttle 與 debounce 的寫法見 [模擬面試 12](./interview-12.md#interview-12-1)。
