## 命名格式轉換：`snake_case` 與 `camelCase` {#1-6-13-1}

後端（尤其 Java、資料庫欄位）常回傳 `POLICY_NO` 這種大寫底線格式，前端習慣 `policyNo`。

```js
// POLICY_START_DATE → policyStartDate
function toCamelCase(str) {
  return str
    .toLowerCase()
    .split('_')
    .map((word, i) => (i === 0 ? word : word.charAt(0).toUpperCase() + word.slice(1)))
    .join('')
}

// policyStartDate → POLICY_START_DATE
function toUpperSnakeCase(str) {
  return str.replace(/([A-Z])/g, '_$1').toUpperCase()
}

// 整個物件的 key 一起轉（只轉第一層；巢狀資料要遞迴）
const camelizeKeys = (obj) =>
  Object.fromEntries(Object.entries(obj).map(([k, v]) => [toCamelCase(k), v]))
```

架構上的建議：這種轉換只在 API 層做**一次**（見 [1-6-11 去框架化 7 原則](./1-6-11.md#1-6-11-1)），不要散落在各元件裡。

## 起訖日期互相限制 {#1-6-13-2}

需求：查詢條件有「起日」與「迄日」，起日不能晚於迄日、迄日不能早於起日，兩者都不能早於 N 年前、不能晚於今天。

```js
import { computed } from 'vue'

const LIMIT_YEARS = 11

// N 年前的今天
function yearsAgo(years) {
  const d = new Date()
  return new Date(d.getFullYear() - years, d.getMonth(), d.getDate())
}

// 'YYYY-MM-DD' → 當地時間的 Date（不要用 new Date('2026-11-04')，那會被當成 UTC 零時）
function parseLocalDate(str) {
  const [y, m, d] = str.split('-').map(Number)
  return new Date(y, m - 1, d)
}

const startMin = computed(() => yearsAgo(LIMIT_YEARS))
const startMax = computed(() => (form.endDate ? parseLocalDate(form.endDate) : new Date()))
const endMin = computed(() => (form.startDate ? parseLocalDate(form.startDate) : yearsAgo(LIMIT_YEARS)))
const endMax = computed(() => new Date())
```

```vue
<DatePicker v-model="form.startDate" :min-date="startMin" :max-date="startMax" />
<DatePicker v-model="form.endDate" :min-date="endMin" :max-date="endMax" />
```

注意：
- 前端限制只是 UX，後端查詢仍要驗證日期範圍（避免一次撈出十幾年資料拖垮資料庫）。
- 跨時區系統要明確定義「今天」是哪個時區的今天。

## 讓日期元件也能顯示表單驗證錯誤 {#1-6-13-3}

問題：第三方日期元件（例如 `@vuepic/vue-datepicker`）不是表單框架的原生輸入框，驗證訊息與紅框樣式接不上。

做法：在日期元件上疊一個**看不見、不可點擊**的表單輸入元件，讓表單框架對它做驗證並顯示錯誤，使用者實際操作的仍是底下的日期元件。

```scss
// 在 main.ts 全域引入；統一日期元件的高度與邊框，跟其他輸入框一致
.dp__input {
  height: 30px;
  line-height: 22px;
  border: 1px solid rgba(0, 0, 0, 0.33);
}
.dp__input:hover:not(.dp__input_focus) {
  border-color: rgba(0, 0, 0, 1);
}

// 用來包住「日期元件 + 驗證用輸入框」
.dp-validate-wrapper {
  position: relative;
}

// 驗證用輸入框：疊在上面、透明、不攔截點擊，只保留錯誤訊息與外框樣式
.dp-validate {
  position: absolute;
  inset: 0;
  color: transparent;
  pointer-events: none;

  input {
    display: none;
  }

  // 起迄日之間有「-」連接符號時，扣掉符號寬度讓兩邊一致
  &.start {
    width: calc(100% - 17px);
  }
}
```

更好的長期做法是把日期元件包成自己的 `AppDatePicker`，內部處理 v-model 與驗證狀態，業務頁面不用知道這個技巧（見 [1-6-12 高難度通用元件](./1-6-12.md#1-6-12-2)）。

## 表格排序轉成後端排序參數 {#1-6-13-4}

UI 框架的資料表（例如 Vuetify `v-data-table`）的排序狀態是 `[{ key: 'createdAt', order: 'desc' }]`，後端 API 要的是 `['createdAt desc']`。

```js
import { ref } from 'vue'

const sortBy = ref([])

// 多欄排序
function onMultiSort(newSortBy) {
  sortBy.value = structuredClone(newSortBy)
  query.orderBys = newSortBy.map(({ key, order }) => `${key} ${order}`)
  fetchList()
}

// 單欄排序：只保留最新點擊的那一欄
function onSingleSort(newSortBy) {
  const latest = newSortBy.at(-1)
  sortBy.value = latest ? [latest] : []
  query.orderBys = sortBy.value.map(({ key, order }) => `${key} ${order}`)
  fetchList()
}
```

修正原始寫法的兩個問題：原本 `sortBy = reactive(...)` 直接重新賦值會讓模板失去響應（應該用 `ref` 改 `.value`，見 [模擬面試 5 Q2](./interview-5.md#interview-5-2)）；原本在 `forEach` 裡每次迴圈都呼叫查詢，應該組好參數後只查一次。

## MyBatis 動態查詢的寫法與陷阱 {#1-6-13-5}

這是 Java 後端常見的 MyBatis XML 寫法，前端工程師讀後端程式除錯時很常遇到。

```xml
<select id="findGroups" resultType="GroupView">
  SELECT g.group_id,
         g.group_name,
         LISTAGG(gc.channel_code, ',') WITHIN GROUP (ORDER BY gc.channel_code) AS channel_codes
  FROM app_group g
  LEFT JOIN app_group_channel gc ON g.group_id = gc.group_id
  <where>
    <if test="groupId != null and groupId != ''">
      AND g.group_id = #{groupId}
    </if>
    <if test="startDate != null and startDate != ''">
      AND g.created_at &gt;= TO_DATE(#{startDate}, 'YYYY-MM-DD')
    </if>
    <if test="endDate != null and endDate != ''">
      <!-- 迄日要包含當天整天：小於「迄日 + 1 天」 -->
      AND g.created_at <![CDATA[ < ]]> TO_DATE(#{endDate}, 'YYYY-MM-DD') + 1
    </if>
  </where>
  GROUP BY g.group_id, g.group_name
  <!-- 排序欄位不能用參數綁定，只能拼接，所以必須在 Java 端先比對白名單 -->
  <if test="orderBy != null">ORDER BY ${orderBy}</if>
</select>
```

重點：
1. **`#{}` 與 `${}`**：`#{}` 是參數綁定（PreparedStatement），安全；`${}` 是字串直接拼接，**有 SQL Injection 風險**。排序欄位只能用 `${}`，所以要在後端用白名單把前端傳來的 `createdAt desc` 對應成實際欄位與方向，不符合就丟棄。
2. **`<where>`** 會自動加上 `WHERE` 並去掉第一個多餘的 `AND`。
3. **XML 中的 `<`** 要寫成 `&lt;` 或包在 `<![CDATA[ ]]>` 裡。
4. **日期迄日**：欄位有時分秒時，`<= 迄日` 會漏掉當天 00:00 之後的資料，改成 `< 迄日 + 1 天`。
5. **`LISTAGG`**（Oracle）把多列合併成逗號字串，PostgreSQL 對應 `string_agg`、MySQL 對應 `GROUP_CONCAT`。
6. 欄位轉成字串比對（`TO_DATE(欄位)`、`LIKE '%' || x || '%'`）會讓索引失效，資料量大時要改成在欄位本身建索引、讓條件直接比對欄位。
