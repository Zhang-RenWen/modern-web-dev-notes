# 1-7-4 React: 新一代特性 {#1-7-4}

::: info 改寫（2026-11）
原內容整理自 2019 年前的書籍，當時 Hooks 剛推出、`Suspense` 還在實驗階段（原文還推薦 react-loadable）。已精簡元件寫法的演進史，保留 Hooks 原理，並更新到 React 19：併發渲染、Actions、Server Components 與 React Compiler。
:::

## 元件寫法的演進 {#1-7-4-2}

| 時期 | 寫法 | 被取代的原因 |
| --- | --- | --- |
| 2013～ | `React.createClass({ … })`，自動綁定 `this`，用 mixins 共用邏輯 | mixins 會互相覆蓋、來源不清楚；React 16 移除 |
| 2015～ | `class extends React.Component`，生命週期方法 | 同一個功能的程式碼散在 `componentDidMount`／`DidUpdate`／`WillUnmount`；共用邏輯要靠 HOC、render props，元件樹越包越深 |
| 2019～ | **函式元件 + Hooks** | 依「功能」而不是「生命週期」組織程式碼，共用邏輯寫成自訂 Hook |

class 元件仍可使用，但新功能（Server Components、`use`、Actions）都只為函式元件設計。

## Hooks 的原理：靠呼叫順序記住狀態 {#1-7-4-3}

函式元件每次渲染都是重新執行一次函式，`useState` 怎麼記得上次的值？React 在每個元件實例上存了一個陣列（實際是鏈結串列），**依 Hook 的呼叫順序**對應：

```js
// 極簡示意：單一元件、忽略批次更新
let hooks = []
let index = 0

function useState(initial) {
  const i = index++
  if (hooks[i] === undefined) hooks[i] = initial
  const setState = (v) => {
    hooks[i] = typeof v === 'function' ? v(hooks[i]) : v
    rerender()
  }
  return [hooks[i], setState]
}

function useEffect(effect, deps) {
  const i = index++
  const prev = hooks[i]
  const changed = !prev || !deps || deps.some((d, k) => !Object.is(d, prev.deps[k]))
  if (changed) {
    prev?.cleanup?.()
    hooks[i] = { deps, cleanup: effect() } // 實際上 React 會在畫面更新後才執行
  }
}

function rerender() {
  index = 0 // 每次渲染從頭對應
  render(App)
}
```

所以 **Hook 只能寫在元件最上層**，不能放在 `if`、迴圈或巢狀函式裡：只要某次渲染少呼叫一個 Hook，後面的全部會對錯位置。

`useState` 回傳陣列而不是物件，是為了讓你自由命名：`const [count, setCount] = useState(0)`。

**useState 還是 useReducer**：狀態是幾個獨立的簡單值就用 `useState`；好幾個欄位會一起變、更新邏輯有分支（例如表單的載入／成功／失敗狀態機），用 `useReducer` 把邏輯集中成一個可測試的純函式。`useState` 在 React 內部其實就是簡化版的 `useReducer`。

`useReducer` + Context 可以做出「迷你 Redux」，但 Context 的限制見 [1-7-3](./1-7-3.md#1-7-3-3)。

## React 18：併發渲染 {#1-7-4-4}

React 18 起渲染可以被中斷：先處理緊急的更新（輸入、點擊），再處理不緊急的（大清單篩選結果）。

| API | 用途 |
| --- | --- |
| `startTransition`／`useTransition` | 把某個更新標成「不緊急」，輸入框不會因為下方結果在重算而卡住 |
| `useDeferredValue` | 拿一個「延後版本」的值去渲染昂貴的部分 |
| `<Suspense fallback>` | 子元件還沒準備好（程式碼、資料）時顯示 fallback |
| `React.lazy(() => import('./X'))` | 程式碼分割，搭配 `Suspense`（取代 react-loadable） |
| 自動批次更新 | 見 [1-7-2](./1-7-2.md#1-7-2-2) |

`Suspense` 的原理：元件在資料還沒好時「丟出」一個 Promise，最近的 `Suspense` 接住後顯示 fallback，Promise 完成後重新渲染。錯誤則由 Error Boundary 接住。

## React 19：Actions、use 與 Server Components {#1-7-4-5}

| 功能 | 說明 |
| --- | --- |
| Actions | `<form action={async (formData) => …}>`，pending、錯誤、重置表單由 React 處理 |
| `useActionState`、`useFormStatus` | 取得 Action 的結果與送出中狀態 |
| `useOptimistic` | 先在畫面上顯示預期結果，請求失敗自動還原 |
| `use(promise)`、`use(context)` | 在渲染中讀取 Promise（搭配 Suspense）或 Context，可以寫在條件判斷裡 |
| `ref` 直接當 prop | 不再需要 `forwardRef` |
| Server Components | 只在伺服器執行、不送 JS 到瀏覽器的元件，可以直接讀資料庫；需要 Next.js 這類框架支援 |
| React Compiler（2025 年 1.0） | 編譯時自動加上記憶化，大部分情況不用再手寫 `useMemo`、`useCallback`、`memo` |

## React 現代主線 {#1-7-4-1}

- `useEffect` 只放副作用（訂閱、DOM、timer）並寫 cleanup；伺服器資料交給 TanStack Query／SWR；Context 只放低頻全域設定（主題、登入者、語系）；複雜表單用 React Hook Form + Zod；不要到處包 `useMemo`／`useCallback`。
- 優化順序：先用 Profiler 確認真的有問題 → 把 state 下放到用得到的元件 → 拆 Context → 最後才用 `memo`（有 React Compiler 的專案連這步都可以省）。
- `useEffect` 常見錯誤有三個：依賴陣列漏寫、沒寫 cleanup、請求競態（用 `AbortController` 取消或忽略舊結果）。伺服器資料不要複製一份到全域 store。
- 「這個值可以從 props 或 state 算出來」就直接在渲染時算，不要用 `useEffect` 同步到另一個 state。
