## 設計原則 {#1-8-4-1}

- **翻譯放哪**：靜態文案放在 Git 的翻譯檔，可營運修改的動態內容放 DB。
- **後端只回 code，不回翻好的字**：錯誤與訊息回傳 code 加 parameters，前端依語系組字；日期、數字用 `Intl` 格式化。
- **CI 把關**：檢查各語系的 key 一致、沒有硬編碼中文。
- **決定語系的順序**：使用者明確選過的優先於 `navigator.languages`。切換語系時同步更新 `<html lang>`、呼叫 IdP 時帶 `ui_locales`，並處理語系代碼的對應（`zh-TW` ↔ `zh-Hant`）。
- **後端種子資料的名稱**：用穩定的 key 在前端翻譯，缺翻譯時退回 DB 名稱。各語系的 key 要完全一致，避免只有英文才有的 `_one`／`_other` 複數 key；名單串接用 `Intl.ListFormat`。
- **後端沒有發布翻譯**時回傳來源英文名並標 `localized: false`，前端若照單全收，中文介面會整批變英文。要依語系決定：有內建翻譯的語系跳過未翻譯項目，沒有內建翻譯的語系才用備援值，並補單元測試。

```js
// 日期、數字、名單都交給 Intl，不要自己拼字串
new Intl.DateTimeFormat('zh-TW', { dateStyle: 'medium' }).format(new Date())
new Intl.NumberFormat('ja-JP', { style: 'currency', currency: 'JPY' }).format(123456)
new Intl.ListFormat('en', { type: 'conjunction' }).format(['A', 'B', 'C']) // "A, B, and C"
```

## 排版與句型 {#1-8-4-2}

- 日文沒有空格，加 `word-break: auto-phrase` 才會在詞的邊界斷行；長標籤可以用 `:lang()` 選擇器，只在非中文語系換行。
- 自動產生的白話摘要句：判斷門檻只放後端，前端用固定模板加上算出來的詞組。句中的差距要用畫面上四捨五入後的數字相減，否則會出現「3.4 − 1.2 = 2.3」這種對不上的句子。這類問題單元測試抓不到，要用真實資料把每個語系實際讀一遍。
- 版面是否在某語系爆版，要跑「寬度 × 語系」矩陣（見 CSS 與 RWD 的實戰筆記）。

## 測試 {#1-8-4-3}

- 自動化測試切語系要透過畫面上的語言選單操作；直接改 localStorage 可能被登入後的會員偏好覆蓋，量到的是錯的語系。
