# 1-22-5 資料管線 Data Pipeline {#1-22-5}

::: info 新增（2026-11）
整理自 Notion「系統設計與架構」五〈資料管線 Data Pipeline〉。
:::

```txt
Ingestion → Data Lake（原始資料）→ ETL / Computation → Data Warehouse → API / Dashboard
```

- **架構圖上一個節點 ≠ 一個要自己寫的服務**。S3、Kinesis、BigQuery、Redshift 本身就是完整 managed service。看任何雲端架構圖先問：**這個節點是我要「開發」，還是要「選擇、設定、整合」？**
- 不值得自己造：Object Storage、Message Queue / Streaming、Data Warehouse、Distributed Compute。你的責任是：選什麼 → 怎麼組 → 資料怎麼流 → 怎麼失敗恢復 → 怎麼控成本。
- 真正要自己掌握：Ingestion（rate limit、retry）、Raw Data Design（schema、partition、時間格式）、ETL 裡的 Domain Logic、Orchestration（排程、依賴、重跑、資料品質）、Query API。小系統可能只是幾個 scheduled job + managed services。
- **ETL**：先轉換再載入，適合格式固定、隱私要求高的常態報表。**ELT**：先載入再用目標端算力轉換，適合非結構化與彈性分析（儲存變便宜後成為主流）。
- 金融案例：保單 / 收費 / 理賠 / CRM / 銀行扣款凌晨批次進數倉；各國央行利率格式不同，統一成 `date / country / interest_rate / currency`。
- **CRUD 系統處理交易，ETL 系統處理資料流**。資金流監控這類系統的難度大約：爬資料 30%、ETL 40%、分析模型 20%、前端 10%——資料髒了，後面全部失真。
