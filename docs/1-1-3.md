## WCAG 2.1 AA（POUR） {#1-1-3-1}

- **可感知**：圖片要有 `alt`、影片要有字幕。
- **可操作**：全功能可用鍵盤操作、避免引發癲癇的閃爍。
- **可理解**：色彩對比足夠、表單錯誤提示明確。
- **穩定**：相容各瀏覽器與螢幕閱讀器。
- AA 是多數企業與政府（含台灣數位發展部）的合規基準；最新版是 WCAG 2.2。元件層的無障礙互動（整列可點、tooltip）見 [1-8-2 前端實戰案例](./1-8-2.md)。

## 高價值 HTML {#1-1-3-2}

- 語意標籤：header、nav、main（一頁一個）、section、article、aside、footer；標題階層 h1–h3 照內容層級，不為字體大小跳級。
- head 重點：charset、viewport、description、title（比 meta keywords 重要得多）。
- 表單：label、name/value、fieldset + legend、required / pattern / min / max / autocomplete；`disabled` 不會送出、`readonly` 會送出；`accept` 只是提示，不是安全驗證。
- 圖片：`srcset` + `sizes` 讓瀏覽器挑合適尺寸；寫 width/height 預留空間。
- 原生互動：`details` / `summary`（FAQ）、`dialog` + `showModal()`（Modal）。
- 影片 `poster`、連結 `download`（跨網域不保證有效）、`tel:` / `mailto:`、`#id` 錨點。
- `contenteditable` 不等於編輯器：要處理 XSS、貼上 HTML、IME、Undo。

## 常見錯誤修正 {#1-1-3-3}

- `alt` 是替代文字（載入失敗、螢幕閱讀器），不是 hover 提示。
- `option` 裡的文字是使用者看到的，`value` 是送出的值。
- `del` 是被刪除的內容；`s` 是不再正確的內容；淘汰 tt、strike、acronym、`a name`、img align/border。
- `script type="text/javascript"`、`style type="text/css"` 不必寫；ES module 才寫 `type="module"`。
- table 只用來呈現表格資料，不拿來排版。

## 無障礙檢測 {#1-1-3-4}

- **自動化**：axe DevTools、Lighthouse Accessibility、WAVE。自動工具大約只能抓到一部分問題。
- **手動**：拔掉滑鼠只用 Tab／Shift+Tab／Enter／Esc 操作一遍；用 VoiceOver（Mac／iOS）或 NVDA（Windows）實際聽一次。
- DevTools Elements → **Accessibility** 分頁：看無障礙樹、ARIA 屬性、計算出的名稱與角色；Color picker 會顯示對比度是否達 WCAG AA／AAA。
- 附帶好處：AI 代理瀏覽器多半依賴無障礙樹理解頁面，a11y 做得好的網站，AI 也操作得比較順。

## 名詞剖析 {#1-1-3-5}

| 名詞 | 意思 |
| --- | --- |
| WCAG | W3C 的網頁無障礙指引；A／AA／AAA 是由低到高的符合等級 |
| POUR | WCAG 四大原則：Perceivable 可感知、Operable 可操作、Understandable 可理解、Robust 穩健 |
| a11y | accessibility 的縮寫（a + 11 個字母 + y） |
| ARIA | 補充語意的屬性（role、aria-label、aria-expanded…），原生標籤不夠表達時才用；能用原生標籤就不要用 ARIA |
| 無障礙樹 | 瀏覽器從 DOM 算出的簡化樹，只留角色、名稱、狀態，螢幕閱讀器和 AI 代理都讀這棵樹 |
| 螢幕閱讀器 | 把畫面內容唸出來的輔助軟體，常見 VoiceOver（Apple）、NVDA（Windows，免費） |
| srcset／sizes | 提供多個尺寸的圖片候選，讓瀏覽器依螢幕寬度與 DPR 挑最適合的一張 |
| dialog／showModal() | 原生對話框；showModal 會自動處理焦點鎖定、Esc 關閉、背景不可操作 |
| IME | 輸入法（注音、日文）；組字過程中的暫存字元不該被當成送出 |
