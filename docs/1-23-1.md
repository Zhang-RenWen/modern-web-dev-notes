## Node.js 是什麼 {#1-23-1-1}

Node.js 是 JavaScript 的執行環境（runtime）。對前端工程師來說，可以把它想成「沒有畫面的瀏覽器」：同樣用 V8 執行 JavaScript，但提供的是檔案、網路、程序等系統能力，而不是 DOM。

```txt
Node.js API（JavaScript：fs、http、net、stream…）
        ↓
Node.js Bindings（把 C/C++ 核心包成 JS API）／ C/C++ Addons（第三方原生模組）
        ↓
V8（執行 JS）  libuv（事件迴圈與非同步 I/O、執行緒池）  OpenSSL、zlib、c-ares…
        ↓
作業系統
```

- **Bindings** 是核心模組的膠水層；**Addons** 是給第三方 C/C++ 函式庫用的同一套機制。
- **libuv** 提供事件迴圈與跨平台的非同步 I/O；檔案系統、DNS、壓縮等工作在它的執行緒池裡跑。

## 單執行緒 + 事件迴圈 {#1-23-1-2}

- **「單執行緒」指的是執行你的 JavaScript 的那條執行緒**；Node.js 底層仍是多執行緒（libuv thread pool）。
- 傳統多執行緒伺服器：每個請求占一條執行緒，執行緒等 I/O 時就閒著；執行緒用完，新請求只能排隊。
- Node.js：事件迴圈不等待 I/O，把 I/O 交給底層，完成後再透過 callback 回來處理，所以少量執行緒就能扛大量連線。

比喻：銀行櫃檯是多執行緒模型（每個窗口一次服務一人，客人填單時窗口也在等）；咖啡店是事件迴圈模型（收銀台收完單就服務下一位，飲料做好再叫號）。

| 優點 | 代價 |
| --- | --- |
| I/O 密集時併發能力強，記憶體占用小 | **CPU 密集運算會卡住整個事件迴圈**，所有請求一起變慢 |
| 不用處理多執行緒共享記憶體的鎖 | 未捕捉的錯誤會讓整個程序退出，需要程序管理器（PM2、容器重啟策略） |
| npm 生態、前後端同語言 | 弱型別難維護 → 用 TypeScript |
| | 只用到一顆 CPU 核心 → 用多程序或 worker_threads（見 [1-23-4](./1-23-4.md)） |

## 寫 Node.js 的三個挑戰 {#1-23-1-3}

1. **錯誤處理**：瀏覽器裡沒處理的錯誤通常只是 console 報錯；Node.js 裡可能讓整個服務掛掉。callback 慣例是 `(err, result)`，每一個都要處理；現代寫法用 async/await + try/catch，並監聽 `unhandledRejection`。
2. **非同步流程控制**：「A 完成後同時跑 B 和 C，兩者都完成才跑 D」用巢狀 callback 很難寫也很慢，改用 Promise 組合（`await A(); await Promise.all([B(), C()]); D()`）。
3. **長時間執行**：前端頁面會重新整理，伺服器不會。記憶體洩漏、V8 記憶體上限、多程序協作都要考慮（見 [1-23-3](./1-23-3.md)、[1-23-4](./1-23-4.md)）。

## WebSocket 與反向代理在 Node.js 部署中的角色 {#1-23-1-4}

- **WebSocket** 一樣建立在 TCP 上，用 HTTP Upgrade 握手後變成持續的雙向連線，伺服器可以主動推送。它沒有同源限制，但主要用途是即時雙向通訊，不是拿來解跨域。在 Node.js 裡，`wss.on('connection')`、`socket.on('message')` 背後就是 EventEmitter 的事件驅動模型。
- **反向代理（Nginx 等）** 放在 Node.js 前面：
  - 靜態檔直接由代理回應或快取，API 請求轉給後端。
  - 瀏覽器只跟同一個來源溝通，代理與後端之間是伺服器對伺服器，**沒有同源政策**，所以也能順便解決跨域。
  - 負載平衡、TLS 終止、隱藏真實後端位址。
- **正向代理**由客戶端指定（例如 VPN、開發時 Webpack／Vite dev server 的 `proxy` 設定），伺服器不知道真實的客戶端是誰；反向代理則是客戶端不知道真實的後端是誰。
- 校正：放 Nginx 的理由不只是「Node.js 單執行緒撐不住」，而是分工：連線管理、靜態資源、TLS、限流交給代理，Node.js 專注業務邏輯。雲端平台或 Serverless 部署時，這層常由平台提供。
- WebSocket 目前仍是即時雙向通訊的主流；單向推播可用 SSE，WebTransport 還在發展中。

```nginx
server {
  listen 80;
  root /usr/share/nginx/html;          # 靜態檔
  location /api/ {
    proxy_pass http://localhost:3000;  # API 轉給 Node.js
  }
  location /ws/ {
    proxy_pass http://localhost:3000;
    proxy_http_version 1.1;            # WebSocket 需要升級連線
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
  }
}
```

## Node.js 學習地圖 {#1-23-1-5}

| 主軸 | 內容 |
| --- | --- |
| 執行環境 | V8、事件迴圈、CommonJS／ESM、`process`、REPL |
| 核心模組 | fs、path、os、buffer、stream、events、timers、net、dns、crypto、child_process、cluster、readline、zlib |
| 非同步與 I/O | 非阻塞 I/O、callback → Promise → async/await、Stream、libuv |
| 網路服務 | http／https、REST API、Express／Fastify／NestJS、WebSocket、CORS |
| 資料庫 | SQL vs NoSQL、PostgreSQL／MySQL、MongoDB、ORM（Prisma、TypeORM、Sequelize）、連線池、交易、索引 |
| 認證與安全 | Session／Cookie、JWT、OAuth 2.0／OIDC、bcrypt／argon2、輸入驗證、Helmet |
| 測試 | 單元、整合、E2E、Mock、覆蓋率（見 [1-23-5](./1-23-5.md)） |
| 效能與除錯 | Profiler、記憶體與 GC、洩漏偵測、日誌與錯誤追蹤 |
| 部署與維運 | Docker、Kubernetes、Nginx、CI/CD、環境變數、Prometheus／Grafana、集中式日誌 |

| 生態工具 | npm／pnpm、TypeScript、esbuild、ESLint、Prettier、OpenAPI |

## 從 Node.js 轉到 Go 或 Java {#1-23-1-6}

可以直接帶走的觀念：非同步與併發、事件驅動、模組化與封裝、API 設計、資料庫交易與索引、測試與 CI/CD、效能與資源管理。

| 面向 | Node.js | Go | Java |
| --- | --- | --- | --- |
| 併發 | 單執行緒事件迴圈 + 非阻塞 I/O | goroutine + channel（CSP 模型） | 執行緒、ExecutorService、CompletableFuture、虛擬執行緒（Java 21） |
| 型別 | 動態（靠 TypeScript 補） | 靜態、編譯期檢查 | 靜態、編譯期檢查 |
| 物件導向 | class + prototype | 沒有 class，struct + interface，組合優於繼承 | 完整 OOP（class、interface、abstract） |
| 錯誤處理 | 例外 + Promise rejection | 回傳 `error` 值 | 例外（checked／unchecked） |
| 執行方式 | V8 JIT | 編譯成單一執行檔 | Bytecode + JVM JIT |
| 生態 | Express、Fastify、NestJS | net/http、Gin、GORM | Spring Boot、Hibernate、Maven／Gradle |

要另外補學的：
- **Go**：靜態型別與編譯錯誤、指標、`defer`、goroutine 與 channel 的最佳實踐、`error` 回傳慣例、go modules、`go test`／`go vet`。
- **Java**：完整 OOP 與設計模式、例外體系、泛型、執行緒與同步鎖、JVM 與 GC 調校、Spring 生態、Maven／Gradle。
