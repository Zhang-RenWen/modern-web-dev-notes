# 1-23-4 Node.js 多程序與多執行緒 {#1-23-4}

::: info 新增（2026-11）
整理自 Notion「Node.js 了不起」子頁〈Node.js 多進程〉，已套用原頁 AI 校正的現況（`isMaster` → `isPrimary`、部署改用 CI/CD 等）。
:::

一個 Node.js 程序只用到一顆 CPU 核心，而且程序一掛整個服務就停。要用滿多核心、提高穩定性，就要開多個程序；要處理 CPU 密集運算，則用 worker_threads。

多程序要解決兩件事：**程序之間怎麼溝通**、**誰來管理程序的啟停**。

## PM2：生產環境的程序管理器 {#1-23-4-1}

```bash
npm i -g pm2
pm2 start app.js -i 0        # 依 CPU 核心數啟動多個程序（cluster mode）
pm2 list / pm2 monit / pm2 logs
pm2 restart app / pm2 stop app / pm2 delete app
pm2 save                     # 保存目前程序清單
pm2 resurrect                # 依保存的清單重新啟動
pm2 startup                  # 產生開機自動啟動的設定
```

- PM2 啟動一個常駐的守護程序（God Daemon），應用程式崩潰時自動重啟。手動 `stop`／`delete` 的程序不會被重啟。
- `-i 0` 啟動的多個程序是**並列的副本**，請求會被分散到各程序（負載平衡）。
- **程序之間不共用記憶體**：登入狀態、快取若放在程序內的變數，下一個請求被分到另一個程序就找不到。共享狀態要放 Redis、資料庫或其他外部儲存。
- `pm2 init` 產生 `ecosystem.config.js`，可以設定多個應用、各環境的環境變數（`--env production`）。
- PM2 也有 `pm2 deploy` 遠端部署功能，但現在主流是用 GitHub Actions、GitLab CI 等 CI/CD 流程部署；容器化部署則交給 Docker／Kubernetes 的重啟策略與副本數。

## cluster 模組：主程序 + 工作程序 {#1-23-4-2}

```js
// primary.js
import cluster from 'node:cluster'
import { availableParallelism } from 'node:os'

cluster.setupPrimary({ exec: './worker.js' })   // 把工作程序的程式碼分開，不用 if/else 混在一起
for (let i = 0; i < availableParallelism(); i++) cluster.fork()

cluster.on('exit', (worker, code, signal) => {
  console.log(`worker ${worker.process.pid} exited (${signal ?? code})，重新啟動`)
  cluster.fork()                                // 意外退出就補一個，就是簡易版的守護程序
})

// worker.js
import http from 'node:http'
http.createServer((req, res) => res.end(`I'm worker ${process.pid}\n`)).listen(8080)
```

- Node.js 16 起 `cluster.isMaster`、`setupMaster` 改名為 `isPrimary`、`setupPrimary`。
- 多個工作程序可以監聽同一個 port，這是 cluster 存在的主要原因。
- **連線分配方式**：
  1. **Round-robin**（Windows 以外的預設）：主程序接收連線，再輪流交給工作程序。
  2. 主程序建立 socket 後交給工作程序自己 accept。理論上較快，但多個程序被同時喚醒搶同一個連線（**驚群效應**），實際負載常常不平均。
- **溝通**：主程序 `worker.send(msg)`、工作程序 `process.on('message')`；反過來是 `process.send(msg)` 與 `worker.on('message')`。工作程序之間不能直接溝通，要透過主程序轉發。
- 管理 API：`fork()` 建立、`disconnect()` 斷開、`kill()` 結束；事件有 `online`、`listening`、`disconnect`、`exit`、`error`。
- 容器環境要確認取得的核心數符合容器的 CPU 限制；通常容器內只跑一個程序，用 Kubernetes 的副本數做水平擴展。

## child_process：執行其他程式 {#1-23-4-3}

要呼叫 Shell 指令、Python 腳本等非 Node.js 程式時用 child_process。cluster 其實就是建立在 child_process 與 net 模組之上。

| 方法 | 行為 | 適合 |
| --- | --- | --- |
| `spawn` | 啟動指令，以串流取得 stdout／stderr | 長時間執行、輸出量大 |
| `exec` | 在 shell 中執行，結束後一次回傳輸出 | 簡短指令（注意命令注入風險） |
| `execFile` | 直接執行檔案，不經過 shell | 比 `exec` 安全 |
| `fork` | 啟動新的 Node.js 程序，內建 IPC 通道 | Node.js 子程序、需要互傳訊息 |

各方法都有 `*Sync` 同步版本，會阻塞事件迴圈，只適合 CLI 工具。

- **IPC**：父程序建立管道，子程序透過環境變數連上，雙方用 `send()` 與 `message` 事件溝通。`send()` 的第二個參數可以傳遞**控制代碼**（handle，例如 server 或 socket），讓多個子程序共用同一個 port；cluster 就是用這個機制實作的。直接用 `fork` 讓多個子程序各自 `listen(8080)` 則會出現 `EADDRINUSE`。
- **非 Node.js 的子程序**：用標準輸入輸出溝通，`child.stdin.write()` 送資料、`child.stdout.on('data')` 收結果。
- 子程序事件：`exit`、`close`（stdio 關閉）、`error`、`message`、`disconnect`。

```js
import { spawn } from 'node:child_process'

const py = spawn('python3', ['score.py'])
let out = ''
py.stdout.on('data', (buf) => { out += buf })
py.stderr.on('data', (buf) => console.error(buf.toString()))
py.on('close', (code) => console.log('exit', code, out))
py.stdin.end(JSON.stringify({ id: 1 }))
```

## worker_threads：真正的多執行緒 {#1-23-4-4}

Node.js 12 起穩定，用來處理 **CPU 密集**的工作（影像處理、加解密、大量計算）。I/O 工作不需要它，事件迴圈本來就處理得好，開執行緒反而增加成本。

和多程序相比：執行緒切換成本較低；可以用 `SharedArrayBuffer` 共享記憶體、或用 transfer 移轉 ArrayBuffer 而不複製；跟著父程序一起結束。

```js
// main.js
import { Worker } from 'node:worker_threads'

function runTask(data) {
  return new Promise((resolve, reject) => {
    const worker = new Worker(new URL('./task.js', import.meta.url), { workerData: data })
    worker.once('message', resolve)
    worker.once('error', reject)
    worker.once('exit', (code) => code !== 0 && reject(new Error(`exit ${code}`)))
  })
}
console.log(await runTask({ n: 40 }))

// task.js
import { parentPort, workerData } from 'node:worker_threads'
const fib = (n) => (n < 2 ? n : fib(n - 1) + fib(n - 2))
parentPort.postMessage(fib(workerData.n))
```

- 溝通：`workerData` 傳初始資料，`postMessage` / `message` 事件雙向傳訊；也可以建立 `MessageChannel`，把其中一個 port 傳給子執行緒，兩個 port 地位對等。
- 管理：`worker.terminate()` 立即停止；事件有 `online`、`message`、`error`、`exit`。
- 實務上用執行緒池（例如 Piscina）重複利用 worker，不要每個請求都新建。

## 怎麼選 {#1-23-4-5}

| 需求 | 做法 |
| --- | --- |
| 用滿多核心處理 HTTP 請求、程序掛了自動重啟 | PM2 cluster mode，或容器 + Kubernetes 多副本 + 外部負載平衡 |
| 自己控制主從程序 | cluster 模組 |
| 執行其他語言的程式或指令 | child_process |
| CPU 密集運算不要卡住事件迴圈 | worker_threads（搭配執行緒池） |
| 程序之間共享狀態 | Redis、資料庫等外部儲存 |

cluster 與 worker_threads 不是替代關係：前者解決「多程序共用 port」，後者解決「CPU 密集運算」。
