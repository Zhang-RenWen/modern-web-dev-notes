# 4-3 產生器函式和產生器物件

::: info 改寫（2026-11）
整理自《Practical Modern JavaScript》（2017）。已精簡重複的 `next()` 輸出，「用 generator 處理非同步流程」改成歷史說明（現在用 async/await），補上 ES2025 的迭代器輔助方法。
:::

### 4-3-1 基本語法 {#4-3-1}

`function*` 宣告的函式，呼叫時**不會立刻執行**，而是回傳一個產生器物件；每次要下一個值時才執行到下一個 `yield` 並暫停。

```js
function* numbers() {
  console.log('開始')
  yield 1
  yield 2
  return 3 // return 的值在 for...of、展開時會被忽略
}

const g = numbers() // 還沒印出「開始」
[...numbers()]      // 印出「開始」，得到 [1, 2]
```

產生器物件**同時是可迭代物件和迭代器**：有 `next()`，`g[Symbol.iterator]()` 回傳的就是自己。所以它只能走訪一次，走完就結束了。

**`yield*` 委派**給另一個可迭代物件，逐一產出它的值：

```js
function* salute(name) {
  yield* 'hello '
  yield* name
}
[...salute('you')] // ['h', 'e', 'l', 'l', 'o', ' ', 'y', 'o', 'u']
```

### 4-3-2 手動呼叫 next {#4-3-2}

```js
const g = numbers()
g.next() // { value: 1, done: false }
g.next() // { value: 2, done: false }
g.next() // { value: 3, done: true }：return 的值在這裡拿得到
g.next() // { value: undefined, done: true }：結束後再呼叫都一樣
```

### 4-3-3 用產生器實作可迭代物件 {#4-3-3}

手寫 `next()` 要自己維護狀態；用產生器，狀態就是區域變數：

```js
const fibonacci = {
  *[Symbol.iterator]() {
    let [prev, curr] = [0, 1]
    while (true) {
      yield curr
      ;[prev, curr] = [curr, prev + curr]
    }
  },
}
Iterator.from(fibonacci).take(8).toArray() // [1, 1, 2, 3, 5, 8, 13, 21]（ES2025）
```

### 4-3-4 走訪樹狀結構 {#4-3-4}

遞迴 + `yield*` 很適合寫樹的走訪，呼叫端可以隨時停止：

```js
function* walk(node) {
  yield node
  for (const child of node.children ?? []) yield* walk(child)
}
for (const node of walk(document.body)) {
  if (node.id === 'target') break // 找到就停，不會走完整棵樹
}
```

### 4-3-5 把「怎麼走訪」和「拿來做什麼」分開 {#4-3-5}

產生器負責產生序列，使用端負責處理，兩邊可以獨立替換。搭配延遲計算，處理大量資料時只計算需要的部分：

```js
function* readLines(text) {
  for (const line of text.split('\n')) yield line
}
const firstErrors = Iterator.from(readLines(log))
  .filter((l) => l.includes('ERROR'))
  .take(10)
  .toArray() // 找到 10 筆就停，不會處理整份 log
```

### 4-3-6 雙向溝通：next(value) {#4-3-6}

`next(value)` 傳入的值，會成為暫停中那個 `yield` 運算式的結果：

```js
function* conversation() {
  const name = yield '你叫什麼名字？'
  const age = yield `${name}，你幾歲？`
  return `${name} ${age} 歲`
}
const c = conversation()
c.next().value       // '你叫什麼名字？'（第一次 next 的參數會被忽略）
c.next('Ren').value  // 'Ren，你幾歲？'
c.next(30).value     // 'Ren 30 歲'
```

### 4-3-7 throw 與 return {#4-3-7}

```js
g.throw(new Error('x')) // 在暫停的 yield 處丟出錯誤，產生器內部可以用 try/catch 接住
g.return('end')         // 直接結束，回傳 { value: 'end', done: true }；會執行 finally 區塊
```

`for...of` 中途 `break` 或丟錯時，會自動呼叫 `return()`，所以產生器裡的 `finally` 一定會執行，適合放清理資源的程式碼。

### 4-3-8 用產生器寫非同步流程（歷史） {#4-3-8}

async/await 出現之前，產生器加上一個「執行器」可以把非同步程式寫成同步的樣子：

```js
run(function* () {
  const user = yield fetchJSON('/user') // yield 出 Promise，執行器等它完成後用 next(結果) 送回來
  const posts = yield fetchJSON(`/posts?user=${user.id}`)
})

function run(genFn) {
  const g = genFn()
  const step = (result) => {
    if (result.done) return Promise.resolve(result.value)
    return Promise.resolve(result.value).then((v) => step(g.next(v)), (e) => step(g.throw(e)))
  }
  return step(g.next())
}
```

這就是 co 函式庫與 Koa 1 的做法。**async/await 等於把 `run` 內建進語言**：`async function` 取代 `function*`，`await` 取代 `yield`。現在寫非同步一律用 async/await（見 [4-4](./4-4.md)）。

### 4-3-9 現在還會用到產生器的地方 {#4-3-9}

- 自訂可迭代物件、延遲產生的序列（分頁讀取、無限捲動的資料來源）。
- 樹、圖的走訪。
- 非同步產生器 `async function*` 處理串流資料（見 [4-5](./4-5.md)）。
- redux-saga 用產生器描述副作用流程，方便測試（新專案較少用）。
