# 9-6 類別與代理器

::: info 改寫（2026-11）
整理自《Practical Modern JavaScript》（2017），已精簡。
:::

## 類別 {#9-6-1}

和手寫原型相比，`class` 的好處是**所有東西集中在一個地方**：建構函式、方法、靜態方法、繼承都寫在同一個區塊裡，不會散落在 `Player.prototype.xxx = …` 的一長串賦值中；也能直接繼承 `Array`、`Date`、`Error` 這類內建物件。

```js
class List extends Array {
  get last() { return this.at(-1) }
}
new List('a', 'few', 'examples').last // 'examples'
```

但 JavaScript 不強制使用類別。什麼時候用：

| 用 class | 用一般物件或函式 |
| --- | --- |
| 會建立很多實例，而且有共用的行為 | 只有一個實例（設定、單一服務），物件字面值就夠了 |
| 需要私有狀態（`#` 欄位）、繼承內建物件 | 資料結構（`{ id, name }`），用物件 + 純函式處理更好測試與序列化 |
| 框架要求（Web Components、部分 Angular、NestJS） | React、Vue 3 的元件與邏輯共用已經以函式為主 |

繼承超過兩層就要停下來想：用組合（把能力當參數或 mixin 傳進來）通常更有彈性。

## 代理器 {#9-6-2}

Proxy 能做到以前做不到的事（攔截任意屬性存取），但代價是**行為變得不直覺**：讀一個屬性可能觸發任何邏輯，除錯時很難看出來。

適合：

- 函式庫、框架內部（Vue 的響應式、Immer、MobX）。
- 開發工具、測試替身、存取記錄。
- 在開發環境加上額外的檢查（例如存取不存在的屬性就警告），正式環境拿掉。

不適合：一般業務邏輯。能用一般函式、getter/setter 或驗證函式解決的，就不要用 Proxy。

Proxy 的用法見 [6-1](./6-1.md)。
