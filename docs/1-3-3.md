# 1-3-3 物件導向和原型鏈 {#1-3-3}

::: info 改寫（2026-11）
原內容整理自 2019 年前的書籍，已精簡並更新：刪掉 Babel 6 編譯結果逐行解說與相容 IE10 的寫法；「Babel 編譯後無法繼承 Date」已經不成立；jQuery 與 EventEmitter 範例濃縮成重點。
:::

> 一句話：**JavaScript 的物件沒有「類別」這張藍圖，只有一條原型鏈**：自己身上找不到的屬性，就往原型找，一路找到 `null`。`class` 是這套機制的語法糖。

## 原型鏈怎麼運作 {#1-3-3-1}

| 名詞 | 是什麼 |
| --- | --- |
| `Foo.prototype` | 函式（建構函式、class）身上的物件，`new Foo()` 產生的實例會以它為原型 |
| 物件的 `[[Prototype]]` | 每個物件內部指向原型的連結；用 `Object.getPrototypeOf(obj)` 讀取（舊寫法 `obj.__proto__`） |
| `constructor` | `Foo.prototype.constructor === Foo`，從實例找回建構函式 |

```js
class Person { greet() { return 'hi' } }
const p = new Person()

p.greet()        // p 自己沒有 → Person.prototype 有
p.toString()     // Person.prototype 沒有 → Object.prototype 有
Object.getPrototypeOf(Person.prototype) === Object.prototype // true
Object.getPrototypeOf(Object.prototype)                      // null，鏈的終點
```

- `obj instanceof Foo`：檢查 `Foo.prototype` 有沒有出現在 `obj` 的原型鏈上。
- `Object.hasOwn(obj, 'x')`（ES2022）：只看自己身上，不往原型找。
- 方法放在原型上，所有實例共用同一份；屬性寫在建構函式裡，每個實例各一份。

## new 做了什麼 {#1-3-3-2}

```js
function myNew(Ctor, ...args) {
  const obj = Object.create(Ctor.prototype) // 1. 建立物件，原型指向 Ctor.prototype
  const result = Ctor.apply(obj, args)      // 2. 以 obj 為 this 執行建構函式
  // 3. 建構函式明確回傳物件（或函式）就用它，否則回傳 obj
  return (typeof result === 'object' && result !== null) || typeof result === 'function' ? result : obj
}
```

`class` 不能用 `myNew` 呼叫：class 建構函式只能用 `new` 執行，直接 `apply` 會丟 `TypeError`。

## 繼承：從 ES5 到 class {#1-3-3-3}

ES5 時代的「寄生組合式繼承」，也就是 `class extends` 背後做的事：

```js
function Parent(name) { this.name = name }
Parent.prototype.say = function () { return this.name }

function Child(name, age) {
  Parent.call(this, name) // 繼承實例屬性
  this.age = age
}
Child.prototype = Object.create(Parent.prototype) // 繼承原型方法，且不會執行 Parent
Child.prototype.constructor = Child               // 修回 constructor
Object.setPrototypeOf(Child, Parent)              // 繼承靜態方法
```

早期還有「`Child.prototype = new Parent()`」的寫法，缺點是會多執行一次 `Parent`，而且所有子實例共用同一份父實例屬性，現在不要用。

現在直接寫：

```js
class Child extends Parent {
  constructor(name, age) {
    super(name) // 一定要先呼叫 super 才能用 this
    this.age = age
  }
}
```

| ES5 寫法做不到、`class` 可以的事 | 說明 |
| --- | --- |
| 繼承內建物件（`Date`、`Array`、`Error`、`Map`） | `class MyDate extends Date {}` 可以正常呼叫 `getTime()`；ES5 用 `Date.call(this)` 會得到「this is not a Date object」 |
| 私有欄位 `#x`、`static` 區塊 | 真正的私有，不是命名慣例 |
| 防止忘記 `new` | class 不用 `new` 呼叫會直接報錯 |

以前用 Babel 6 把 class 轉成 ES5 時無法繼承 `Date`；Babel 7 改用 `Reflect.construct` 後已經可以。現在的建置目標大多是 ES2015 以上，class 根本不會被轉譯。

## 原型在實務上的例子 {#1-3-3-4}

- **jQuery**：`$('p')` 回傳的物件，原型是 `$.fn`，所以每個結果都有 `addClass` 這些方法；`$.ajax` 直接掛在 `$` 函式上，是靜態方法。替 `$.fn` 加方法就是在寫 jQuery 外掛。
- **元件共用能力**：讓所有 UI 元件繼承一個有事件功能的基底類別，元件之間就能用 `emit`／`on` 溝通。瀏覽器現在內建 `EventTarget`，可以直接 `class Widget extends EventTarget`，再用 `dispatchEvent(new CustomEvent('favor'))` 發事件。
- **繼承不要太深**：超過兩層就很難追「這個方法到底定義在哪」。現在更常用組合（把功能做成函式或 mixin 注入），React Hooks、Vue Composables 都是這個方向。

TypeScript 的 class、介面、抽象類別見 [1-4-4 TypeScript 的物件導向語法](./1-4-4.md)。
