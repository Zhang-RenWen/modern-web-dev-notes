# 1-8-5 瀏覽器擴充功能開發（MV3） {#1-8-5}

::: info 新增（2026-11）
整理自 Notion「JavaScript」17。範例是一個從零寫的 MV3 擴充「頁面健檢器」，指標意義見 Web 檢測與 DevTools。
:::

## 架構原理 {#1-8-5-1}

擴充功能本質上是一個**打包好的小型網頁應用**（HTML／CSS／JS），但被瀏覽器賦予了一般網頁沒有的權限（讀寫分頁、攔截請求、存取 Cookie 等）。各大瀏覽器都採用 **WebExtensions API** 這套共通規格，加上 **Manifest V3（MV3）**。

```txt
┌──────────────────────────── 擴充功能 ────────────────────────────┐
│  Service Worker（背景）     Popup／Options／Side Panel            │
│  - 事件驅動、閒置會被終止   - 一般擴充頁面，可用完整 chrome.* API  │
│  - 監聽分頁、alarm、訊息    - 關掉就銷毀                           │
│          ▲  │ chrome.runtime 訊息    ▲                             │
│          │  ▼                       │                             │
│  Content Script（注入到網頁）  ◀─────┘                             │
│  - 能讀寫該網頁的 DOM                                              │
│  - 跑在「隔離世界」：與頁面 JS 共用 DOM，但不共用 JS 變數           │
│  - 只能用少量擴充 API（runtime、storage、i18n）                    │
└─────────────────────────────────────────────────────────────────┘
                 │ 共享 DOM
                 ▼
          網頁本身的 JS（Main World）
```

| 元件 | 執行位置 | 能做什麼 | 限制 |
| --- | --- | --- | --- |
| Service Worker | 擴充自己的背景環境 | 監聽瀏覽器事件、呼叫大部分 API、協調各元件 | 沒有 DOM；閒置約 30 秒會被終止，**不能用全域變數存狀態** |
| Content Script | 目標網頁的隔離世界 | 讀寫 DOM、注入 UI | 跨源請求受該網頁源限制，大部分 API 要透過訊息請背景做 |
| Popup | 點工具列圖示的小視窗 | 快速操作 UI | 一失焦就關閉 |
| Side Panel | 瀏覽器側邊欄 | 常駐 UI（AI 助手類擴充常用） | Chrome／Edge 為主 |
| Options Page | 設定頁 | 使用者設定 | — |
| Offscreen Document | 隱藏的擴充頁 | 需要 DOM 的背景工作（剪貼簿、音訊、DOM 解析） | 一次只能一個，須宣告用途 |
| DevTools Page | DevTools 內的自訂面板 | 做自己的檢測工具 | 只在 DevTools 開啟時存在 |

## MV2 → MV3 的核心變化 {#1-8-5-2}

| 項目 | MV2 | MV3 | 原因 |
| --- | --- | --- | --- |
| 背景 | 常駐 background page | 事件驅動 **Service Worker** | 省記憶體與電量 |
| 遠端程式碼 | 可載入遠端 JS | **禁止**，所有程式碼必須打包在擴充內 | 讓審查看得到全部程式碼，防止上架後偷換惡意程式 |
| 網路攔截 | `webRequest` 可阻擋／改寫 | 改用宣告式 **`declarativeNetRequest`** 規則；`webRequest` 只能觀察（企業政策例外） | 擴充不再能看到並竄改每個請求內容，提升隱私與效能 |
| 執行腳本 | `tabs.executeScript` | `chrome.scripting.executeScript` | API 整理 |
| 工具列 | `browser_action`／`page_action` | 統一為 `action` | 簡化 |
| CSP | 可放寬 | 不可用 `eval`／遠端腳本 | 安全 |

MV3 的爭議點：`declarativeNetRequest` 有規則數量上限，限制了廣告封鎖器的彈性。Firefox 雖然也支援 MV3，但保留了阻擋式 `webRequest`，背景也可用事件頁而非強制 Service Worker，所以在 Firefox 上進階內容過濾類擴充仍較有優勢。

## 從零寫一個 MV3 擴充：頁面健檢器 {#1-8-5-3}

點圖示後顯示目前頁面的 Core Web Vitals、缺 alt 的圖片數量、外部腳本數量。

```txt
page-checker/
├── manifest.json
├── background.js
├── content.js
├── popup.html
└── popup.js
```

```json
{
  "manifest_version": 3,
  "name": "頁面健檢器",
  "version": "1.0.0",
  "description": "快速檢查目前頁面的效能與基本品質",
  "action": { "default_popup": "popup.html", "default_title": "頁面健檢" },
  "background": { "service_worker": "background.js", "type": "module" },
  "permissions": ["activeTab", "scripting", "storage"],
  "content_scripts": [
    { "matches": ["<all_urls>"], "js": ["content.js"], "run_at": "document_start" }
  ]
}
```

::: warning 最小權限原則
能用 `activeTab`（只在使用者點擊時取得目前分頁權限）就不要要 `<all_urls>` 的 host_permissions。權限越大，審查越久、安裝時警告越嚇人。上面的 content_scripts 為了在頁面一開始就量 LCP／CLS 而用 `<all_urls>`，正式產品可改成使用者點擊後才用 `scripting` 動態注入。
:::

**content.js**（在頁面內量測，用 PerformanceObserver）

```js
const metrics = { lcp: null, cls: 0, longTasks: 0 }

new PerformanceObserver((list) => {
  metrics.lcp = Math.round(list.getEntries().at(-1).startTime)
}).observe({ type: 'largest-contentful-paint', buffered: true })

new PerformanceObserver((list) => {
  for (const e of list.getEntries()) if (!e.hadRecentInput) metrics.cls += e.value
}).observe({ type: 'layout-shift', buffered: true })

new PerformanceObserver((list) => {
  metrics.longTasks += list.getEntries().length
}).observe({ type: 'longtask', buffered: true })

chrome.runtime.onMessage.addListener((msg, _sender, sendResponse) => {
  if (msg.type === 'GET_REPORT') {
    sendResponse({
      ...metrics,
      cls: Number(metrics.cls.toFixed(3)),
      imgNoAlt: document.querySelectorAll('img:not([alt])').length,
      thirdPartyScripts: [...document.scripts]
        .filter((s) => s.src && new URL(s.src).origin !== location.origin).length,
    })
  }
})
```

**popup.html**

```html
<!doctype html>
<html lang="zh-Hant">
<head><meta charset="utf-8"><style>
  body { font: 14px system-ui; width: 260px; padding: 12px; }
  td:last-child { text-align: right; font-weight: 600; }
</style></head>
<body>
  <h3>頁面健檢</h3>
  <table id="report"><tr><td>讀取中…</td></tr></table>
  <script type="module" src="popup.js"></script>
</body>
</html>
```

**popup.js**（`type="module"` 所以可以用頂層 await）

```js
const [tab] = await chrome.tabs.query({ active: true, currentWindow: true })
const r = await chrome.tabs.sendMessage(tab.id, { type: 'GET_REPORT' })

const rows = [
  ['LCP', `${r.lcp ?? '—'} ms`, r.lcp && r.lcp <= 2500],
  ['CLS', r.cls, r.cls <= 0.1],
  ['Long Tasks', r.longTasks, r.longTasks === 0],
  ['缺 alt 的圖片', r.imgNoAlt, r.imgNoAlt === 0],
  ['第三方腳本', r.thirdPartyScripts, r.thirdPartyScripts < 10],
]
document.getElementById('report').innerHTML = rows
  .map(([k, v, ok]) => `<tr><td>${ok ? '✅' : '⚠️'} ${k}</td><td>${v}</td></tr>`)
  .join('')
```

**background.js**（Service Worker 的正確寫法：狀態存 storage，不存變數）

```js
chrome.runtime.onInstalled.addListener(() => {
  chrome.storage.local.set({ checksRun: 0 })
})
```

載入測試：`chrome://extensions` → 開啟「開發人員模式」→「載入未封裝項目」→ 選資料夾。

## 元件之間的通訊 {#1-8-5-4}

| 方式 | 適用 |
| --- | --- |
| `chrome.runtime.sendMessage`／`onMessage` | 一次性請求–回應（content ↔ background ↔ popup） |
| `chrome.tabs.sendMessage(tabId, …)` | 背景／popup 主動送給某分頁的 content script |
| `chrome.runtime.connect` → Port | 長連線、串流資料 |
| `chrome.storage.onChanged` | 用儲存當共享狀態，各元件被動同步 |
| `window.postMessage` | content script ↔ 網頁本身的 JS（必須驗證 `event.origin` 與資料格式） |
| `externally_connectable` | 讓指定網站直接和擴充通訊 |

**儲存選擇**：`storage.local`（本機，預設約 10MB，可申請 unlimitedStorage）、`storage.sync`（跨裝置同步，容量小）、`storage.session`（記憶體內，瀏覽器關閉即清，適合放暫存敏感資料）。

## MV3 常見坑與解法 {#1-8-5-5}

| 坑 | 解法 |
| --- | --- |
| Service Worker 被終止，全域變數消失 | 狀態一律存 `chrome.storage`；事件監聽器必須在頂層**同步註冊** |
| `setTimeout`／`setInterval` 不可靠 | 用 `chrome.alarms` |
| 背景需要 DOM（解析 HTML、剪貼簿） | 用 Offscreen Document |
| 想用 `eval`／遠端程式碼 | 不允許；設定檔可以遠端抓 JSON，但邏輯要打包 |
| Content script 抓不到頁面的 JS 變數 | 隔離世界；需要時用 `scripting.executeScript({ world: 'MAIN' })`，並注意安全 |
| Content script 跨源 fetch 被 CORS 擋 | 改由 background 發請求（需宣告 host_permissions） |
| SPA 換頁後 content script 沒重跑 | 監聽 `history` 變化或用 `MutationObserver`，或 `webNavigation.onHistoryStateUpdated` |

## 跨瀏覽器開發 {#1-8-5-6}

| 面向 | Chrome／Edge | Firefox | Safari |
| --- | --- | --- | --- |
| 命名空間 | `chrome.*`（MV3 多數 API 已回傳 Promise） | `browser.*`（Promise），也相容 `chrome.*` | `browser.*` |
| 背景 | Service Worker | 事件頁 `background.scripts` | Service Worker／非持久背景頁 |
| 阻擋式 webRequest | 否（企業安裝例外） | 是 | 否 |

| 商店 | Chrome Web Store／Edge Add-ons | addons.mozilla.org（AMO） | App Store |

## 除錯與測試 {#1-8-5-7}

- **Service Worker**：`chrome://extensions` → 擴充卡片上的「Service Worker」連結 → 開它專屬的 DevTools。
- **Popup**：在 popup 上右鍵 → 檢查。
- **Content Script**：在目標網頁開 DevTools → Console 左上角下拉選單切換到擴充的執行環境；Sources → Content scripts 分頁下中斷點。
- 模擬 SW 被終止：在 `chrome://serviceworker-internals` 停止它，確認狀態恢復邏輯正確。
- **單元測試**：Vitest + `@webext-core/fake-browser`（WXT 內建支援）模擬 `browser.*` API。
- **E2E 測試**：Playwright 用 `launchPersistentContext` 載入未封裝擴充（`--load-extension`），可測 popup 與 content script 的實際行為。

## 安全與隱私 {#1-8-5-9}

- **擴充是供應鏈攻擊熱門目標**：熱門擴充被收購或開發者帳號被盜，更新後植入惡意程式碼的事件屢見不鮮。開發者帳號務必開 2FA。
- Content script 收到網頁的 `postMessage` 一律視為不可信輸入；不要把網頁資料直接塞進 `innerHTML`（用 `textContent` 或框架自動跳脫）。
- 敏感資料（Token）放 `storage.session`，不要放 `storage.sync`；絕不把 GitHub token 等金鑰寫進擴充，要同步就用自己的後端或 OAuth。
- **企業端**：可透過 Chrome／Edge 企業政策（`ExtensionInstallAllowlist`、`ExtensionSettings`）限制員工能安裝的擴充，金融業通常採白名單制。

## 2026 年的新方向 {#1-8-5-10}

- **AI Side Panel 擴充**：用 `sidePanel` API 做常駐 AI 助手，搭配 content script 讀取頁面內容。
- **瀏覽器內建 AI API**：Chrome 提供在裝置端執行的 Prompt／Summarizer／Translator 等內建 AI API，擴充可直接呼叫而不必把資料送到雲端（依版本與裝置條件開放，使用前查官方文件）。
- **DevTools 擴充**：用 `devtools_page` + `chrome.devtools.panels` 做自訂檢測面板（例如公司內部的 API 監看器）。
- WXT 已讓「一套程式碼、四家瀏覽器」成為常態。

## 作品點子：追蹤粉絲增減 {#1-8-5-11}

- 架構：Content Script 讀 DOM → `chrome.storage.local` 存快照 → 與上次比對 → Popup 顯示新增／消失；GitHub Pages 只做官網、說明、匯入 JSON 畫圖（它是靜態站，不能當資料庫）。
- 比對用穩定的 user id，其次 username，不用顯示名稱；用 Map／Set 比對。
- 真正難點：無限捲動抓不完整、DOM 改版 selector 失效、區分「退追／改名／刪帳／抓取失敗」、遵守平台條款。
- 履歷寫法：寫安裝數、活躍用戶、評分、節省時間、技術（Manifest V3、Service Worker、最小權限、本機儲存）。

**練習路線**：① 手寫一次原生 MV3「頁面健檢器」→ ② 用 WXT + React + TypeScript 重寫並同時輸出 Chrome／Firefox 版 → ③ 加上 DevTools 面板，顯示 Network 請求統計 → ④ 寫 Playwright E2E 測試 → ⑤ 上架 Edge Add-ons（免費）當作品集。

## 名詞剖析 {#1-8-5-12}

| 名詞 | 意思 |
| --- | --- |
| WebExtensions API | 各大瀏覽器共通的擴充功能 API 規格 |
| Service Worker（擴充） | 事件驅動的背景腳本，沒有 DOM、閒置會被關掉；跟網頁離線快取用的 Service Worker 是同一種技術 |
| Isolated World／Main World | 隔離世界：content script 自己的 JS 環境，與頁面共用 DOM 但變數互不可見；Main World 是頁面本身的 JS 環境 |
| Offscreen Document | MV3 給背景用的隱藏頁面，讓沒有 DOM 的 Service Worker 有地方做 DOM 工作 |
| declarativeNetRequest | 宣告式網路規則：擴充只提供規則，由瀏覽器自己執行封鎖或改寫，擴充看不到請求內容 |
| host_permissions／activeTab | 前者宣告可存取哪些網站；後者是使用者點擊時才臨時取得目前分頁權限 |
| chrome.alarms | 擴充專用的排程器，Service Worker 被終止也會喚醒執行 |
| PerformanceObserver | 瀏覽器 API，訂閱 LCP、layout-shift、longtask 等效能事件 |
| externally_connectable | manifest 設定，指定哪些網站可以直接對擴充發訊息 |
| 供應鏈攻擊 | 不直接攻擊目標，而是污染它依賴的套件、擴充或更新管道 |
