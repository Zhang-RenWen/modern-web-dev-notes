# 1-16-3 軟體到硬體的分層：Server × OS × CPU {#1-16-3}

::: info 新增（2026-11）
整理自 Notion「計算機基礎」第 3 節，以及「程式語言」第四節〈底層心智模型〉的語言與 OS 分層。
:::

```txt
應用程式 → Runtime／Library → 作業系統 OS → ISA 指令集 → CPU／SoC → 電晶體
例：Node.js API → V8 → Linux → ARM64 → AWS Graviton → 實體 CPU
```

- **ISA ≠ CPU**：ISA 是「CPU 看得懂哪些指令」的規格（x86-64、ARM64／AArch64、RISC-V）；CPU 是實作它的產品（Intel Xeon、AMD EPYC 用 x86-64；Apple Silicon、AWS Graviton、Ampere 用 ARM64）。
- **OS 與 ISA 不是一對一**：Linux 支援 x86-64／ARM64／RISC-V；Windows 也有 ARM64 版；macOS 現代主要是 ARM64。重點是「OS 必須有對應 ISA 的版本」，不要背「Linux＝x86」。
- **Docker 的 linux/amd64、linux/arm64 就是 ISA**（amd64≈x86-64）。Apple Silicon Mac 跑舊 x86 image 會 architecture mismatch → 要 multi-arch image 或模擬。
- **程式怎麼跑到 CPU**：Source → Compiler／Interpreter／Runtime → 機器指令 → OS Process → Scheduler → Thread → CPU Core。C／C++ 直接編成機器碼；Java 是 Bytecode → JVM／JIT；JavaScript 是 V8 JIT。
- **Server 硬體**：CPU 執行指令、ECC RAM 暫存執行中的資料、NVMe SSD 長期儲存、NIC 網路傳輸、GPU 選配做平行運算。
- **Cloud 沒脫離這套模型**：App → Guest OS → Hypervisor → 實體 Server。延伸線：Physical Server → VM → Container → Kubernetes → Cloud。

> OS 管理硬體資源；ISA 定義軟體與 CPU 之間的指令介面；CPU 是 ISA 的硬體實作；Cloud 是在實體硬體上再做資源抽象。

## 語言與 OS 分層 {#1-16-3-1}

User Space（Bash、C++/Rust/Node 程式、Docker Engine）→ System Call（open／read／write／fork／execve）→ Kernel（排程、記憶體、VFS、網路堆疊、driver）→ Hardware

- 語言不決定權限，權限由 CPU 特權層級與 OS 決定；C++/Rust 只是能以更低抽象成本使用這些介面。
- Docker 不是 VM：Container 共用 Host Kernel，用 Namespaces 隔離視圖、Cgroups 限制資源；映射到同一個 Host Port 仍會衝突。
- Linux 三個核心問題：誰有權限？誰能用資源？同時操作會不會出錯？（這就是要學 mutex／atomic／memory ordering 的原因）
- 開機流程：UEFI → Bootloader → Kernel → Init → Apps。
