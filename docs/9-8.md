# 9-8 複雜性、抽象化與規範

::: info 改寫（2026-11）
整理自《Practical Modern JavaScript》（2017），已精簡並修正錯字。
:::

**抽象化是把複雜性搬到別的地方，而不是消除它。** async 函式建立在產生器的概念上，產生器是可迭代的，迭代器靠 Symbol 實作，非同步迭代器又用到 Promise，Promise 底層則是回呼。每一層都讓上層程式碼更簡單，但出問題時，你需要懂它下面那幾層。

**一致性比單一寫法的優劣更重要。** 一個專案大部分用 Promise、一部分用回呼，讀程式的人每換一段就要切換思考方式。兩種寫法各自都能降低複雜度，混在一起反而增加。

這就是為什麼需要**團隊規範**：

- 決定預設寫法（例如「非同步一律 async/await」「預設 `const`」「具名匯出」），寫進文件。
- 能自動化的交給工具：ESLint 規則、Prettier、TypeScript 的嚴格設定、commit 前檢查（見 [1-9-4](./1-9-4.md)）。
- 例外要有理由，並在程式碼旁留註解說明為什麼。

程式碼是寫給人讀的溝通工具，電腦只是剛好也能執行它。開發者大部分時間都在讀程式，所以選擇語法時，優先考慮的是「下一個讀的人能不能一眼看懂」。
