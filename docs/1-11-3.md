# 1-11-3 伺服器發送事件（SSE） {#1-11-3}

::: info 改寫（2026-11）
原內容整理自《High Performance Browser Networking》（Ilya Grigorik，2013）第 16 章。已刪掉 polyfill 與 IE 相容的段落（所有瀏覽器都原生支援），協定說明濃縮成一個範例；補上 HTTP/2 下連線數不再是限制，以及 LLM 串流輸出這個近年最常見的用途。
:::

> 一句話：**伺服器透過一個不結束的 HTTP 回應，持續把文字訊息推給瀏覽器**；瀏覽器內建斷線重連，還會帶上最後收到的訊息 ID。

## 用戶端：EventSource {#1-11-3-1}

```js
const source = new EventSource('/stream') // 跨網域要帶 Cookie：new EventSource(url, { withCredentials: true })

source.onmessage = (e) => render(JSON.parse(e.data)) // 沒有指定 event 名稱的訊息
source.addEventListener('price', (e) => updatePrice(e.data)) // 指定類型的訊息
source.onerror = () => {
  // 斷線時觸發；瀏覽器會自己重連，不需要手動處理
  if (source.readyState === EventSource.CLOSED) showOffline()
}
source.close() // 不再需要時關閉
```

## 伺服器：text/event-stream 格式 {#1-11-3-2}

回應標頭 `Content-Type: text/event-stream`，內容是一則則以**空行**分隔的訊息：

```text
retry: 5000
                                    ← 空行：上一則訊息結束
data: 第一則，純文字

data: {"msg": "JSON 也只是文字"}

id: 42
event: price
data: 第一行
data: 第二行（多個 data 會用換行接起來）

: 冒號開頭是註解，常用來當心跳，避免代理伺服器因閒置而斷線
```

| 欄位 | 用途 |
| --- | --- |
| `data` | 訊息內容（只能是 UTF-8 文字，二進位要自己編成 Base64） |
| `event` | 訊息類型，對應 `addEventListener('類型')`；沒寫就是 `message` |
| `id` | 訊息 ID，瀏覽器會記住最後一個 |
| `retry` | 斷線後幾毫秒重連 |

```js
// Node.js 最小範例
import http from 'node:http'
http.createServer((req, res) => {
  res.writeHead(200, { 'Content-Type': 'text/event-stream', 'Cache-Control': 'no-cache' })
  const lastId = Number(req.headers['last-event-id'] ?? 0) // 重連時從這裡接著送
  let id = lastId
  const timer = setInterval(() => res.write(`id: ${++id}\ndata: ${Date.now()}\n\n`), 1000)
  req.on('close', () => clearInterval(timer))
}).listen(3000)
```

**斷線續傳**：重連時瀏覽器會自動帶 `Last-Event-ID: 42` 標頭，伺服器據此補送漏掉的訊息（伺服器要保留最近的訊息才能補）。

## 什麼時候用 SSE {#1-11-3-3}

| 優點 | 限制 |
| --- | --- |
| 就是一般 HTTP：Cookie 認證、CORS、壓縮、負載平衡、代理伺服器都照常運作 | 只有伺服器 → 用戶端；用戶端要送資料就另外發 `fetch` |
| 內建重連與續傳 | 只能傳文字 |
| 比 WebSocket 簡單，不用另外的協定和伺服器 | `EventSource` 不能自訂請求標頭、只能 GET（要帶 token 或用 POST 時，改用 `fetch` 讀串流，自己解析格式） |

適合：通知、動態牆、股價、建置進度、**LLM 逐字輸出**（各家 AI API 的串流回應就是 SSE 格式，前端多半用 `fetch` + `ReadableStream` 讀取，因為要 POST 和帶 API 標頭）。

**HTTP/1.1 的連線數限制**：每個 SSE 都占一條連線，HTTP/1.1 下同一網域最多約 6 條，開好幾個分頁就會把連線用光、其他請求卡住。HTTP/2、HTTP/3 下所有串流共用一條連線，沒有這個問題。

需要雙向、頻繁互傳時改用 [WebSocket](./1-11-4.md)；各方案比較見 [1-11-1](./1-11-1.md#1-11-1-2)。
