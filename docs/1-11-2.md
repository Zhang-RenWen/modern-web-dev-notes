# 1-11-2 XMLHttpRequest 與 fetch {#1-11-2}

::: info 改寫（2026-11）
原內容整理自《High Performance Browser Networking》（Ilya Grigorik，2013）第 15 章，當時 `fetch` 還不存在，串流只能用 XHR 的 `responseText` 手動切割。已改成以 `fetch` 為主、XHR 只留下它仍有優勢的地方（上傳進度）；刪掉 XHR 簡史；CORS 的細節移到 [1-5-6](./1-5-6.md)。
:::

> 一句話：**JS 發 HTTP 請求的 API**，連線、快取、重新導向、安全限制都由瀏覽器處理。新程式用 `fetch`，只有需要上傳進度時用 XHR。

XHR 從 IE5 開始，讓網頁不必重新整理就能和伺服器交換資料，開啟了 AJAX 與單頁應用。`fetch`（2015）是它以 Promise 為基礎的後繼者。

## fetch 與 XHR 的差別 {#1-11-2-1}

| | `fetch` | `XMLHttpRequest` |
| --- | --- | --- |
| 寫法 | Promise，可以 `await` | 事件 callback |
| HTTP 錯誤（404、500） | **不會 reject**，要自己檢查 `res.ok` | 一樣不算錯誤，看 `status` |
| 取消 | `AbortController`；`AbortSignal.timeout(ms)` 設逾時 | `xhr.abort()`、`xhr.timeout` |
| 串流讀取回應 | `res.body` 是 `ReadableStream`，文字和二進位都可以 | 只能讀不斷變長的 `responseText` |
| 下載進度 | 讀串流時自己累計位元組 | `progress` 事件 |
| **上傳進度** | 沒有 | **`xhr.upload.onprogress`** |
| Cookie | 同源預設帶；跨域要 `credentials: 'include'` | 跨域要 `withCredentials = true` |
| 在 Service Worker 裡用 | 可以 | 不行 |

```js
async function getJSON(url) {
  const res = await fetch(url, { signal: AbortSignal.timeout(8000) })
  if (!res.ok) throw new Error(`HTTP ${res.status}`) // 404、500 要自己丟錯
  return res.json()
}
```

## 下載：回應的格式 {#1-11-2-2}

| 方法 | 得到 | 用在 |
| --- | --- | --- |
| `res.json()` | 物件 | API |
| `res.text()` | 字串 | HTML、CSV |
| `res.blob()` | `Blob` | 圖片、檔案下載（搭配 `URL.createObjectURL`） |
| `res.arrayBuffer()` | 二進位 | 音訊處理、自訂二進位格式 |
| `res.body` | `ReadableStream` | 大檔案、邊收邊處理 |

```js
// 下載進度
const res = await fetch(url)
const total = Number(res.headers.get('Content-Length'))
let received = 0
const reader = res.body.getReader()
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  received += value.length
  onProgress(received / total) // 回應有壓縮時 Content-Length 是壓縮後大小，比例只是估計
}
```

**串流處理文字**，例如逐行讀 NDJSON 或 LLM 的逐字輸出：

```js
const res = await fetch('/stream')
const lines = res.body.pipeThrough(new TextDecoderStream())
for await (const chunk of lines) render(chunk) // 每收到一段就處理
```

## 上傳 {#1-11-2-3}

```js
const form = new FormData()
form.append('file', fileInput.files[0])
form.append('note', '備註')
await fetch('/upload', { method: 'POST', body: form }) // 不要自己設 Content-Type，瀏覽器會加上 boundary
```

需要上傳進度條時用 XHR：

```js
const xhr = new XMLHttpRequest()
xhr.upload.onprogress = (e) => e.lengthComputable && onProgress(e.loaded / e.total)
xhr.onload = () => console.log(xhr.status)
xhr.open('POST', '/upload')
xhr.send(form)
```

大檔案（影片、備份）要能續傳：用 `file.slice(start, end)` 切成每塊幾 MB 分批上傳，伺服器記錄收到哪幾塊，斷線後只補缺的；或直接用 tus 協定、雲端儲存的分段上傳 API。

## 用請求模擬即時通知：輪詢與長輪詢 {#1-11-2-4}

| | 輪詢（polling） | 長輪詢（long polling） |
| --- | --- | --- |
| 做法 | 每隔固定時間問一次 | 請求發出後，伺服器**有資料才回應**，用戶端收到後馬上再發下一個 |
| 延遲 | 最多一個間隔 | 幾乎即時 |
| 成本 | 沒資料時也一直發請求，間隔短就浪費、長就不即時 | 每則訊息都要一次完整的 HTTP 請求與回應；訊息很頻繁時比輪詢還貴 |

現在只在環境不允許長連線（某些代理伺服器、舊系統）時用來備援；伺服器要主動推送用 [SSE](./1-11-3.md) 或 [WebSocket](./1-11-4.md)。

## 效能注意事項 {#1-11-2-5}

- 每個請求都會帶上 Cookie 和標頭；很小又很頻繁的請求，標頭可能比內容還大。HTTP/2 會壓縮標頭，但請求數本身仍有成本。
- 能合併的請求就合併（批次 API），彼此無關的請求用 `Promise.all` 並行。
- 跨網域、非簡單請求會多一次 CORS 預檢（`OPTIONS`）；伺服器回 `Access-Control-Max-Age` 讓瀏覽器快取預檢結果。
- 使用者離開頁面時要送出的資料（統計、草稿），用 `navigator.sendBeacon` 或 `fetch(url, { keepalive: true })`，一般請求可能被取消。
