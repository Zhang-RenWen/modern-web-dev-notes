## Workflow vs Agent {#1-22-9-1}

> **確定性的事情交給程式與 Workflow；不確定性的事情才花 Token 交給 LLM；需要動態規劃與工具選擇時才升級成 Agent。**

- 固定 API、排程、Webhook、ETL、通知、格式轉換、CRUD → Code / Workflow（n8n、Temporal）。
- 理解自然語言、非結構化資料、意圖判斷、動態選工具、未知步驟規劃 → LLM / Agent。
- **Workflow 負責 orchestration，Agent 負責 intelligence**：例如收到 Email → Workflow 判斷是否需要 AI → 需要才交給 LLM 分類摘要 → 回到 Workflow 寫 DB / 通知。比「全部丟給 Agent」更好控成本、延遲、除錯。
- 工具會換，長壽的概念是：Orchestration、Event-driven、Idempotency、Retry、Queue、State、Observability、Human-in-the-loop、LLM Routing、Cost Control。

## RAG 演進 {#1-22-9-2}

- **RAG**：先查資料再讓 LLM 根據查到的內容回答。實務版要加 BM25 / Hybrid Search、Reranker、Metadata Filtering、Query Rewriting、Citation、Evaluation。
- **Agentic RAG**：Agent 決定要不要查、查哪裡、查幾次、用什麼工具（Memory、Planning、Tools、ReAct）。
- **Multi-Agent RAG**：多個專職 Agent + Aggregator。
- 判斷原則：**Simple RAG 能解就不要 Agentic；單 Agent 能解就不要 Multi-Agent；Workflow 能解就不要 Agent**（每升一級都多 latency、token、除錯難度與評估複雜度）。
- Memory 是危險的一層：隱私、權限、錯誤記憶、prompt injection、長期治理。MCP / Tool calling 要有權限控制、sandbox、allowlist、audit log、人工核准、密鑰保護。
- Production 必備：eval dataset、regression test、tracing、成本與延遲監控、prompt 版本控管、存取控制、資料外洩防護。
