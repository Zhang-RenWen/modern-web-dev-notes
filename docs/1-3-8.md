## LazyMan 題目 {#1-3-8-1}

```js
LazyMan('Hank').sleep(10).eat('dinner')
// Hi! This is Hank!
// （等 10 秒）Wake up after 10
// Eat dinner~

LazyMan('Hank').sleepFirst(5).eat('supper')
// （等 5 秒）Wake up after 5
// Hi! This is Hank!
// Eat supper~
```

要看出三件事：

1. **鏈式呼叫**：每個方法 `return this`。
2. **呼叫時不能馬上執行**，因為 `sleepFirst` 寫在後面卻要最先執行。所以每次呼叫只是把任務放進佇列，等整條鏈呼叫完才開始跑。
3. **任務一個接一個**：每個任務做完再呼叫 `next()` 取下一個，`sleep` 就是「過幾秒才呼叫 `next()`」。

## 解答 {#1-3-8-2}

```js
class LazyManImpl {
  #tasks = []

  constructor(name) {
    this.#tasks.push(() => {
      console.log(`Hi! This is ${name}!`)
      this.#next()
    })
    setTimeout(() => this.#next(), 0) // 等同步的鏈式呼叫全部登記完才開始
  }

  #next() {
    this.#tasks.shift()?.()
  }

  #sleepTask(sec, first) {
    const task = () =>
      setTimeout(() => {
        console.log(`Wake up after ${sec}`)
        this.#next()
      }, sec * 1000)
    first ? this.#tasks.unshift(task) : this.#tasks.push(task) // sleepFirst 插到最前面
    return this
  }

  sleep(sec) { return this.#sleepTask(sec, false) }
  sleepFirst(sec) { return this.#sleepTask(sec, true) }
  eat(food) {
    this.#tasks.push(() => {
      console.log(`Eat ${food}~`)
      this.#next()
    })
    return this
  }
}
const LazyMan = (name) => new LazyManImpl(name)
```

考點：用佇列延後執行、`setTimeout(…, 0)` 讓同步的鏈式呼叫先跑完、`unshift` 處理插隊、私有方法封裝內部細節。

## 中介軟體：同一個 next 思路 {#1-3-8-3}

LazyMan 的「做完自己的事再呼叫 `next()`」就是 Express、Koa、Redux middleware 的核心。差別在於 `next()` 之後還能不能做事。

**Express／connect：線性**

```js
function createApp() {
  const stack = []
  const app = (req, res) => {
    let i = 0
    const next = (err) => {
      const fn = stack[i++]
      if (!fn) return res.end(err ? 'Error' : 'Not Found')
      try {
        fn(req, res, next) // 交給中介軟體，由它決定要不要呼叫 next
      } catch (e) {
        next(e)
      }
    }
    next()
  }
  app.use = (fn) => stack.push(fn)
  return app
}
```

真正的 connect 還會比對路徑前綴（`app.use('/api', fn)`），以及依參數個數區分錯誤處理中介軟體（`(err, req, res, next)` 四個參數）。

**Koa：洋蔥模型**

`next()` 回傳 Promise，`await next()` 之後的程式會在「後面所有中介軟體都做完」才執行，所以可以在前後各做一件事（例如計時、統一錯誤處理）：

```js
app.use(async (ctx, next) => {
  const start = Date.now()
  await next()                                  // 往內層走
  ctx.set('X-Response-Time', `${Date.now() - start}ms`) // 內層都做完才回到這裡
})
```

`koa-compose` 的核心只有十幾行：

```js
function compose(middlewares) {
  return (ctx) => {
    let last = -1
    const dispatch = (i) => {
      if (i <= last) return Promise.reject(new Error('next() called multiple times'))
      last = i
      const fn = middlewares[i]
      if (!fn) return Promise.resolve()
      try {
        return Promise.resolve(fn(ctx, () => dispatch(i + 1)))
      } catch (e) {
        return Promise.reject(e)
      }
    }
    return dispatch(0)
  }
}
```

| | Express | Koa | Redux middleware |
| --- | --- | --- | --- |
| `next` 回傳 | 沒有回傳值 | Promise | 下一層的 `dispatch` 結果 |
| `next()` 之後的程式 | 會執行，但不保證在內層完成之後 | 一定在內層完成之後（洋蔥） | 在 reducer 處理完之後 |
| 錯誤處理 | 四參數中介軟體 | 最外層 `try { await next() } catch` | 自己包 |

**co 函式庫**：async/await 出現前，用 Generator 的 `yield` 暫停、由 co 自動呼叫 `next()` 推進，Koa 1 就是這樣寫的。它的原理是「遞迴地把 `yield` 出來的 Promise 接上 `then`，完成後把結果傳回 `gen.next(result)`」，async/await 等於把這件事做進語言裡，現在不需要它了。
