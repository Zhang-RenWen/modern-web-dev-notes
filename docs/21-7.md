### Q1. Angular 的架構由哪些部分組成？ <Badge type="tip" text="基礎" /> {#21-7-1}

::: details 標準答案與過程
- **Component**：模板 + 類別 + 樣式。Angular 14 起支援 standalone component，17 起新專案預設 standalone，不再需要 `NgModule`。
- **Service + DI**：商業邏輯與資料存取放 Service，透過依賴注入取得（`inject()` 或建構子注入）。
- **Router**：路由、懶載入、Guard、Resolver。
- **Pipe**：模板中的格式轉換（`date`、`currency`、`async`）。
- **Directive**：屬性型（改變元素行為）與結構型（`*ngIf`、`*ngFor`；17 起有內建控制流 `@if`、`@for`）。
- **RxJS**：HttpClient、Router 事件、表單值變化都是 Observable。

和 Vue／React 最大差別：Angular 是「完整框架」，路由、表單、HTTP、DI、測試都內建，團隊寫法比較一致，適合大型企業專案。
:::

### Q2. 依賴注入（DI）是什麼？有什麼好處？ <Badge type="tip" text="高頻" /> {#21-7-2}

::: details 標準答案與過程
DI 是「物件不自己建立依賴，而是由外部（Injector）提供」。

```ts
@Injectable({ providedIn: 'root' })        // 全站單例
export class PolicyService {
  private http = inject(HttpClient)
  getPolicy(id: string) { return this.http.get<Policy>(`/api/policies/${id}`) }
}

@Component({ selector: 'app-policy', standalone: true, template: `...` })
export class PolicyComponent {
  private policyService = inject(PolicyService)
}
```

好處：
1. **可測試**：測試時替換成假的 Service。
2. **解耦**：元件依賴抽象（Token），實作可替換。
3. **生命週期與作用域**：`providedIn: 'root'` 是全站單例；放在元件 `providers` 則每個元件實例一份。

Injector 是階層式的：元件 → 父元件 → 模組／環境 → root，找不到就往上找。
:::

### Q3. Angular 的變更偵測怎麼運作？OnPush 和 Signals 解決什麼？ <Badge type="tip" text="高頻" /> {#21-7-3}

::: details 標準答案與過程
**預設策略（Default）**：Zone.js 攔截所有非同步事件（點擊、HTTP、setTimeout），事件結束後從根元件往下檢查**整棵樹**的綁定是否改變。簡單但元件多時成本高。

**OnPush**：只有以下情況才檢查這個元件：
1. `@Input` 參考改變（所以要不可變更新）。
2. 元件內觸發事件。
3. 模板中的 `async` pipe 收到新值。
4. 手動 `markForCheck()`。

**Signals**（Angular 16+）：`signal()`、`computed()`、`effect()`，細粒度追蹤讀取了哪些 signal，只更新相依的部分，可以不依賴 Zone.js（zoneless）。

```ts
count = signal(0)
double = computed(() => this.count() * 2)
increment() { this.count.update(v => v + 1) }
```

實務：新元件用 OnPush + Signals；大型表格或高頻更新畫面一定要 OnPush。
:::

### Q4. Observable 和 Promise 差在哪？`switchMap`、`mergeMap`、`concatMap`、`exhaustMap` 怎麼選？ <Badge type="tip" text="高頻" /> {#21-7-4}

::: details 標準答案與過程
| | Promise | Observable |
| --- | --- | --- |
| 值的數量 | 一個 | 零到多個（串流） |
| 執行時機 | 建立就執行（eager） | 訂閱才執行（lazy） |
| 取消 | 不能（要靠 AbortController） | `unsubscribe()` |
| 運算子 | `then` | map、filter、debounceTime、retry… |

高階映射運算子差在「新值來時，舊的內層請求怎麼處理」：

| 運算子 | 行為 | 場景 |
| --- | --- | --- |
| `switchMap` | 取消舊的，只要最新的 | 搜尋自動完成、切換分頁 |
| `mergeMap` | 全部並行 | 彼此獨立的批次請求 |
| `concatMap` | 排隊依序執行 | 必須依順序的寫入 |
| `exhaustMap` | 進行中時忽略新的 | 防止重複送出、登入按鈕 |

```ts
this.results$ = this.searchControl.valueChanges.pipe(
  debounceTime(300),
  distinctUntilChanged(),
  filter(q => q.length >= 2),
  switchMap(q => this.api.search(q).pipe(catchError(() => of([])))),
)
```
:::

### Q5. 怎麼避免 RxJS 訂閱造成記憶體洩漏？ <Badge type="tip" text="高頻" /> {#21-7-5}

::: details 標準答案與過程
HttpClient 的請求完成後會自動 complete，但 `valueChanges`、Router events、`interval`、自建的 Subject 不會。

做法（由推薦到不推薦）：

1. 模板用 `async` pipe，元件銷毀時自動取消。
2. `toSignal(obs$)`，跟著注入上下文自動清理。
3. `takeUntilDestroyed()`（Angular 16+）。
4. 手動在 `ngOnDestroy` 中 `unsubscribe`。

```ts
constructor() {
  this.route.paramMap
    .pipe(takeUntilDestroyed())
    .subscribe(p => this.load(p.get('id')!))
}
```
:::

### Q6. Vue 開發者怎麼快速對應 Angular 的概念？ <Badge type="tip" text="基礎" /> {#21-7-6}

::: details 標準答案與過程
| Vue | Angular |
| --- | --- |
| `props` / `emit` | `@Input()` / `@Output()` + `EventEmitter`；新版 `input()` / `output()` / `model()` |
| `v-if` / `v-for` | `@if` / `@for`（舊：`*ngIf` / `*ngFor`） |
| `v-model` | `[(ngModel)]` 或 Reactive Forms |
| `ref` / `computed` / `watchEffect` | `signal` / `computed` / `effect` |
| Composable | Service + DI |
| Pinia | NgRx Store 或 Signal Store、Service + Signal |
| `provide` / `inject` | DI 階層 |
| Vue Router 導航守衛 | Route Guards（`canActivate`、`canMatch`） |
| `onMounted` / `onUnmounted` | `ngOnInit` / `ngOnDestroy` |
| Teleport | CDK Portal / Overlay |

面試回答方式：「我主要用 Vue，但核心觀念相通：元件通訊、響應式、DI、路由守衛、狀態管理。Angular 我會從 Signals 與 standalone component 切入，第一週就能讀懂既有專案。」再用一個小 Demo 證明。
:::

### Q7. NgRx 的資料流是什麼？什麼時候需要它？ <Badge type="warning" text="進階" /> {#21-7-7}

::: details 標準答案與過程
NgRx 是 Redux 模式：

```txt
Component ──dispatch(Action)──▶ Reducer（純函式產生新 State）──▶ Store
    ▲                                  │
    └──── Selector（記憶化查詢）◀──────┘
Action ──▶ Effect（處理 API 等副作用）──▶ 成功／失敗 Action
```

- **Action**：描述發生什麼事（`[Policy Page] Load`）。
- **Reducer**：純函式，不可變更新。
- **Selector**：從 State 取值，有記憶化。
- **Effect**：監聽 Action 處理副作用，再發出新 Action。

何時需要：多個頁面共享且頻繁變動的狀態、需要時光回溯除錯、團隊大要嚴格規範資料流。小功能用 Service + Signal 或 `@ngrx/signals` 的 Signal Store 即可，避免樣板程式碼過多。
:::
