## OOP 在解決什麼問題 {#1-25-4-1}

OOP 是把**資料和操作資料的行為**組織成物件，用四個概念管理複雜度：

| 概念 | 一句話 | 解決的問題 |
| --- | --- | --- |
| 封裝 | 狀態只能透過方法改 | 任何地方都能改資料 → 規則散落、難以追查 |
| 抽象 | 依賴「能做什麼」而不是「怎麼做」 | 呼叫端被實作細節綁住 |
| 繼承 | 子類別重用父類別 | 重複的程式碼（但容易濫用） |
| 多型 | 同一個介面，不同實作 | 一長串 `if (type === ...)` |

## class 基本語法 {#1-25-4-2}

```ts
class Account {
  // 屬性
  readonly id: string                // 建立後不能改（Java: final）
  private balance = 0                // 只有類別內部能存取（Java: private）
  protected owner: string            // 類別內部與子類別能存取（Java: protected）
  static count = 0                   // 屬於類別本身，不屬於實例（Java: static）

  constructor(id: string, owner: string) {
    this.id = id
    this.owner = owner
    Account.count++
  }

  // 方法：改狀態只能透過這裡，規則集中
  deposit(amount: number): void {
    if (amount <= 0) throw new Error('金額必須大於 0')
    this.balance += amount
  }

  // getter：唯讀的計算屬性
  get currentBalance(): number {
    return this.balance
  }
}

const acc = new Account('A001', 'Amy')
acc.deposit(100)
acc.currentBalance   // 100
acc.balance          // ❌ 編譯錯誤：private
```

**建構子參數屬性**（TS 獨有的縮寫，NestJS、Angular 到處都是）：

```ts
class UserService {
  constructor(private readonly repo: UserRepository) {}
  // 等同於宣告 private readonly repo 屬性，並在建構子裡賦值
}
```

**`private` 與 `#` 的差別**：TS 的 `private` 只在編譯期檢查，編譯後的 JS 仍然可以存取；`#balance` 是 JavaScript 原生私有欄位，執行期也真的存取不到（見 [16-6 Private class features](./16-6.md)）。

## 封裝：不要讓外部直接改狀態 {#1-25-4-3}

```ts
// ❌ 貧血模型：資料是公開的，規則散落在各處的 service 或元件裡
order.status = 'paid'
order.paidAt = new Date()

// ✅ 狀態變化透過有名字的方法，規則（能不能付款）跟資料放在一起
class Order {
  private status: 'pending' | 'paid' | 'cancelled' = 'pending'
  private paidAt?: Date

  pay(now = new Date()) {
    if (this.status !== 'pending') throw new Error(`訂單狀態為 ${this.status}，不能付款`)
    this.status = 'paid'
    this.paidAt = now
  }

  cancel() {
    if (this.status === 'paid') throw new Error('已付款的訂單要走退款流程')
    this.status = 'cancelled'
  }
}
```

## 抽象：interface 與 abstract class {#1-25-4-4}

```ts
// interface：只定義「能做什麼」，沒有實作
interface PaymentGateway {
  charge(amount: number, currency: string): Promise<{ transactionId: string }>
}

// abstract class：可以放共用的實作，但不能直接 new
abstract class BaseNotifier {
  async notify(userId: string, message: string) {
    const target = await this.resolveTarget(userId)     // 共用流程
    await this.send(target, message)                    // 交給子類別實作
  }
  protected abstract resolveTarget(userId: string): Promise<string>
  protected abstract send(target: string, message: string): Promise<void>
}
```

| | interface | abstract class |
| --- | --- | --- |
| 實作 | 沒有 | 可以有部分實作 |
| 多重 | 一個 class 可以 `implements` 多個 | 只能 `extends` 一個 |
| 執行期 | 不存在（型別擦除） | 存在，可以用 `instanceof` |
| 用途 | 定義契約、依賴的抽象 | 多個子類別共用同一套流程（Template Method） |

## 繼承與多型 {#1-25-4-5}

```ts
class EmailNotifier extends BaseNotifier {
  protected async resolveTarget(userId: string) { return `${userId}@example.com` }
  protected async send(to: string, msg: string) { /* 寄信 */ }
}

class SmsNotifier extends BaseNotifier {
  protected async resolveTarget(userId: string) { return '0912000000' }
  protected async send(to: string, msg: string) { /* 發簡訊 */ }
}

// 多型：呼叫端只認得 BaseNotifier，不需要 if/else 判斷是哪一種
async function notifyAll(notifiers: BaseNotifier[], userId: string, msg: string) {
  await Promise.all(notifiers.map((n) => n.notify(userId, msg)))
}
```

- `extends` 繼承、`super(...)` 呼叫父類別建構子、`super.method()` 呼叫父類別方法。
- 加上 `override` 關鍵字（搭配 `noImplicitOverride`），父類別方法改名時編譯器會提醒你（Java: `@Override`）。

**繼承只用在明確的「是一種」（is-a）關係**，而且層數保持很淺。只是想重用程式碼時，優先用組合（見 [1-25-5 組合優於繼承](./1-25-5.md#1-25-5-2)）。

## 泛型類別 {#1-25-4-6}

```ts
class Repository<T extends { id: string }> {
  private items = new Map<string, T>()

  save(item: T): T {
    this.items.set(item.id, item)
    return item
  }

  findById(id: string): T | undefined {
    return this.items.get(id)
  }
}

const users = new Repository<User>()     // Java: new Repository<User>()
```

## 何時用 class，何時用函式與物件 {#1-25-4-7}

TS／JS 不是只能 OOP，前端很多地方用函式加普通物件更簡單：

| 適合 class | 適合函式 + 物件 |
| --- | --- |
| 有內部狀態，且狀態變化有規則（帳戶、訂單、購物車） | 純資料（API 回應、設定） |
| 需要多型、依賴注入（Angular、NestJS 的 Service） | 純計算、轉換（格式化、驗證） |
| 要管理資源生命週期（連線、計時器、WebSocket） | React Hooks、Vue Composable |

Vue 與 React 本身偏向函式式寫法；Angular、NestJS、Java 生態則以 class 為主。看懂兩種，換專案時才不會卡住。
