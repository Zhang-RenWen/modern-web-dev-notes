# 1-7-5 Container：Docker 與 Kubernetes {#1-7-5}

::: info 新增（2026-11）
整理自 Notion「開發工具與 DevOps」第 8 節。
:::

- **為什麼值得學**：容器沒有增加複雜度，而是把以前被跳過的工作（精準描述環境依賴）從「可做可不做」變成「必須用程式碼寫清楚」。結果是告別 *It works on my machine*、告別凌晨手動 SSH 逐台貼指令的發布。
- **演進**：chroot（1979，隔離根目錄）→ LXC（2008，OS 層虛擬化）→ Docker（2013，對程式員友善的單一程式容器）→ Kubernetes（2014，以程式化方式管理容器叢集）。
- **Docker 概念**：Image（模板）/ Container（實例）/ Dockerfile（說明書）/ Volume（持久化）/ Network（Bridge、Host、Overlay、Service Name DNS）/ Registry。常用：build、run、ps、logs、exec、compose up/down。Port mapping 要懂 Host Port vs Container Port，不要只會 `-p 8080:3000`。
- **K8s 最低限度**：Control Plane（API Server、Scheduler、etcd）、Worker（Kubelet）、Pod、Deployment、Service（ClusterIP / NodePort / LoadBalancer）、Ingress、ConfigMap、Secret、PV。一個 App 通常 = Deployment + Service + Ingress。
- **K8s 倒逼的好設計**：設定與密碼從程式碼抽離（ConfigMap / Secret）；程式保持 Stateless、資料 Stateful 分開管理（與 functional programming 理念相通）。
- Service Mesh、Operator、Sidecar 等對 99% 專案用不上；從最基本的概念、最簡單的環境邊用邊學。
- Container 與 Host Kernel 的關係見 [1-16-3](./1-16-3.md)。

## Docker 網路 {#1-7-5-1}

::: info 新增（2026-11）
本節以下整理自 Notion「Node.js 了不起」子頁〈Docker〉，已套用原頁 AI 校正（Node.js 版本、容器不等於 VM 等）。
:::

容器解決的老問題：同一台主機上 port 衝突、環境變數互相干擾、不同專案需要不同版本的 Node.js；每部署一台機器就要重裝一次依賴。虛擬機也能隔離，但建置麻煩、吃資源、啟動慢。

校正：容器是**作業系統層級的虛擬化**，共用主機的 Kernel，所以比 VM 輕量，但隔離性也比較弱，高安全需求的多租戶場景要額外評估。

安裝後預設有三個網路（`docker network ls`）：

| 網路 | 行為 | 適合 |
| --- | --- | --- |
| `bridge`（預設） | 容器拿到子網 IP（例如 172.17.0.x），用 `-p 主機:容器` 映射 port 對外 | 單一容器 |
| `host` | 直接使用主機網路，不需要 `-p`，但失去網路隔離 | 代理伺服器等需要直接存取主機網路的容器 |
| `none` | 沒有網路 | 完全隔離的批次工作 |
| **自訂 bridge** | 同一個網路的容器可以**用容器名稱互相連線**（內建 DNS） | 前端 + 後端 + 資料庫這類多容器應用 |

舊的 `--link` 會讓容器互相依賴（被連的停了，連它的也停），已不建議，改用自訂網路或 Docker Compose（Compose 會自動建立專案網路）。

```bash
docker network create app-net
docker run -d --name db --network app-net postgres:17
docker run -d --name api --network app-net -e DB_HOST=db -p 3000:3000 my-api
docker network inspect app-net     # 看網關、連到哪些容器
docker network rm app-net / docker network prune
```

## Docker 儲存 {#1-7-5-2}

資料直接寫在容器的可寫層有三個問題：容器刪掉資料就沒了、主機與其他容器拿不到、寫入效能較差。三種掛載方式：

| 方式 | 存在哪裡 | 適合 |
| --- | --- | --- |
| **Volume**（官方推薦） | Docker 管理的主機目錄 | 資料庫資料、多容器共享資料、備份與遷移 |
| **Bind mount** | 主機上任意指定的路徑 | 開發時掛原始碼、設定檔 |
| **tmpfs** | 只在記憶體 | 不想落地的敏感暫存資料、需要高速讀寫的暫存 |

```bash
docker volume create pgdata
docker run -d -v pgdata:/var/lib/postgresql/data postgres:17            # volume
docker run -d --mount type=bind,source="$PWD",target=/app,readonly node:24  # bind mount
docker volume ls / inspect / rm / prune
```

Volume 不會隨容器刪除而消失，要手動清理。Bind mount 掛到容器內已有檔案的目錄時，會蓋掉容器裡原本的內容。

## Dockerfile 實務 {#1-7-5-3}

- **用 Dockerfile 建映像，不要用 `docker commit`**：Dockerfile 可以版本控制、可重現、能利用快取；commit 出來的映像是看不出做過什麼的黑箱。
- **指定基礎映像版本**：不要用 `latest`，選目前支援中的 LTS（例如 `node:24`）。
- **善用分層快取**：每一行指令是一層，某層變了，後面全部重建。所以把不常變的放前面：先複製 `package*.json` 安裝依賴，再複製原始碼，改程式碼時就不用重裝依賴。
- **`.dockerignore`**：排除 `node_modules`、`.git`、`.env`，避免把本機的依賴蓋掉容器內安裝的版本，也避免把密鑰打包進去。
- 新版 Node.js 映像不一定內建 Yarn，用 npm，或用 corepack 啟用 pnpm／Yarn（Node.js 25 起 corepack 不再內建，要另外安裝）。

```dockerfile
FROM node:24-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
EXPOSE 8080
USER node                 # 不要用 root 執行
CMD ["node", "app.js"]
```

## 用容器當開發環境 {#1-7-5-4}

好處是每個人的開發環境一致，也和部署環境一致（某些原生模組在特定作業系統上會裝不起來）。

```bash
docker run -it --name dev -v "$PWD":/app -w /app -p 8080:8080 node:24 bash
# 進入容器後
npm install
npm run dev
```

- `-it`：互動模式 + 虛擬終端；`-d` 背景執行；`-v` 掛載原始碼；`-w` 工作目錄；`-p` 映射 port。
- 之後用 `docker exec -it dev bash` 回到容器裡操作。
- Windows 主機掛載的目錄可能收不到檔案變更事件，熱重載要開輪詢（nodemon `-L`、Vite `server.watch.usePolling`）。
- 多個服務一起開發用 Docker Compose；VS Code 的 Dev Containers 可以把這套設定寫進專案。

延伸：容器與 CI/CD 整合（在 pipeline 中建映像、推到 registry）、rootless 模式與映像弱點掃描，見 [1-7-1](./1-7-1.md)、[1-7-6](./1-7-6.md)。
