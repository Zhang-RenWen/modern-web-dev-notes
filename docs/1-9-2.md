> 一句話：**打包工具從入口出發，沿著 `import` 找出所有依賴，轉譯成瀏覽器看得懂的格式，再依規則切成幾個檔案輸出。**

## 打包產物長什麼樣 {#1-9-2-1}

webpack 把每個模組包成一個函式，放進一張表，再附上一個迷你的模組載入器：

```js
(() => {
  const modules = {
    './src/index.js': (module, exports, require) => {
      const { sayHello } = require('./src/hello.js')
      console.log(sayHello('Ren'))
    },
    './src/hello.js': (module, exports) => {
      exports.sayHello = (name) => `hello ${name}`
    },
  }
  const cache = {}
  function require(id) {
    if (cache[id]) return cache[id].exports // 每個模組只執行一次
    const module = (cache[id] = { exports: {} })
    modules[id](module, module.exports, require)
    return module.exports
  }
  require('./src/index.js') // 從入口開始執行
})()
```

**動態 `import()`** 會被切成獨立的 chunk 檔案：執行到時才用 `<script>` 載入，載完把新模組加進模組表，再 resolve Promise。路由層級的程式碼分割就是靠這個。

Rollup 則是把所有模組「攤平」到同一個作用域（scope hoisting），產物幾乎就是原始碼串在一起，沒有載入器的額外程式碼，所以特別適合打包函式庫。webpack 的 `optimization.concatenateModules` 也會做類似的事。

## 工作流程 {#1-9-2-2}

1. 讀設定檔，初始化所有 plugin（plugin 在這時註冊要監聽的建置事件）。
2. 從 `entry` 開始，對每個檔案：用符合的 **loader** 轉成 JavaScript → 解析成 **AST** → 找出 `import`／`require` → 遞迴處理依賴，建立依賴圖。
3. 依入口和動態 `import()` 把模組分組成 **chunk**，做 tree shaking、壓縮、加上 hash。
4. 輸出檔案。

整個過程中，webpack 在每個階段發出事件（hook），plugin 就是在這些時間點介入。

**AST（抽象語法樹）**：把原始碼解析成樹狀結構，例如 `var ast = 'demo'` 會變成 `Program → VariableDeclaration → VariableDeclarator（id: ast, init: 'demo'）`。打包工具靠它找出依賴，Babel 靠它轉換語法，ESLint 靠它檢查規則。可以在 [AST Explorer](https://astexplorer.net/) 貼程式碼看結果。

**compiler 與 compilation**：`compiler` 代表整個 webpack 執行過程，只有一個；`compilation` 代表一次建置，開發模式每次存檔重新編譯就會建立新的 `compilation`，裡面有這次的模組、chunk 和產出檔案。

## loader：轉換單一檔案 {#1-9-2-3}

loader 就是一個函式：輸入檔案內容，輸出轉換後的內容。多個 loader 由**後往前**執行（陣列最後一個先執行）：

```js
module.exports = {
  module: {
    rules: [
      // less-loader（Less → CSS）→ css-loader（處理 @import、url）→ style-loader（插入 <style>）
      { test: /\.less$/, use: ['style-loader', 'css-loader', 'less-loader'] },
    ],
  },
}
```

```js
// 自己寫一個：移除程式碼裡的 console.log
module.exports = function (source) {
  const { keep = false } = this.getOptions() // 讀取 loader 選項
  return keep ? source : source.replace(/console\.log\(.*?\);?/g, '')
}
```

實際的 loader 不會用正規表達式改程式碼（會誤刪字串裡的內容），而是解析成 AST 再修改。

## plugin：介入整個建置過程 {#1-9-2-4}

plugin 是有 `apply(compiler)` 方法的物件，在 hook 上註冊 callback：

```js
class FileListPlugin {
  apply(compiler) {
    // processAssets：產出檔案準備好、還沒寫入磁碟之前
    compiler.hooks.thisCompilation.tap('FileListPlugin', (compilation) => {
      compilation.hooks.processAssets.tap(
        { name: 'FileListPlugin', stage: compilation.constructor.PROCESS_ASSETS_STAGE_SUMMARIZE },
        (assets) => {
          const list = Object.keys(assets).map((name) => `- ${name}`).join('\n')
          compilation.emitAsset('filelist.md', new compiler.webpack.sources.RawSource(list))
        },
      )
    })
  }
}
```

| | loader | plugin |
| --- | --- | --- |
| 作用範圍 | 單一檔案 | 整個建置流程 |
| 做什麼 | 把非 JS 檔案或新語法轉成 JS | 產生 HTML、抽出 CSS、注入環境變數（`DefinePlugin`）、分析檔案大小 |

webpack 的 hook 由 tapable 函式庫提供，有同步／非同步、串列／並行、可提早中斷（Bail）、傳遞結果（Waterfall）等多種類型。

## 2026 年的建置工具 {#1-9-2-5}

| 工具 | 定位 |
| --- | --- |
| **Vite** | 新專案的預設：開發時不打包，直接讓瀏覽器載入 ES Module，啟動和熱更新都很快；正式建置用 Rollup，正在換成 Rust 寫的 Rolldown |
| webpack | 生態最完整、設定最彈性；大型舊專案仍大量使用 |
| Rspack | 用 Rust 重寫、和 webpack 設定及 plugin 相容，舊專案提速的升級路線 |
| Turbopack | Next.js 內建（Next.js 16 起預設） |
| Rollup | 打包函式庫，輸出乾淨的 ES Module |
| esbuild | 極快的轉譯與打包，常被其他工具當作底層 |

選擇原則：新專案用 Vite（或框架內建的工具）；webpack 專案嫌慢但不想改設定就試 Rspack；寫函式庫用 Rollup、tsup、或 Vite 的 library mode。Vite 的實戰設定見 [1-9-5](./1-9-5.md)。
