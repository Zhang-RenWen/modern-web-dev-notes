# 1-3-6 實作非同步流程 {#1-3-6}

::: info 改寫（2026-11）
原內容整理自 2019 年前的書籍，已精簡並更新：同一段 `walk` 動畫程式原本重複貼了四次，改成只比較串接寫法；補上現在更適合的 Web Animations API；修正「限制並行數」範例的錯誤；巨任務清單拿掉不屬於任務的 `requestAnimationFrame` 與 UI 繪製；補上 Chrome 取消 1ms 最小延遲的變化。

## 同一件事，四種串接寫法 {#1-3-6-1}

題目：元素先向左移 20px、再向上 50px、再向左 30px，一段結束才開始下一段。

把「移動一段」包成函式後，差別只在怎麼串：

```js
// 1. 回呼：每多一段就多一層巢狀（callback hell）
walkCb('left', 20, () => walkCb('top', 50, () => walkCb('left', 30)))

// 2. Promise：walk 回傳 Promise，用 then 串成一條鏈
walk('left', 20).then(() => walk('top', 50)).then(() => walk('left', 30))

// 3. Generator：yield 暫停，但要自己（或 co 函式庫）反覆呼叫 next()
function* task() { yield walk('left', 20); yield walk('top', 50); yield walk('left', 30) }

// 4. async/await：Generator + 自動執行器的語法糖，讀起來像同步程式
async function run() {
  await walk('left', 20)
  await walk('top', 50)
  await walk('left', 30)
}
```

`walk` 本身現在不必用 `setTimeout` 每 20ms 移 1px，直接用瀏覽器的 **Web Animations API**，`finished` 就是一個 Promise，還會用合成層跑、比較順：

```js
const walk = (el, x, y) =>
  el.animate([{ translate: '0 0' }, { translate: `${x}px ${y}px` }], { duration: 400, fill: 'forwards', composite: 'add' }).finished

await walk(man, -20, 0)
await walk(man, 0, -50)
await walk(man, -30, 0)
```

## 紅綠燈：無限循環的任務 {#1-3-6-2}

紅燈 3 秒、綠燈 1 秒、黃燈 2 秒，不斷輪流：

```js
const sleep = (ms) => new Promise((r) => setTimeout(r, ms))

async function trafficLight(signal) {
  while (!signal.aborted) {
    red();    await sleep(3000)
    green();  await sleep(1000)
    yellow(); await sleep(2000)
  }
}
const ctrl = new AbortController()
trafficLight(ctrl.signal) // 要停的時候 ctrl.abort()
```

用 `while` 迴圈比「最後再呼叫自己一次」清楚，也不會讓 Promise 鏈越接越長；記得留一個停止的方法。

## 預先載入圖片：依序、全部、限制並行數 {#1-3-6-3}

```js
const loadImg = (url) =>
  new Promise((resolve, reject) => {
    const img = new Image()
    img.onload = () => resolve(url)
    img.onerror = () => reject(new Error(`載入失敗：${url}`))
    img.src = url
  })
```

| 需求 | 寫法 |
| --- | --- |
| 一張接一張 | `for (const url of urls) await loadImg(url)` |
| 全部同時發出，任一失敗就算失敗 | `await Promise.all(urls.map(loadImg))` |
| 全部同時發出，各自成功失敗都要知道 | `await Promise.allSettled(urls.map(loadImg))` |
| **最多同時 3 個** | 下面的工作池 |

```js
async function loadWithLimit(urls, limit) {
  const results = []
  let next = 0
  async function worker() {
    while (next < urls.length) {
      const i = next++ // 單執行緒，這行不會有競爭問題
      results[i] = await loadImg(urls[i]).catch((e) => e)
    }
  }
  await Promise.all(Array.from({ length: Math.min(limit, urls.length) }, worker))
  return results // 順序和 urls 一致
}
```

思路：開 `limit` 個 worker，每個 worker 做完一張就去拿下一張，直到清單空了。比「用 `Promise.race` 等最快的那個再補一個」好寫，也不會算錯要移除哪一個。

## setTimeout 的細節 {#1-3-6-4}

- **延遲是「最少」等多久，不是「準時」**：主執行緒在忙（例如跑 200ms 的迴圈），時間到了也要等同步程式跑完才輪得到。在 callback 裡寫無窮迴圈，整個頁面就卡死。
- **最小延遲**：巢狀呼叫超過 5 層後，瀏覽器會把延遲拉到至少 4ms。Chrome 101（2022）取消了原本「`0` 會被當成 1ms」的規則，所以 `setTimeout(a, 1)` 和 `setTimeout(b, 0)` 誰先執行因瀏覽器而異，不要依賴。
- **背景分頁**：計時器最多每秒觸發一次，Chrome 對長時間隱藏的分頁還會再節流到每分鐘一次。要精準計時用 `performance.now()` 比對實際經過時間。
- **最大延遲**：超過 2³¹−1 毫秒（約 24.8 天）會溢位，變成立刻執行。

## 巨任務與微任務 {#1-3-6-5}

事件迴圈每一輪：**執行一個巨任務 → 清空所有微任務 → 有需要就渲染畫面**（`requestAnimationFrame` 在渲染前執行）→ 下一個巨任務。

| 巨任務（task） | 微任務（microtask） |
| --- | --- |
| `<script>` 本身、`setTimeout`、`setInterval`、使用者事件、`MessageChannel`／`postMessage`、網路回應 | `Promise` 的 `then`／`catch`／`finally`、`await` 之後的程式、`queueMicrotask`、`MutationObserver` |

Node.js 另外有 `process.nextTick`（比 Promise 微任務更早）和 `setImmediate`（瀏覽器沒有）。

```js
console.log('start')
setTimeout(() => console.log('timeout'), 0)
Promise.resolve().then(() => console.log('promise'))
console.log('end')
// start → end → promise → timeout
```

```js
console.log('start here')
new Promise((resolve) => {
  console.log('first promise constructor') // executor 是同步執行的
  resolve()
})
  .then(() => {
    console.log('first promise then')
    return new Promise((resolve) => {
      console.log('second promise')
      resolve()
    }).then(() => console.log('second promise then'))
  })
  .then(() => console.log('another first promise then')) // 要等上一個 then 回傳的 Promise 完成
console.log('end here')
// start here → first promise constructor → end here → first promise then
// → second promise → second promise then → another first promise then
```
