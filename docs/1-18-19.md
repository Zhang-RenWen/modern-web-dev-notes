# 1-18-19 SSH 與內網連線 {#1-18-19}

::: info 新增（2026-11）
整理自 Notion「計算機基礎」第 7 節。
:::

- **SSH vs HTTP**：HTTP 是 request/response 拿資料（80／443），像外送點餐；SSH 是加密的互動式指令通道（22），像拿鑰匙進廚房直接操作。遠端機器跑 sshd，你用 client 下 `ssh user@host`，驗證用密碼或金鑰。
- 用途：遠端管理伺服器、`scp`／`sftp` 傳檔、自動化部署（Ansible、CI）、跳板機連線。
- **協定不能硬切，但能隧道（tunnel）**：把 A 協定包在 B 協定裡，像貨物裝進貨櫃。

```bash
# 本地轉發：本機 8080 → 經 server → example.com:80
ssh -L 8080:example.com:80 user@server

# 反向轉發：內網機器主動連出去，外網伺服器的 2222 就對應內網機器的 22
ssh -R 2222:localhost:22 user@外網伺服器
```

- **什麼時候才需要隧道**：能直連就直接 SSH。需要繞的情境是防火牆只開 80／443、只能走 HTTP Proxy（SSH over HTTP CONNECT）、要把內部服務（DB、K8s API）安全給外部用而不想開 port、地區封鎖特定協定。
- **從外面連回純內網機器的四種方法**：Port Forwarding（路由器開 port，最容易被掃、最不安全）→ 反向 SSH tunnel → VPN（WireGuard、Tailscale、ZeroTier，放進同一虛擬網段）→ 跳板機 Bastion Host（企業／金融內網最常見）。同一區網內直接 `ssh user@192.168.x.x` 就好。
