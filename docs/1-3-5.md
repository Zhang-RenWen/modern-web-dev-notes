## 元素到文件頂部的距離 {#1-3-5-1}

`getBoundingClientRect()` 回傳的是**相對於視窗**的位置，加上目前的捲動距離就是相對於整份文件：

```js
function offset(el) {
  if (!el.getClientRects().length) return { top: 0, left: 0 } // display: none 或不在 DOM 裡
  const rect = el.getBoundingClientRect()
  return { top: rect.top + window.scrollY, left: rect.left + window.scrollX }
}
```

- 舊做法是沿著 `offsetParent` 一路累加 `offsetTop`，要自己處理捲動容器、`fixed` 元素，容易算錯。
- 只是想知道元素「有沒有進入畫面」（懶載入、曝光追蹤），不要在 `scroll` 事件裡算位置，改用 `IntersectionObserver`。

## reduce {#1-3-5-2}

```js
arr.reduce((acc, cur, index, array) => newAcc, initialValue)
```

- 有給 `initialValue`：從索引 0 開始，`acc` 的初始值是它。
- 沒給：拿第一個元素當初始值，從索引 1 開始；**空陣列又沒給初始值會丟 `TypeError`**，所以實務上一律給。

手寫 reduce 要注意這兩個邊界，還有跳過稀疏陣列的空位：

```js
Array.prototype.myReduce = function (fn, ...init) {
  const arr = this
  let i = 0
  let acc
  if (init.length) acc = init[0]
  else {
    while (i < arr.length && !(i in arr)) i++ // 跳過空位，找第一個有值的元素
    if (i >= arr.length) throw new TypeError('Reduce of empty array with no initial value')
    acc = arr[i++]
  }
  for (; i < arr.length; i++) if (i in arr) acc = fn(acc, arr[i], i, arr)
  return acc
}
```

reduce 常見用途：

```js
// 依序執行一串回傳 Promise 的函式（上一個的結果傳給下一個）
const runInSequence = (fns, init) => fns.reduce((p, fn) => p.then(fn), Promise.resolve(init))
// 現在用 for...of + await 更好讀：
async function runInSequence2(fns, init) {
  let value = init
  for (const fn of fns) value = await fn(value)
  return value
}

// 從物件挑出指定欄位（Koa 的 only 模組就是這樣寫）
const pick = (obj, keys) => keys.reduce((ret, k) => (k in obj ? { ...ret, [k]: obj[k] } : ret), {})
// 或：Object.fromEntries(keys.filter((k) => k in obj).map((k) => [k, obj[k]]))
```

並行執行（不在乎順序）用 `Promise.all`，見 [1-3-7](./1-3-7.md)。

## pipe 與 compose {#1-3-5-3}

兩者都是把多個函式串成一個，差別只在方向：

```js
const pipe = (...fns) => (x) => fns.reduce((acc, fn) => fn(acc), x)        // 由左到右
const compose = (...fns) => (x) => fns.reduceRight((acc, fn) => fn(acc), x) // 由右到左

compose(f, g, h)(x) // 等同 f(g(h(x)))
pipe(h, g, f)(x)    // 同上
```

Redux 的版本讓最右邊的函式可以接收多個參數：

```js
function compose(...funcs) {
  if (funcs.length === 0) return (arg) => arg
  return funcs.reduce((a, b) => (...args) => a(b(...args)))
}
```

Redux 的 `applyMiddleware` 用它把多個 middleware 串成一條鏈；Koa 的 middleware 則是另一種「洋蔥模型」，見 [1-3-8](./1-3-8.md)。

## 手寫 call 與 apply {#1-3-5-4}

原理是**隱式綁定**：把函式暫時掛到目標物件上，用 `obj.fn()` 呼叫，`this` 就是 `obj`。

```js
Function.prototype.myCall = function (ctx, ...args) {
  ctx = ctx == null ? globalThis : Object(ctx) // null／undefined 用全域；原始值包成物件
  const key = Symbol('fn')                     // 用 Symbol 避免覆蓋物件原有的屬性
  ctx[key] = this
  try {
    return ctx[key](...args)
  } finally {
    delete ctx[key]
  }
}
Function.prototype.myApply = function (ctx, args = []) {
  return this.myCall(ctx, ...args)
}
```

面試常追問的點：

- 為什麼用 `Symbol`：如果用固定字串當 key，目標物件剛好有同名屬性就會被覆蓋又刪掉。
- 嚴格模式下原生 `call(null)` 的 `this` 是 `null`，不會換成全域物件；上面的寫法模擬的是非嚴格模式。
- `bind` 多了兩件事：預填參數、被 `new` 呼叫時忽略綁定的 `this`。
