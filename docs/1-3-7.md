## 把回呼 API 包成 Promise {#1-3-7-1}

回呼風格的 API 一層套一層就是「回呼地獄」。包成 Promise 後可以用 `then` 串、用 `await` 寫：

```js
// 通用的 promisify：適用 { success, fail } 風格的 API（例如小程式的 wx.request）
const promisify = (fn) => (options = {}) =>
  new Promise((resolve, reject) => {
    fn({ ...options, success: resolve, fail: reject })
  })

const request = promisify(wx.request)
const user = await request({ url: '/userInfo' })
const friends = await request({ url: `/${user.data.id}/friendList` })
```

Node 的 `(err, result) => {}` 風格直接用內建的 `util.promisify`；新版 Node 的 `fs/promises`、瀏覽器的 `fetch` 本來就回傳 Promise。

## 實作前要懂的四條規則 {#1-3-7-2}

1. **三種狀態，只能變一次**：`pending` → `fulfilled` 或 `rejected`，之後再呼叫 `resolve`／`reject` 都無效。
2. **`then` 永遠回傳新的 Promise**，新 Promise 的結果由 callback 決定：回傳一般值就 fulfilled、丟錯就 rejected、回傳 Promise（或任何有 `then` 方法的 thenable）就跟著它的結果走。
3. **callback 一律非同步執行**（放進微任務），就算 Promise 早就有結果了，`then` 裡的程式也不會同步跑。
4. **值穿透**：`then` 的參數不是函式就被忽略，值原封不動傳給下一個，所以 `p.then(null).then(console.log)` 拿得到值；`catch(fn)` 就是 `then(null, fn)`。

## 完整實作 {#1-3-7-3}

```js
class MyPromise {
  #state = 'pending'
  #value
  #handlers = []

  constructor(executor) {
    const settle = (state, value) => {
      if (this.#state !== 'pending') return // 規則 1：只能變一次
      this.#state = state
      this.#value = value
      this.#handlers.forEach((h) => h())
    }
    const resolve = (value) => {
      if (value === this) return settle('rejected', new TypeError('Chaining cycle'))
      // 規則 2：resolve 一個 thenable，就等它的結果
      if (value !== null && (typeof value === 'object' || typeof value === 'function')) {
        let called = false
        try {
          const then = value.then
          if (typeof then === 'function') {
            then.call(
              value,
              (v) => { if (!called) { called = true; resolve(v) } },
              (e) => { if (!called) { called = true; settle('rejected', e) } },
            )
            return
          }
        } catch (e) {
          if (!called) settle('rejected', e)
          return
        }
      }
      settle('fulfilled', value)
    }
    try {
      executor(resolve, (reason) => settle('rejected', reason))
    } catch (e) {
      settle('rejected', e) // executor 丟錯等於 reject
    }
  }

  then(onFulfilled, onRejected) {
    // 規則 4：不是函式就穿透
    onFulfilled = typeof onFulfilled === 'function' ? onFulfilled : (v) => v
    onRejected = typeof onRejected === 'function' ? onRejected : (e) => { throw e }

    return new MyPromise((resolve, reject) => {
      const run = () =>
        queueMicrotask(() => { // 規則 3：非同步執行
          try {
            const cb = this.#state === 'fulfilled' ? onFulfilled : onRejected
            resolve(cb(this.#value)) // 規則 2：callback 的結果決定新 Promise
          } catch (e) {
            reject(e)
          }
        })
      this.#state === 'pending' ? this.#handlers.push(run) : run()
    })
  }

  catch(onRejected) { return this.then(null, onRejected) }
  finally(fn) {
    return this.then(
      (v) => MyPromise.resolve(fn()).then(() => v),          // finally 不改變原本的值
      (e) => MyPromise.resolve(fn()).then(() => { throw e }),
    )
  }
}
```

這份實作通過 Promises/A+ 規範的核心要求。各段要對應的面試追問：狀態為什麼要鎖（規則 1）、為什麼要 `queueMicrotask`（規則 3）、`resolve` 自己會怎樣（循環參考要 reject）、thenable 為什麼要用 `called` 防止重複呼叫（第三方 thenable 可能同時呼叫兩個 callback）。

## 靜態方法 {#1-3-7-4}

| 方法 | 什麼時候完成 | 結果 |
| --- | --- | --- |
| `Promise.all` | 全部成功，或**任一失敗** | 結果陣列（順序同輸入）；或第一個錯誤 |
| `Promise.allSettled`（ES2020） | 全部結束，不會失敗 | `[{ status, value／reason }]` |
| `Promise.race` | 第一個結束（成功或失敗） | 那一個的結果 |
| `Promise.any`（ES2021） | 第一個成功；全部失敗才失敗 | 那個值；或 `AggregateError` |
| `Promise.withResolvers()`（ES2024） | — | `{ promise, resolve, reject }`，不用把 resolve 存到外層變數 |
| `Promise.try(fn)`（ES2025） | — | 不管 `fn` 是同步丟錯還是回傳 rejected Promise，都統一成 rejected Promise |

`all` 和 `race` 的實作重點：

```js
MyPromise.resolve = (v) => (v instanceof MyPromise ? v : new MyPromise((r) => r(v)))
MyPromise.reject = (e) => new MyPromise((_, r) => r(e))

MyPromise.all = (iterable) =>
  new MyPromise((resolve, reject) => {
    const items = [...iterable]
    const results = new Array(items.length)
    let done = 0
    if (items.length === 0) return resolve(results) // 空陣列直接成功
    items.forEach((item, i) => {
      MyPromise.resolve(item).then((v) => {
        results[i] = v // 用索引放，不能用 push，否則順序會依完成先後亂掉
        if (++done === items.length) resolve(results)
      }, reject)
    })
  })

MyPromise.race = (iterable) =>
  new MyPromise((resolve, reject) => {
    for (const item of iterable) MyPromise.resolve(item).then(resolve, reject)
  })
```

`race` 常用來做逾時：`Promise.race([fetch(url), timeout(5000)])`。不過 `fetch` 本身現在可以傳 `signal: AbortSignal.timeout(5000)`，逾時會真的取消請求，比 `race` 只是「不等了」更好。

## 常見錯誤 {#1-3-7-5}

- **`then` 裡忘了 `return`**：下一個 `then` 拿到 `undefined`，也不會等裡面的非同步工作完成。
- **沒有接錯誤**：rejected 的 Promise 沒人處理會觸發 `unhandledrejection`（Node 預設直接結束程序）。鏈的最後要有 `catch`，`await` 要包 `try/catch`。
- **把已經回傳 Promise 的函式又包一層 `new Promise`**：`new Promise((r) => fetch(url).then(r))` 會吞掉錯誤，直接 `return fetch(url)` 就好。
- **迴圈裡 `await` 造成不必要的序列化**：彼此無關的請求用 `Promise.all` 一起發。
