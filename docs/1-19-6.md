## 寫入 API 防護（防 F12 竄改 payload） {#1-19-6-1}

對應 OWASP API Security Top 10 的 BOLA（越權存取物件）、BOPLA / Mass Assignment（偷塞欄位）、資源濫用。

- [ ] **認證**：所有寫入路由都過 auth middleware；userId 一律取自 server 驗證結果，不收前端傳入。
- [ ] **授權 / 所有權**：從 DB 讀出資源，比對 `ownerId` 或 scope，不信任前端宣稱的 owner。
- [ ] **欄位白名單**：Zod `.strict()` 或 NestJS `ValidationPipe({ whitelist: true, forbidNonWhitelisted: true })`；`role`、`status`、`price`、`ownerId` 由後端決定或計算。
- [ ] **業務規則驗證**：enum、範圍、交互規則（`end > start`）、狀態機只允許合法轉移。
- [ ] **CSRF**（用 cookie 時）：SameSite + CSRF token + 驗 Origin/Referer。CORS 不是 CSRF 防護。
- [ ] **併發**：樂觀鎖（version / ETag + `If-Match`），不符回 409。
- [ ] **重送**：建立/存檔帶 `Idempotency-Key`。
- [ ] **限流**：依 user + IP 雙維度，限制 body 大小。
- [ ] **DB 最後防線**：NOT NULL、UNIQUE、FK、CHECK，必要時 Postgres RLS。
- [ ] **審計**：記錄誰、何時、改了哪些欄位（前後值）；大量 403/409 觸發告警。

## 資料遮罩 / 去識別化 {#1-19-6-2}

- **在伺服器邊界處理**：前端拿到的 API 回應本身就該是遮罩過的（用 DevTools Network 驗證，不是只看畫面）。
- 單一真相來源：一張「欄位 → 規則」表（none / partial / hash / tokenize / drop + 可繞過的角色），所有 API、匯出、報表共用同一個序列化器。
- ORM `select` 白名單，不要把 entity 直接吐出去。
- Log redaction：Authorization header、密碼、卡號、Email、電話；錯誤堆疊不能帶 payload。
- 身分證號這類「可能值很少」的欄位，**不要用無鹽 SHA-256**（可被窮舉），要用 HMAC + 伺服器端密鑰，或 tokenize。
- 前端需要呈現時三種模式：
  1. **永遠遮罩**（列表、搜尋、匯出）
  2. **按需解鎖**：角色檢查 + 2FA + 填理由 → 後端回傳短效原文（如 60 秒）、`Cache-Control: no-store`、寫 audit log；前端只放 memory，不落地 localStorage。
  3. **動作型**：使用者只需「用」不需「看」（寄信、撥號、下載），由後端代操作或發短效簽名連結。
- 關於 SSR：安全來自「敏感資料在伺服器處理」，不是渲染方式本身。CSR 搭配已遮罩的 API 一樣安全；SSR 反而要小心個人化頁面被 CDN 快取。
