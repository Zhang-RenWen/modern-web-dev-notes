# 1-5 瀏覽器原理 {#1-5}

<SectionToc />

用「一個 URL 從輸入到變成畫面」這條主線，把現代瀏覽器的架構與原理串起來，最後比較各家瀏覽器差在哪裡。資料更新到 2026 年 10 月。

## 這些原理怎麼用在工作上

- **效能**：動畫只碰 `transform`／`opacity`；避免讀寫幾何屬性交錯；長任務切塊或丟 Worker；用 `content-visibility: auto` 跳過畫面外的渲染（渲染管線、JS 引擎）。
- **載入**：關鍵 CSS 內聯、JS 用 `defer`／`module`、圖片給尺寸避免版面位移（CLS）、善用 `preconnect` 與 HTTP 快取標頭（導航、渲染管線）。
- **相容性**：Chrome 能跑不代表 Safari 能跑；iOS 一律以 WebKit 測試；查 [caniuse](https://caniuse.com/) 與 MDN 的 Baseline 標示（瀏覽器差異）。
- **安全**（金融業尤其重要）：正確設定 CSP、`HttpOnly`／`Secure`／`SameSite` Cookie、CORS 白名單、HSTS；理解「瀏覽器只負責執行政策，政策由伺服器宣告」（安全模型、CORS）。
- **除錯工具**：DevTools 的 Performance 面板（主執行緒火焰圖、Layout／Paint 時間）、Rendering 面板（Paint flashing、Layer borders）、Lighthouse、`chrome://tracing`。

::: tip 一頁總結
瀏覽器 = 多進程 + 沙箱的作業系統級應用。導航流程決定「資料怎麼來」，渲染管線（DOM → Style → Layout → Paint → Composite）決定「畫面怎麼出來」，JS 引擎用分層 JIT 與隱藏類別讓動態語言跑得快，Event Loop 讓單執行緒能兼顧互動與繪製。各家差異：Chromium 系功能最快、生態最大；Safari 省電、重隱私、壟斷 iOS；Firefox 是唯一非 Apple／Google 的主流引擎。2026 年的主旋律是 AI 代理化與引擎多樣性的再嘗試（Ladybird）。
:::
