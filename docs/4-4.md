# 4-4 非同步函式

::: info 改寫（2026-11）
整理自《Practical Modern JavaScript》（2017）。已精簡，補上 ES2022 的頂層 `await`，並加入常見錯誤（迴圈裡逐一 `await`、`forEach` 不會等待）。async 函式背後的 generator 執行器見 [4-3](./4-3.md#4-3-8)。
:::

### 4-4-1 為什麼需要 async/await {#4-4-1}

同一段流程的三種寫法：

```js
// 回呼：一層包一層，每層都要處理 err
getArticle((err, article) => {
  if (err) return handle(err)
  renderView(article, (err, html) => { … })
})

// Promise 鏈：比較平，但中間結果要靠閉包或額外變數才能傳到後面
getArticle()
  .then((article) => renderView(article))
  .then((html) => setPageContents(html))
  .catch(handle)

// async/await：讀起來像同步程式，可以用一般的 if、for、try/catch
async function showArticle() {
  try {
    const article = await getArticle()
    const html = await renderView(article)
    setPageContents(html)
  } catch (err) {
    handle(err)
  }
}
```

### 4-4-2 規則 {#4-4-2}

- `async function` **一定回傳 Promise**：`return x` 等於 resolve 成 `x`，丟出錯誤等於 reject。
- `await` 等待一個 Promise（不是 Promise 的值會直接拿來用），期間函式暫停，但**不會阻塞主執行緒**，其他程式照常執行。
- `await` 之後的程式碼在微任務中繼續執行（見 [1-3-6](./1-3-6.md#1-3-6-5)）。
- `await` 只能在 `async` 函式裡用；ES2022 起 **ES Module 的頂層**也可以直接 `await`（會延後依賴這個模組的其他模組執行）。
- 箭頭函式、方法、class 方法都可以加 `async`：`const f = async () => {}`。

### 4-4-3 並行，不要不小心變成循序 {#4-4-3}

```js
// 循序：總時間 = a + b + c
const a = await fetchA()
const b = await fetchB()

// 並行：總時間 ≈ 最慢的那一個
const [a2, b2] = await Promise.all([fetchA(), fetchB()])
```

彼此沒有依賴的請求，先全部發出再一起 `await`。

**迴圈裡的陷阱**：

```js
for (const id of ids) await save(id)          // 一個接一個：需要順序時才這樣寫
await Promise.all(ids.map((id) => save(id)))  // 全部並行
ids.forEach(async (id) => await save(id))      // 錯：forEach 不會等待，函式立刻往下執行，錯誤也接不到
```

數量很多時不要一次全部並行，要限制同時進行的數量（見 [1-3-6](./1-3-6.md#1-3-6-3)）。

### 4-4-4 錯誤處理 {#4-4-4}

```js
async function load() {
  try {
    return await fetchJSON('/items') // 要在 try 裡 await，錯誤才會被這個 catch 接住
  } catch (err) {
    report(err)
    return [] // 回傳備用值
  }
}

load().catch(report) // 或在呼叫端用 .catch 處理
```

- 沒處理的 rejection 會觸發 `unhandledrejection`。
- `return promise`（沒有 `await`）時，promise 的錯誤不會被同一個函式的 `try/catch` 接住。
- 想要「各自處理成敗、不讓一個失敗中斷全部」用 `Promise.allSettled`。

### 4-4-5 內部運作 {#4-4-5}

async 函式可以看成「generator + 自動執行器」：

```js
async function example(a, b) {
  const x = await a
  return x + (await b)
}
// 概念上等同
function example(a, b) {
  return run(function* () {
    const x = yield a
    return x + (yield b)
  })
}
```

執行器每次拿到 `yield` 出來的值，就等它完成，再用 `next(結果)` 送回去繼續執行；遇到錯誤就用 `throw(錯誤)` 丟回去。`run` 的實作見 [4-3](./4-3.md#4-3-8)。實際的引擎實作不經過 generator，但行為一致。
