# 4-1 Promise

::: info 改寫（2026-11）

:::

### 4-1-1 為什麼需要 Promise {#4-1-1}

Promise 代表「一個之後才會有結果的值」。`fetch` 回傳的就是 Promise：

```js
fetch('/items')
  .then((res) => res.json())
  .then((items) => render(items))
  .catch((err) => showError(err))
```

和其他非同步寫法比較：

| 寫法 | 問題 |
| --- | --- |
| 回呼函式 `fetch(url, (err, res) => {})` | 巢狀越來越深；每一層都要自己檢查 `err`；多個步驟的錯誤要各自處理 |
| 事件 `req.on('data', …)`、`req.on('error', …)` | 適合會觸發很多次的事件；一次性的結果用起來囉唆，也很難串接下一步 |
| Promise | 可以串接、錯誤會一路往下傳到 `catch`、可以組合（全部完成、取最快的） |

### 4-1-2 串接與錯誤傳遞 {#4-1-2}

**`then`、`catch` 每次都回傳新的 Promise**，所以可以一直串下去：

- callback 回傳一般值 → 下一個 `then` 收到這個值。
- callback 回傳 Promise → 等它完成，下一個 `then` 收到它的結果。
- callback 丟出錯誤 → 跳過後面的 `then`，直到遇到 `catch`。
- `catch` 處理完沒有再丟錯 → 鏈恢復正常，後面的 `then` 會繼續執行。

```js
Promise.resolve(2)
  .then((x) => { throw new Error('failed') })
  .then((x) => x * 2)                         // 被跳過
  .catch((err) => console.error(err.message)) // 'failed'
  .then(() => console.log('恢復正常'))         // 會執行
```

**`catch` 要接在哪一個 Promise 上很重要**。把 Promise 想成樹狀結構：

```js
const p = fetch('/items').then((res) => res.a.b.c) // 這裡會丟錯

p.catch((e) => console.error(e.message)) // 會印出
p.catch((e) => console.error(e.message)) // 也會印出：兩個 catch 都直接接在 p 上

p.catch((e) => console.error(e.message))
 .catch((e) => console.error(e.message)) // 不會印出：第一個 catch 已經處理掉了
```

沒有任何 `catch` 的 rejected Promise 會觸發 `unhandledrejection`（Node.js 預設直接結束程序），鏈的最後一定要處理錯誤。

### 4-1-3 自己建立 Promise {#4-1-3}

只有在包裝「回呼風格」的 API 時才需要 `new Promise`：

```js
const delay = (ms) => new Promise((resolve) => setTimeout(resolve, ms))

const loadImage = (src) =>
  new Promise((resolve, reject) => {
    const img = new Image()
    img.onload = () => resolve(img)
    img.onerror = () => reject(new Error(`無法載入 ${src}`))
    img.src = src
  })
```

- executor 裡丟出錯誤，等同呼叫 `reject`。
- `Promise.resolve(value)`、`Promise.reject(error)` 直接建立已經有結果的 Promise。
- 本來就回傳 Promise 的函式，不要再包一層 `new Promise`（會吞掉錯誤，也多此一舉）。
- ES2024 的 `Promise.withResolvers()` 回傳 `{ promise, resolve, reject }`，適合要在 executor 外面決定結果的情況（例如等某個事件發生）。

### 4-1-4 狀態與結果 {#4-1-4}

Promise 有三種狀態：`pending`（等待中）→ `fulfilled`（成功，有一個值）或 `rejected`（失敗，有一個原因）。**一旦確定就不會再改變**，之後再呼叫 `resolve`／`reject` 都會被忽略。後來才接上的 `then` 也會拿到同一個結果。

`then` 的 callback 一律非同步執行（放進微任務佇列），就算 Promise 早就有結果：

```js
Promise.resolve('data').then(console.log)
console.log(1)
// 1 → data
```

### 4-1-5 Promise#finally {#4-1-5}

不管成功或失敗都要執行的收尾工作（ES2018）：

```js
showSpinner()
fetch('/items')
  .then(render)
  .catch(showError)
  .finally(hideSpinner) // 不會收到任何參數，也不會改變原本的結果
```

`finally` 的 callback 如果丟錯或回傳 rejected 的 Promise，才會改變結果。

### 4-1-6 善用 Promise.all 和 Promise.race {#4-1-6}

```js
// 並行發出，全部成功才成功，任一失敗就立刻失敗
const [user, posts] = await Promise.all([fetchUser(id), fetchPosts(id)])

// 取最快結束的那一個（成功或失敗）
const result = await Promise.race([fetch(url), timeout(5000)])
```

| 方法 | 完成條件 |
| --- | --- |
| `Promise.all` | 全部成功；或任一失敗 |
| `Promise.allSettled`（ES2020） | 全部結束，永遠不會失敗，每個結果標明成功或失敗 |
| `Promise.race` | 第一個結束的 |
| `Promise.any`（ES2021） | 第一個成功的；全部失敗才失敗 |

`Promise.all` 失敗時，其他還在進行的請求**不會被取消**，只是結果不再被使用；需要真的取消要搭配 `AbortController`。四個方法的時間軸比較動畫見 [1-3-7](./1-3-7.md#1-3-7-4)。
