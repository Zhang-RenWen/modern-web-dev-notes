# 1-16-5 並行：Async vs Multi-thread {#1-16-5}

::: info 新增（2026-11）
整理自 Notion「計算機基礎」第 5 節。
:::

> 物理上一句話：**async 的平行發生在「裝置（網卡、磁碟）與 CPU 之間」；multi-thread 的平行發生在「CPU 不同核心之間」。**

| | Async 非同步 | Multi-thread 多執行緒 |
| --- | --- | --- |
| 機制 | 少數執行緒＋Event Loop；遇到 I/O 等待就暫停（suspend）去做別的 Task，I/O 完成後經 callback／await 恢復 | 多條執行緒由 OS 排程，多核心時真正同時執行 |
| 適合 | I/O 密集：API 呼叫、DB 查詢、外部系統介接 | CPU 密集：數學運算、影像、AI 訓練、遊戲引擎 |
| 成本 | 記憶體少；但 CPU 密集工作會卡住整個 event loop | 每條執行緒有自己的 stack，記憶體大、切換成本高 |
| 風險 | 忘了 await、在 event loop 裡做重運算 | 共享記憶體 → race condition、deadlock |

- **修正原文**：「每條執行緒獨立運行，隔離性佳也容易除錯」是錯的。同一 process 的執行緒共享記憶體，這正是難除錯的原因；隔離性好的是 multi-process。
- **Coroutine（協程）是實作 async 的機制**：由語言 runtime 管理，可暫停／恢復而不阻塞底層執行緒。C#、Python、PHP 的 await 背後都是這類機制。層次：Async（概念）→ Coroutine（語言實作）→ Thread（OS 資源）。
- **選型**：企業系統介接外部資源 → 首選 async（省資源、易開發）；數據分析、科學計算、AI → multi-thread／multi-process。
- MCU 上：FreeRTOS 支援多工，但小型任務優先 event-driven，省記憶體也免管執行緒。
- 好記比喻：多執行緒＝同時交往多個女友的時間管理大師（行程撞期＝deadlock，翻車＝crash）；async＝專情男把衣服丟進洗衣機，等待時去煮飯拖地，洗好再回來晾。
