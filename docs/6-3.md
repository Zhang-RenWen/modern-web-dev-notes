# 6-3 代理器機關處理器

::: info 改寫（2026-11）
整理自《Practical Modern JavaScript》（2017），已精簡成每個機關一個範例。
:::

延續 [6-1](./6-1.md) 的「隱藏底線開頭屬性」，要藏得徹底，光攔 `get`、`set` 不夠，`in`、`delete`、`Object.keys` 也都會洩漏。

### 6-3-1 has：攔截 in {#6-3-1}

```js
const hidden = (key) => typeof key === 'string' && key.startsWith('_')

const handler = {
  has: (t, key) => !hidden(key) && Reflect.has(t, key),
}
'_secret' in new Proxy({ _secret: 1 }, handler) // false
```

`has` 攔截 `in` 運算子與 `with` 陳述式，但**不攔截** `hasOwnProperty`（那是 `getOwnPropertyDescriptor`）。

### 6-3-2 deleteProperty：攔截 delete {#6-3-2}

```js
handler.deleteProperty = (t, key) => {
  if (hidden(key)) throw new Error(`不能刪除 ${key}`)
  return Reflect.deleteProperty(t, key)
}
```

### 6-3-3 defineProperty：攔截定義屬性 {#6-3-3}

攔截 `Object.defineProperty`，以及一般的賦值（賦值最後也會定義屬性）。可以用來禁止某些屬性被定義或改成 getter：

```js
handler.defineProperty = (t, key, descriptor) => {
  if (hidden(key)) throw new Error(`不能定義 ${key}`)
  return Reflect.defineProperty(t, key, descriptor)
}
```

### 6-3-4 ownKeys：攔截列出鍵 {#6-3-4}

攔截 `Object.keys`、`Object.getOwnPropertyNames`、`Object.getOwnPropertySymbols`、`Reflect.ownKeys`、`for...in`、物件展開與 `JSON.stringify`：

```js
handler.ownKeys = (t) => Reflect.ownKeys(t).filter((key) => !hidden(key))

const proxy = new Proxy({ _secret: 1, name: 'a' }, handler)
Object.keys(proxy)   // ['name']
JSON.stringify(proxy) // '{"name":"a"}'
```

**不變條件（invariants）**：機關不能違反目標物件本身的限制，否則會丟 `TypeError`。例如目標物件的屬性是「不可設定」（non-configurable）的，`ownKeys` 就不能把它過濾掉，`has` 也不能回報它不存在。這保證了代理不會對凍結的物件說謊。
