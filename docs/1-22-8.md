# 1-22-8 系統設計面試套路 {#1-22-8}

::: info 新增（2026-11）
整理自 Notion「系統設計與架構」八〈系統設計面試套路〉。
:::

- 面試在測：把模糊大需求定義成合理需求 → 給出粗略大架構 → 對關鍵元件比較多種方案並說明取捨。
- **以資料流為主軸**：資料怎麼進、怎麼存、怎麼處理、怎麼出，再依需求插入元件。
- 時間分配：約 10 分鐘釐清功能與非功能需求（API、資料形式、availability、latency、使用者數、QPS 與資料量級估算）→ 約 10 分鐘依資料流畫初步架構並說明每個元件選擇 → 深入關鍵元件 → 最後順一次流程，點出瓶頸與改善方向。
- 口袋元件：HTTP / Long Polling / WebSocket；垂直 vs 水平擴充；Load Balancer（DNS / 軟體 / 硬體，Session 外移共享，LB 自己也要避免單點）；Raw Data 放 Object Storage、Metadata 放 SQL / NoSQL；SQL 擴充靠主從讀寫分離、Master-Master、Sharding；NoSQL 要談 CAP；Cache（Redis / Memcached、write-through / around / back、LRU）；CDN；Message Queue 緩衝；Async（例：YouTube 上傳、轉碼、版權檢測都非同步，使用者可先填標題）。
- 加分項：**主動列出多種方案並討論 trade-off**。
