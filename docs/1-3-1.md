# 1-3-1 this {#1-3-1}

::: info 改寫（2026-11）
原內容整理自 2019 年前的書籍，已精簡：規則改成依優先順序的一張表，例題保留最有代表性的幾題並修正原本的語法錯誤，補上 class 與 ES module 預設是嚴格模式的影響。
:::

> 一句話：**`this` 由「怎麼呼叫」決定，不由「在哪裡定義」決定**；只有箭頭函式例外，它沒有自己的 `this`。

## 判斷規則（由上往下，第一個符合的決定） {#1-3-1-1}

| 呼叫方式 | `this` 是 | 例 |
| --- | --- | --- |
| 箭頭函式 | 外層作用域的 `this`，之後怎麼呼叫都改不了 | `() => this` |
| `new Fn()` | 新建立的物件 | `new Person()` |
| `call`／`apply`／`bind` | 指定的物件 | `fn.call(obj)` |
| `obj.fn()` | 點前面的物件 | `user.getName()` |
| 直接呼叫 `fn()` | 嚴格模式 `undefined`，否則全域物件 | `const f = obj.fn; f()` |

**class 內部、ES module（`<script type="module">`、打包工具的程式碼）預設都是嚴格模式**，所以現代程式碼裡「直接呼叫」幾乎都是 `undefined`，取用 `this.x` 會直接報錯。

## 常見陷阱：方法被取出來就丟了 this {#1-3-1-2}

```js
const o1 = { text: 'o1', fn() { return this.text } }
const o2 = { text: 'o2', fn() { return o1.fn() } }
const o3 = { text: 'o3', fn() { const fn = o1.fn; return fn() } }

o1.fn() // 'o1'
o2.fn() // 'o1'：呼叫的是 o1.fn()，點前面是 o1
o3.fn() // 嚴格模式報錯／非嚴格模式 undefined：fn() 是直接呼叫
```

同樣的情況還有：把方法當 callback 傳出去（`setTimeout(obj.fn)`、`arr.map(obj.fn)`）、React class 元件的事件處理函式。修法有三種：

```js
setTimeout(() => obj.fn())   // 1. 包一層箭頭函式
setTimeout(obj.fn.bind(obj)) // 2. 先 bind
class Btn { handle = () => { /* this 永遠是實例 */ } } // 3. class 欄位寫成箭頭函式
```

DOM 事件：`el.addEventListener('click', function () { this })` 的 `this` 是綁定事件的元素（等同 `e.currentTarget`）；寫成箭頭函式就拿不到。

## call、apply、bind {#1-3-1-3}

```js
fn.call(target, a, b)    // 立刻執行，參數逐一傳
fn.apply(target, [a, b]) // 立刻執行，參數用陣列
const bound = fn.bind(target, a) // 不執行，回傳綁好 this（和前面參數）的新函式
bound(b)
```

`bind` 只有第一次有效：`fn.bind(a).bind(b)` 的 `this` 還是 `a`。

## 建構函式與 new {#1-3-1-4}

`new Foo()` 做了三件事：

```js
const obj = Object.create(Foo.prototype) // 1. 建立物件，原型指向 Foo.prototype
const result = Foo.call(obj)             // 2. 用這個物件當 this 執行 Foo
const isObject = (typeof result === 'object' && result !== null) || typeof result === 'function'
const instance = isObject ? result : obj // 3. Foo 回傳物件就用它，否則用 obj
```

所以建構函式 `return {}` 會讓 `new` 拿到那個空物件；`return 1` 這種原始值則會被忽略。

## 優先順序例題 {#1-3-1-5}

```js
function foo(a) { this.a = a }
const obj1 = {}
const bar = foo.bind(obj1)
bar(2)              // obj1.a === 2
const baz = new bar(3)
baz.a               // 3：new 的優先順序比 bind 高，this 換成新物件
obj1.a              // 還是 2
```

```js
function outer() { return () => console.log(this.a) }
const arrow = outer.call({ a: 2 })
arrow.call({ a: 3 }) // 2：箭頭函式的 this 在建立時就固定了，call 改不了
```

```js
var a = 123   // var 宣告的全域變數會掛到 window 上
const b = 456 // let／const 不會
console.log(window.a, window.b) // 123 undefined
```

## 手寫 bind {#1-3-1-6}

重點有兩個：預先填入的參數要和呼叫時的參數合併；被 `new` 呼叫時要忽略綁定的 `this`。

```js
Function.prototype.myBind = function (context, ...preset) {
  const fn = this
  function bound(...args) {
    // 被 new 呼叫時，this 是 bound 的實例，要用它而不是 context
    return fn.apply(new.target ? this : context, [...preset, ...args])
  }
  bound.prototype = Object.create(fn.prototype) // 讓 new bound() 的實例也是 fn 的實例
  return bound
}
```

原生 `bind` 產生的函式還會調整 `length`（減掉預填參數個數）和 `name`（`"bound fn"`），面試提到這兩點即可。
