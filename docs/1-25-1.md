# 1-25-1 TypeScript 型別系統的核心觀念 {#1-25-1}

::: info 新增（2026-11）
先建立心智模型，再學語法。這頁的觀念決定了你能不能看懂後面所有的 TS 程式碼。
:::

## TypeScript 是什麼 {#1-25-1-1}

TypeScript = **JavaScript + 型別註記 + 編譯期檢查**。

- 編譯後型別**全部消失**，輸出的是普通 JavaScript。型別只存在於編輯器與編譯階段，執行期不會幫你檢查任何東西。
- 所以「API 回傳的資料一定符合型別」是錯覺：外部資料要在執行期驗證（見 [1-25-3](./1-25-3.md#1-25-3-3)）。
- 好處不只抓錯：自動完成、重構時一次找出所有受影響的地方、型別就是最新的文件。

## 型別是「值的集合」 {#1-25-1-2}

把型別想成一個集合，就能理解大部分語法：

| 型別 | 代表的集合 |
| --- | --- |
| `string` | 所有字串 |
| `'admin'` | 只有 `'admin'` 這一個值（字面量型別） |
| `'admin' \| 'user'` | 兩個值的聯集（union） |
| `A & B` | 同時符合 A 和 B（intersection） |
| `never` | 空集合，不可能存在的值 |
| `unknown` | 所有值（但使用前要先縮小範圍） |
| `any` | 關掉檢查，不是集合概念 |

「A 可以賦值給 B」就是「A 的集合是 B 的子集合」：`'admin'` 可以給 `string`，反過來不行。

## 結構型別：看形狀，不看名字 {#1-25-1-3}

這是 TS 和 Java 最大的差異之一。TS 只要**結構符合**就相容，不管型別叫什麼名字、有沒有宣告實作：

```ts
interface Point { x: number; y: number }

class Pixel {
  constructor(public x: number, public y: number, public color: string) {}
}

const p: Point = new Pixel(1, 2, 'red')   // ✅ Pixel 有 x、y，就是 Point，不用 implements
```

Java 是**名義型別**（nominal typing）：一定要 `implements Point` 才算 Point（見 [1-25-6](./1-25-6.md#1-25-6-2)）。

## 型別推論：不用每個地方都寫型別 {#1-25-1-4}

```ts
let count = 0                 // 推論為 number
const role = 'admin'          // const 推論為字面量 'admin'
const ids = [1, 2, 3]         // number[]
const user = { id: 1, name: 'Amy' }   // { id: number; name: string }

function add(a: number, b: number) {
  return a + b                // 回傳型別推論為 number
}
```

原則：**參數一定寫型別，區域變數交給推論，公開函式的回傳型別建議明確寫**（避免實作改動時不小心改變對外介面）。

## 縮小型別（Narrowing） {#1-25-1-5}

TS 會根據你寫的判斷，自動把型別範圍縮小，這叫 control flow analysis：

```ts
function format(input: string | number | null) {
  if (input === null) return '-'            // 這裡之後 input: string | number
  if (typeof input === 'number') return input.toFixed(2)   // input: number
  return input.trim()                       // input: string
}
```

縮小的方式：`typeof`、`instanceof`、`in`、相等比較、可辨識聯合、自訂 type guard。詳細範例見 [模擬面試 4 Q5](./interview-4.md#interview-4-5)。

## 最重要的建模工具：可辨識聯合 {#1-25-1-6}

用一個共同欄位（例如 `status`、`type`）區分不同情況，讓**不合法的狀態無法表示**：

```ts
// ❌ 所有欄位都是可選的：可能出現 status 為 success 卻沒有 data
type Bad = { status: string; data?: User; error?: string }

// ✅ 每種狀態只帶自己該有的資料
type Result =
  | { status: 'loading' }
  | { status: 'success'; data: User }
  | { status: 'error'; error: string }

function render(r: Result) {
  switch (r.status) {
    case 'loading': return '載入中'
    case 'success': return r.data.name    // 這裡 TS 知道一定有 data
    case 'error': return r.error
  }
}
```

## 泛型：型別的參數 {#1-25-1-7}

泛型讓函式或型別「對任何型別都適用，但保持型別關係」：

```ts
function first<T>(list: T[]): T | undefined {
  return list[0]
}
first([1, 2, 3])        // T 推論為 number，回傳 number | undefined
first(['a', 'b'])       // T 推論為 string

// 加上限制：T 至少要有 id
function findById<T extends { id: number }>(list: T[], id: number): T | undefined {
  return list.find((item) => item.id === id)
}
```

讀法：`<T>` 是「型別參數」，呼叫時由 TS 推論或手動指定；`T extends X` 在泛型裡是「T 必須符合 X」的限制，不是繼承。

## any、unknown、never 的使用時機 {#1-25-1-8}

- `any`：關掉檢查，會「傳染」給用到它的地方。只在遷移舊程式碼時暫用。
- `unknown`：外部輸入的正確型別（`JSON.parse`、API 回應、`catch (e)`），使用前必須先縮小。
- `never`：窮舉檢查（新增狀態卻忘了處理時讓編譯失敗）、永遠丟錯的函式回傳型別。

詳見 [模擬面試 4 Q1](./interview-4.md#interview-4-1)。

## 型別擦除帶來的限制 {#1-25-1-9}

因為型別在執行期不存在：

- 不能用 `instanceof` 判斷 interface 或 type（它們執行期不存在），只能判斷 class。
- 泛型 `T` 在執行期拿不到，不能寫 `new T()`。
- 要在執行期知道型別，就要留下執行期的值：class、可辨識聯合的 `type` 欄位，或 schema（Zod）。

Java 的泛型也有型別擦除，但 class 與 interface 在執行期都存在（見 [1-25-6](./1-25-6.md)）。
