# 1-7-1 響應式架構設計 {#1-7-1}

::: info 改寫（2026-11）
原內容整理自 2019 年前的書籍，以 Vue 2 的 `Object.defineProperty` 一步步手寫 MVVM。已精簡成原理與一份最小實作，改以 Vue 3 的 Proxy 為主，補上 Signals 這個近年各框架共同的方向；虛擬 DOM 的手寫 diff 改成重點規則加動畫。
:::

> 一句話：**框架都在解決同一件事：資料變了，畫面自動跟著變。** 差別在「怎麼知道資料變了」和「怎麼知道要更新哪一塊畫面」。

## 三步驟：收集依賴、偵測變化、通知更新 {#1-7-1-1}

1. **收集依賴**：渲染時記下「這塊畫面讀了哪些資料」。
2. **偵測變化**：資料被改時要能察覺。
3. **通知更新**：只重新執行用到這筆資料的那幾塊。

各框架「偵測變化」的方式：

| 方式 | 代表 | 怎麼做 | 取捨 |
| --- | --- | --- | --- |
| 髒值檢查 | AngularJS（1.x） | 事件後把所有綁定的值重新比對一遍 | 綁定多就慢 |
| getter／setter 攔截 | Vue 2 | `Object.defineProperty` 改寫每個屬性 | 偵測不到新增屬性、陣列索引賦值，要用 `Vue.set` |
| Proxy 攔截 | Vue 3、MobX | 攔截整個物件的讀寫 | 新增屬性、陣列都偵測得到；延遲到讀取時才深入代理 |
| 重新執行元件 | React | 不偵測，`setState` 時重跑元件函式，再比對虛擬 DOM | 心智模型簡單；要靠 `memo` 或 React Compiler 避免多餘的重算 |
| Signals | Solid、Preact、Angular 16+、Vue 3 的 `ref` | 每個值是一個可訂閱的「訊號」，讀取時自動訂閱 | 更新精準到單一 DOM 節點，不需要虛擬 DOM；TC39 有標準化提案 |
| 編譯期分析 | Svelte | 編譯時就知道哪個變數影響哪段 DOM | 執行期最輕；Svelte 5 也改成 Signals（runes） |

## defineProperty 與 Proxy {#1-7-1-2}

| | `Object.defineProperty`（Vue 2） | `Proxy`（Vue 3） |
| --- | --- | --- |
| 攔截單位 | 單一屬性，要先走訪所有屬性 | 整個物件 |
| 新增、刪除屬性 | 偵測不到 | 偵測得到（`set`、`deleteProperty`） |
| 陣列 | 偵測不到 `arr[0] = x` 和 `length`，要改寫 `push` 等 7 個方法 | 全部偵測得到 |
| 巢狀物件 | 初始化時就遞迴全部處理 | 讀到才代理（延遲） |
| `Map`、`Set` | 不支援 | 支援 |

## 最小實作：Proxy + effect {#1-7-1-3}

Vue 3 響應式核心的縮小版。`track` 記錄「誰讀了什麼」，`trigger` 在寫入時重跑那些函式：

```js
let activeEffect = null
const targetMap = new WeakMap() // 物件 → 屬性 → 用到它的 effect

function track(target, key) {
  if (!activeEffect) return
  let deps = targetMap.get(target)
  if (!deps) targetMap.set(target, (deps = new Map()))
  let set = deps.get(key)
  if (!set) deps.set(key, (set = new Set()))
  set.add(activeEffect)
}

function trigger(target, key) {
  targetMap.get(target)?.get(key)?.forEach((fn) => fn())
}

function reactive(obj) {
  return new Proxy(obj, {
    get(target, key, receiver) {
      track(target, key)
      const value = Reflect.get(target, key, receiver)
      return value !== null && typeof value === 'object' ? reactive(value) : value // 讀到才深入
    },
    set(target, key, value, receiver) {
      const ok = Reflect.set(target, key, value, receiver)
      trigger(target, key)
      return ok
    },
  })
}

function effect(fn) {
  activeEffect = fn
  fn() // 執行時讀到的屬性都會被 track
  activeEffect = null
}

const state = reactive({ count: 0 })
effect(() => (document.title = `點了 ${state.count} 次`))
state.count++ // 標題自動更新
```

真正的 Vue 還處理了：巢狀 effect、執行前清掉舊依賴（條件分支會改變依賴）、批次更新（同一輪多次修改只渲染一次）、`computed` 的快取。

## 模板編譯與雙向綁定 {#1-7-1-4}

Vue、Angular 的模板會先編譯成渲染函式：

```text
模板字串 → 解析成 AST → 標記靜態節點（之後不必比對）→ 產生 render 函式
```

`render` 執行時讀到的資料會被收集成依賴，於是「哪個資料影響哪個元件」自動建立起來。Vue 3 的編譯器還會替動態節點加上標記（patch flags），更新時只比對會變的部分。

`v-model` 只是語法糖：`:value="x"` 加上 `@input="x = $event.target.value"`。資料流本身仍是單向的，「雙向」指的是這兩個綁定同時存在。

**MVVM**：View（模板）↔ ViewModel（響應式資料 + 綁定）↔ Model（資料來源）。ViewModel 讓 View 自動反映資料、也把使用者輸入寫回資料，開發者不用自己操作 DOM。

## 虛擬 DOM {#1-7-1-5}

用 JavaScript 物件描述 DOM 樹（`{ tag: 'ul', props: { id: 'list' }, children: [...] }`）。狀態改變時產生新的一棵，和舊的比對（diff），只把差異套用到真實 DOM（patch）。

- **好處**：開發者只描述「畫面應該長怎樣」，不用自己算要改哪些 DOM；同一套描述也能渲染到原生 App、Canvas、伺服器字串（SSR）。
- **常見誤解**：虛擬 DOM 不會比「手寫最精準的 DOM 操作」快，它多了一層比對。它的價值是在可接受的成本下，讓宣告式寫法可行。Solid、Svelte 走「沒有虛擬 DOM」的路線也能很快。

**diff 的三個假設**（把 O(n³) 的樹比對降到 O(n)）：

1. 只比較同一層，不跨層移動節點。
2. 節點類型（標籤或元件）不同，就整棵子樹砍掉重建。
3. 同一層的子節點用 `key` 辨識身分；有 key 才能正確地移動、重用節點。

`key` 用陣列索引的問題：在清單前面插入一項，後面每一項的 key 都變了，框架會以為每一項都改了內容，而不是移動；如果子元件有內部狀態（例如輸入框內容），還會錯位。
