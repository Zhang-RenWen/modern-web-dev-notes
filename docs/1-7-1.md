> **主線**：Code → Git → PR / Review → CI → Artifact / Image → Deploy → Monitor → Alert → Rollback / 回饋。工具會換，這條鏈路不會。

## 學習原則 {#1-7-1-1}

- **工具三分類**：主流成長型（深學）／成熟維護型（遇到再補，如 Jenkins、Selenium、Eclipse）／式微型（知道即可，如 Travis CI）。「還有人用」≠「值得現在投入」。
- **學能力，不學 Logo**：Source Control → Build → Test → Artifact → Container → CI/CD → Deploy → Observability。GitHub Actions 換成 Jenkins，本質仍是 Trigger → Build → Test → Package → Deploy。
- **架構思維**：需求 → 問題是什麼 → 需要什麼 Pattern → Trade-off → 最後才選服務。例：大量圖片上傳要縮圖 → 不該讓 HTTP 等 → 非同步 → Queue + Worker → S3 → SQS → Lambda。
- **每學一個技術固定問 7 題**：解決什麼問題？不用會怎樣？何時該用？何時不該用？代價？有沒有更簡單方案？規模變大會在哪裡壞？
- **AI 時代分工**：API / CLI / SDK 語法、IaC 初稿交給 AI 查；自己保留「知識地圖 + 問題意識 + 決策能力」。

## 學習優先級 {#1-7-1-2}

| 層級 | 內容 |
| --- | --- |
| **必學** | Linux、Network（HTTP/TCP/DNS/TLS）、Git/GitHub、Docker + Compose、Nginx、GitHub Actions、Cloud 基礎、環境變數 / Secrets、Logging、Monitoring |
| **後端架構加分** | Queue、Event-driven、Redis、Object Storage、DB 備份、API Gateway、Auth / RBAC、Rate limit、Retry / Timeout、Health check、Blue-Green |
| **資料系統** | Data Pipeline、Data Lake、ETL/ELT、Stream、Data Warehouse、Scheduled Jobs、Crawler、AI Summary Workflow |
| **先知道，不急** | Kubernetes 深水區、Terraform、OpenTelemetry、Prometheus/Grafana、Argo CD、Service Mesh、Supply Chain Security、FinOps |
| **可延後** | Puppet、Chef、SaltStack、OpenShift、Nomad、Docker Swarm、OpenStack、Travis CI、TeamCity、Zabbix |

**DevOps 要不要自己寫演算法？** 一般 AWS + ECS + ALB + GitHub Actions 這層幾乎不用；重點是「理解用途、會選、會串、能找瓶頸」。要知道的是策略怎麼選：

- Load Balancer：Round Robin（無狀態 API）、Least Connections、IP Hash / Sticky Session（需黏著的連線，如聊天室、WebSocket）、Health Check
- Auto Scaling：Metric → Threshold → Action（如 CPU > 70% 加 2 台）
- Redis eviction：allkeys-lru / volatile-lru / allkeys-lfu 依場景選
- 真正會碰演算法的是**做基礎設施本身**：LB / CDN（Consistent Hash、Bloom Filter）、DB 核心（B+ Tree、LSM Tree、Query Optimizer）、分散式系統（Raft、Paxos、Gossip、Vector Clock）。等要往那走再學。

## 工程交付流程（Ship Code to Production） {#1-7-1-3}

1. PM 建需求 → 拆 Ticket / User Story
2. 開短生命 feature branch → 寫 code → Conventional Commit
3. Push → 開 PR → CI 跑 lint / test / build / **安全掃描**
4. Code Review → Approve → Merge（Branch Protection）
5. Build **Artifact**（jar、npm package、Docker image）存到 Registry（ECR、GitHub Packages、Artifactory、Nexus）——不是把原始碼直接丟上 prod
6. 部署 Dev → QA → UAT 驗證（功能、Regression、Performance、業務驗收）
7. 上 Production：Feature Toggle / Canary（1% → 10% → 全量）/ Blue-Green / A/B
8. Monitoring / Logging / Tracing → Alert → Escalation
9. 出事：Rollback / Hotfix → Incident Review / Postmortem → 回到下一輪需求

**舊流程圖常缺的現代區塊**：GitOps / IaC（Terraform、Helm、Argo CD）、Security Scan（SAST、DAST、Dependency、Secret、Image Scan、SBOM）、PR Review、Rollback。

**面試講法**：「企業不會直接把 code 丟正式環境。從 ticket 開始，branch 開發、PR review；合併前 CI 跑 lint/test/build 與安全掃描，產出 artifact 或 image，部署 Dev/QA/UAT 驗證；上線用 feature toggle、canary 或 blue-green 降風險，上線後靠 monitoring/alerting/tracing，出問題 rollback 或 hotfix。」
